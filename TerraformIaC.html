Terraform & Infrastructure as Code (IaC)

Terraform

Infrastructure as Code (IaC)

"Automate, Provision, Manage, and Version Cloud Infrastructure on AWS"

1. What is Infrastructure as Code (IaC)? Theory

Infrastructure as Code (IaC) is the practice of managing and provisioning computing infrastructure through machine-readable definition files (code), rather than manual physical hardware configuration or interactive web consoles.

MANUAL CLOUD MANAGEMENT (Error-Prone & Slow): AWS Console ──> Click "Launch Instance" ──> Click "Create VPC" ──> Manual SG Configuration [Disadvantages: Hard to reproduce, no change history, human clicking errors, slow disaster recovery] INFRASTRUCTURE AS CODE (Automated & Declarative): Terraform Code (main.tf) ──> Version Control (Git) ──> terraform apply ──> VPC, EC2, S3, RDS [Advantages: 100% Automated, Version Controlled, Identical Environments (Dev/Staging/Prod), Fast Rollbacks]

Key Advantages of IaC:

1. Automation & Speed: Provision an entire multi-tier VPC, cluster, and database in 3 minutes instead of 4 hours of clicking.
2. Version Control & Auditability: Every infrastructure change is tracked in Git with commit history, pull request reviews, and blame logs.
3. Consistency (No Drift): Guarantees that staging and production environments are 100% identical.
4. Disaster Recovery: If an entire AWS region goes down, rerun terraform apply in another region to rebuild everything automatically.

2 & 3. What is Terraform & The Core Workflow Workflow

Simple Definition:
"Terraform is an open-source declarative Infrastructure as Code tool created by HashiCorp that allows engineers to define cloud resources in human-readable HCL (HashiCorp Configuration Language) files and safely provision them across any cloud provider."

The 4-Step Terraform Lifecycle Workflow:

============================== TERRAFORM CORE WORKFLOW ============================== 1. WRITE CODE (main.tf) │ ▼ 2. terraform init ──────► Downloads required AWS Provider plugins & initializes backend │ ▼ 3. terraform plan ──────► Compares code vs real AWS state, generates an execution plan │ ▼ 4. terraform apply ─────► Sends API calls to AWS, creates resources, updates terraform.tfstate │ ▼ 5. terraform destroy ───► Safely deletes all managed resources when no longer needed =====================================================================================

4, 5, 6. Architecture, Installation & AWS Credentials Setup

How Terraform Communicates with AWS:

Terraform CLI (.tf code) ──► AWS Provider Plugin ──► AWS HTTPS REST APIs ──► AWS Cloud (EC2, S3, VPC)

Installation Verification:

Terminal / PowerShell
# Check Terraform version
terraform -version

# Output should look like:
# Terraform v1.9.x
# on windows_amd64 / linux_amd64

Safe AWS Authentication (Never Hardcode Credentials!):

Security Rule: Never write access_key or secret_key inside .tf files! Use aws configure via AWS CLI or IAM Roles.
AWS CLI Config
# Configure AWS CLI profile locally
aws configure
# AWS Access Key ID: YOUR_ACCESS_KEY_PLACEHOLDER
# AWS Secret Access Key: YOUR_SECRET_KEY_PLACEHOLDER
# Default region name: us-east-1
# Default output format: json

# Verify authentication identity
aws sts get-caller-identity

7 to 12. First Project: Provider, S3 Bucket, Plan & Apply Practical

1. Standard Project File Structure:

terraform-demo/ ├── main.tf # Primary resource declarations (S3, EC2, VPC) ├── variables.tf # Input variable definitions and types ├── outputs.tf # Output values to display after apply ├── terraform.tfvars # Variable values for specific environment └── versions.tf # Terraform and provider version constraints

2. main.tf (Provider & S3 Bucket Resource):

HCL (main.tf)
terraform {
  required_version = ">= 1.5.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.aws_region
}

# Create an AWS S3 Bucket
resource "aws_s3_bucket" "demo_bucket" {
  bucket = "my-unique-tf-demo-bucket-${var.environment}"

  tags = {
    Name        = "MyDemoBucket"
    Environment = var.environment
    ManagedBy   = "Terraform"
  }
}

3. variables.tf & outputs.tf:

HCL (variables.tf & outputs.tf)
# variables.tf
variable "aws_region" {
  type        = string
  default     = "us-east-1"
  description = "AWS deployment region"
}

variable "environment" {
  type        = string
  default     = "dev"
  description = "Environment name (dev, staging, prod)"
}

# outputs.tf
output "s3_bucket_id" {
  value       = aws_s3_bucket.demo_bucket.id
  description = "The name of the created S3 bucket"
}

output "s3_bucket_arn" {
  value       = aws_s3_bucket.demo_bucket.arn
  description = "The ARN of the created S3 bucket"
}

4. Executing Terraform Commands:

Commands
# 1. Initialize working directory (downloads AWS provider plugin)
terraform init

# 2. Format code and validate syntax
terraform fmt
terraform validate

# 3. Generate and inspect execution plan
terraform plan

# 4. Apply changes to AWS cloud
terraform apply -auto-approve

# 5. Inspect output values
terraform output

13 to 19. State File, Drift, Variables, Outputs, Locals & Data Sources Core Concepts

1. What is terraform.tfstate?

Definition: terraform.tfstate is a JSON file that maps your Terraform code resources to real AWS resource IDs, tracks metadata, and boosts performance. Never edit it manually!

2. Infrastructure Drift Detection:

If someone manually deletes or modifies a resource in the AWS Console, running terraform plan compares the real AWS state against your code and proposes actions to restore the desired state.

3. Data Sources (Reading Existing Resources):

HCL Data Source
# Fetch latest Amazon Linux 2023 AMI dynamically
data "aws_ami" "latest_amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

20, 21, 22. Practicals: Complete VPC, EC2 & RDS in Terraform Infrastructure Lab

1. Complete VPC & Subnet Configuration (vpc.tf):

HCL (vpc.tf)
# 1. Custom VPC
resource "aws_vpc" "main_vpc" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  enable_dns_support   = true

  tags = { Name = "Terraform-VPC" }
}

# 2. Public Subnet
resource "aws_subnet" "public_subnet" {
  vpc_id                  = aws_vpc.main_vpc.id
  cidr_block              = "10.0.1.0/24"
  availability_zone       = "${var.aws_region}a"
  map_public_ip_on_launch = true

  tags = { Name = "Public-Subnet" }
}

# 3. Internet Gateway
resource "aws_internet_gateway" "igw" {
  vpc_id = aws_vpc.main_vpc.id
  tags   = { Name = "Main-IGW" }
}

# 4. Route Table & Association
resource "aws_route_table" "public_rt" {
  vpc_id = aws_vpc.main_vpc.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.igw.id
  }
}

resource "aws_route_table_association" "public_assoc" {
  subnet_id      = aws_subnet.public_subnet.id
  route_table_id = aws_route_table.public_rt.id
}

2. Web Server Security Group & EC2 Instance (ec2.tf):

HCL (ec2.tf)
# Security Group allowing HTTP & SSH
resource "aws_security_group" "web_sg" {
  name        = "web-server-sg"
  description = "Allow inbound HTTP and SSH traffic"
  vpc_id      = aws_vpc.main_vpc.id

  ingress {
    description = "HTTP from anywhere"
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

# EC2 Web Server with User Data script
resource "aws_instance" "web_server" {
  ami                    = data.aws_ami.latest_amazon_linux.id
  instance_type          = "t3.micro"
  subnet_id              = aws_subnet.public_subnet.id
  vpc_security_group_ids = [aws_security_group.web_sg.id]

  user_data = <<-EOF
              #!/bin/bash
              yum update -y
              yum install -y httpd
              systemctl start httpd
              systemctl enable httpd
              echo "
Deployed via Terraform on AWS
" > /var/www/html/index.html
              EOF

  tags = { Name = "Terraform-WebServer" }
}

23 to 28. Modules, Remote State (S3 + DynamoDB), Workspaces & Import Enterprise Patterns

1. Reusable Terraform Modules:

Root Module (main.tf) │ ├──► module "vpc" (Creates VPC, Subnets, Gateways) ├──► module "ec2" (Creates Auto Scaling Web Servers) └──► module "rds" (Creates Private PostgreSQL Database)

2. S3 Remote State Backend with DynamoDB State Locking:

HCL Remote Backend
terraform {
  backend "s3" {
    bucket         = "my-company-terraform-state-prod"
    key            = "global/s3/terraform.tfstate"
    region         = "us-east-1"
    dynamodb_table = "terraform-state-locks"
    encrypt        = true
  }
}

29 to 32. Best Practices & Troubleshooting Common Errors Troubleshooting

Error Message Possible Root Cause How to Fix
NoCredentialProviders / Auth Error AWS CLI is not configured or IAM access keys have expired. Run aws configure or check AWS environment variables.
Error acquiring the state lock A previous Terraform run was interrupted, leaving DynamoDB lock active. Run terraform force-unlock <LOCK-ID> after verifying no team members are running apply.
InvalidAMIID.NotFound Hardcoded AMI ID does not exist in the configured AWS region. Use dynamic data "aws_ami" filter query instead of static IDs.
ResourceAlreadyExists Resource was created manually in AWS Console with the same unique name. Import the resource with terraform import or change the resource name.

33. 50+ Terraform Interview Questions & Answers Interview Q&A

# Interview Question Concise & Technical Answer
1What is Terraform?An open-source Infrastructure as Code tool by HashiCorp used to provision and manage cloud resources declaratively.
2What is IaC?Managing and provisioning computing infrastructure through code configuration files rather than manual clicking.
3What is the Terraform State file?A JSON database (terraform.tfstate) that records the real-world resource mappings and metadata of managed infrastructure.
4What is terraform init?Initializes the working directory by downloading required provider plugins and configuring the backend.
5What is terraform plan?Creates an execution plan previewing what resources will be created, modified, or destroyed without applying changes.
6What is terraform apply?Executes the planned actions to reach the desired state defined in configuration files.
7What is terraform destroy?Deletes all infrastructure managed by the current Terraform state file.
8What is a Terraform Provider?A plugin that communicates with cloud APIs (AWS, Azure, GCP) to manage resources.
9What is a Terraform Resource?A block describing one or more infrastructure objects (e.g. aws_instance, aws_vpc).
10What is a Data Source?Allows Terraform to read and use data defined outside of Terraform or managed by another configuration.
11What is a Terraform Module?A container for multiple resources that are used together, promoting code reuse and modular architecture.
12What is Remote State?Storing the .tfstate file in a shared remote location (e.g. AWS S3) for team collaboration and security.
13Why use DynamoDB with S3 backend?To provide state locking, preventing multiple team members from running concurrent applies and corrupting state.
14What is State Drift?When real cloud infrastructure changes out-of-band (manually in console) and differs from the Terraform state.
15What is depends_on?An explicit dependency attribute used when Terraform cannot automatically infer resource dependencies.
16What are Local Values (locals)?Internal named expressions that assign names to expressions to avoid repeating code.
17What is terraform.tfvars?A file containing key-value assignments to set input variables automatically during execution.
18What is terraform validate?Verifies whether a configuration is syntactically valid and internally consistent.
19What is terraform fmt?Automatically rewrites Terraform configuration files to a canonical format and style.
20What is terraform import?Brings existing pre-created cloud infrastructure under Terraform state management.
21What is a Terraform Workspace?Allows managing multiple distinct state files within the same working directory (e.g. dev, prod).
22What is .terraform.lock.hcl?A dependency lock file that pins the exact versions and checksums of installed provider plugins.
23How do you handle secrets in Terraform?Use AWS Secrets Manager, SSM Parameter Store, or environment variables—never commit raw secrets to Git.
24What is count vs for_each?count iterates over integer indices; for_each iterates over maps or sets of strings with stable keys.
25What is the lifecycle block?Controls resource behavior: create_before_destroy, prevent_destroy, ignore_changes.
26What is Terraform Cloud / Enterprise?A managed SaaS platform by HashiCorp providing remote execution, VCS integration, and policy as code (Sentinel).
27Terraform vs AWS CloudFormation?Terraform is multi-cloud and uses HCL; CloudFormation is AWS-only and uses JSON/YAML.
28What happens if terraform apply fails halfway?Terraform records all successfully created resources into state; subsequent runs continue from that point.
29What is terraform refresh?Updates the state file with the real current status of infrastructure in the cloud.
30What is terraform taint / -replace?Forces a resource to be destroyed and recreated on the next apply.
