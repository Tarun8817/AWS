AWS AMI — Complete Guide (Hinglish)

📦 AWS AMI — Complete Guide

Amazon Machine Image ko basics se advanced tak samjho — beginner-friendly aur interview-ready Hinglish mein

1️⃣ AWS AMI Kya Hai?

Ek Amazon Machine Image (AMI) ek pre-configured template hota hai jisme wo saari info hoti hai jo EC2 instance launch karne ke liye chahiye.

Simple bhasha mein — AMI ek ready-made blueprint hai jisse aap bina scratch se install kiye naya server (EC2) bana sakte ho.

Ek AMI mein ye sab ho sakta hai:

  • Operating System — Amazon Linux, Ubuntu, Windows Server
  • Application server — Apache, Nginx
  • Pre-installed software — jo bhi pehle se server pe daala gaya hai
  • Application configuration — app ki settings
  • Required libraries aur dependencies — jo software ko chalane ke liye chahiye
  • Security aur system configurations — firewall rules, permissions, etc.
Real-world example

Socho aapke paas ek EC2 server hai jisme Amazon Linux, Apache, aur ek website pehle se configured hai. Agar aapko bilkul same setup wala ek aur server chahiye, to sab kuch dobara install karne ki zarurat nahi — us server se ek AMI bana lo, phir usi AMI se naya EC2 instance launch kar do. Naya server exactly original jaisa hi configured hoga.

💡 AMI Kyu Use Karte Hain?

  • Fast EC2 instance creation — setup pehle se ready hai, isliye naya server jaldi ban jaata hai.
  • Reusable server configuration — ek baar configure karo, baar baar reuse karo.
  • Easy server replication — same server ki multiple copies banana asaan ho jaata hai.
  • Backup/reference for server configuration — kuch galat ho jaye to AMI backup/reference ka kaam karta hai.
  • Scaling applications — traffic badhne pe, same AMI se naye servers launch karo.
  • Identical environments banana — dev, test, aur production ko identical rakho.
  • Disaster recovery — server crash ho jaye to AMI se turant naya server spin up karo.
  • Same setup wale multiple EC2 instances banana — ek hi action mein kai identical servers.
Simple example

Agar ek EC2 server pe pehle se Apache install hai, website configured hai, Node.js install hai, application deploy hai, aur saari configurations complete hain — to us instance se AMI banake usi setup wala doosra EC2 instance launch kiya ja sakta hai.

🏷️ AMI Ke Types

Public AMIs

Sabhi AWS users ke liye available hote hain, aur generally AWS khud ya trusted publishers dete hain.

Kaam aata hai: common operating systems aur software ke liye.

Examples: Ubuntu, Amazon Linux, Windows Server.

Private AMIs

Ek AWS user dwara banaye jaate hain, aur normally sirf owner ke account tak hi available hote hain.

Inhe specific AWS accounts ke saath share bhi kiya ja sakta hai. Internal applications aur company-specific environments ke liye useful.

AWS Marketplace AMIs / Paid AMIs

Third-party vendors dwara provide kiye jaate hain, aur AWS Marketplace ke through available hote hain.

Include ho sakta hai: extra software, licenses, ya support.

Examples: pre-configured web servers, databases, security software, application environments, LAMP stack.

Free vs Paid: Standard public AMIs (jaise Amazon Linux ya Ubuntu) generally free hote hain — sirf normal AWS infrastructure charge lagta hai. Marketplace AMIs extra software/license charge add kar sakte hain, lekin har Marketplace AMI paid nahi hota — kuch free bhi hote hain.

🧩 AMI Mein Kya Hota Hai?

  • Root volume/template information — instance ka main disk template.
  • Operating system — instance mein kaunsa OS hoga.
  • Software — jo bhi pehle se install tha.
  • Application configuration — app ki settings aur files.
  • Block device mapping — kaunsa disk kis device name se attach hota hai.
  • Architecture — 32-bit ya 64-bit, x86 ya ARM.
  • Virtualization information — HVM ya paravirtual type.
  • Permissions — is AMI ko use karne ki ijaazat kisko hai.
  • Region information — kis AWS Region mein available hai.
Important: Ek AMI external resources ki live state capture nahi karta — jaise Elastic IP ya Load Balancer. Ye alag se manage hote hain aur naye instance ke saath dobara attach karne padte hain.

🔗 AMI Aur EBS Snapshots Ka Relationship

EC2 Instance ↓ EBS Root Volume ↓ Create AMI ↓ EBS Snapshot(s) + AMI metadata ↓ Launch new EC2 ↓ New EBS Volume(s)
  • AMI sirf ek EBS snapshot nahi hai — dono alag concepts hain.
  • Ek snapshot ek single EBS volume ka block-level data store karta hai — sirf disk backup.
  • Ek AMI mein wo saari info hoti hai jo EC2 instance launch karne ke liye chahiye, aur ye required snapshots ko reference karta hai.
  • Jab EBS-backed EC2 instance se AMI banaya jaata hai, to us process ke part ke roop mein AWS snapshots create karta hai.

🌍 AMI Region Concept

  • AMIs Region-specific hote hain.
  • Ek Region mein banaya gaya AMI automatically doosre Region mein available nahi hota.
  • AMIs ko doosre Region mein copy kiya ja sakta hai.
  • Copy karne ke baad, copied AMI ko destination Region mein use kiya ja sakta hai.
Example

eu-north-1 mein banaya gaya AMI, eu-west-1 mein use hone se pehle wahan copy karna padega.

AMI copy karna disaster recovery, multi-region deployment, aur business continuity ke liye useful hai — agar ek Region down ho jaye, to aap turant doosre Region mein servers spin up kar sakte ho.

🗑️ AMI Ko Deregister/Delete Kaise Kare

AMI deregister karna aur uske related snapshots delete karna alag concepts hain.

  1. EC2 kholo.
  2. AMIs pe jao.
  3. AMI select karo.
  4. Actions pe click karo.
  5. Deregister AMI select karo.
  6. Confirm karo.
  • Deregister karne se sirf AMI ka registration remove hota hai.
  • Isse associated EBS snapshots zaruri nahi ki remove ho jaayein.
  • Unused snapshots ko alag se delete karna pad sakta hai.
  • Agar snapshot kisi doosre AMI se reference ho raha hai to delete fail ho sakta hai.
Common error: "The snapshot is currently in use by an AMI."

Iska matlab snapshot abhi bhi kisi active AMI se linked hai. Delete karne se pehle check karo ki wo kisi doosre AMI (ya usi AMI ki dusri copy) se reference ho raha hai kya — pehle us AMI ko deregister karo, phir snapshot safely delete ho jaayega.

Ye sab saath mein aise kaam karte hain: AMI + Launch Template + Auto Scaling Group — pehle AMI banta hai (server image), phir Launch Template usko launch settings ke saath reference karta hai, aur Auto Scaling Group us template ka use karke multiple instances manage karta hai.

🏗️ Create Image vs Create Launch Template — Practical Example

EC2 Server A mein hai:

  • Amazon Linux
  • Apache
  • Node.js
  • Application
  • Configuration

Step 1 — Create Image: Isse Server A ka base configuration wala AMI ban jaata hai.

Step 2 — Create Launch Template: Launch Template ye specify kar sakta hai:

  • AMI
  • Instance type
  • Key pair
  • Security group
  • Network settings
  • IAM role
  • User data
  • Storage configuration

Step 3 — Auto Scaling Group: Multiple EC2 instances launch karne ke liye Launch Template use karta hai.

Existing EC2 ↓ Create Image ↓ AMI ↓ Launch Template ↓ Auto Scaling Group ↓ Multiple EC2 Instances

📈 AMI + Auto Scaling

Jab traffic badhta hai, AMI scalability ke liye bahut useful hota hai kyunki naye servers same configuration ke saath instantly launch ho sakte hain.

Load Balancer ↓ Auto Scaling Group ↓ EC2 ← AMI EC2 ← AMI EC2 ← AMI

Har naya EC2 instance launch configuration ke through same AMI se launch hota hai — isliye har server ka setup bilkul same hota hai.

⚖️ AMI + Load Balancer

Ek important point: AMI khud traffic distribute nahi karta.

  • AMI → server image provide karta hai
  • Launch Template → EC2 launch configuration provide karta hai
  • Auto Scaling Group → EC2 instances manage karta hai
  • Application Load Balancer → incoming requests distribute karta hai
Users ↓ Application Load Balancer ↓ Auto Scaling Group ↓ EC2 Instance 1 EC2 Instance 2 EC2 Instance 3 ↑ AMI se banaye gaye

Example: Pre-configured LAMP Stack

Rapid Deployment

Yaad rakho: har Marketplace AMI paid nahi hota — pricing models alag alag hote hain (kuch free, kuch paid with support/licensing).

📚 Important AMI Terminology

  • AMI ID — har AMI ka unique identifier (jaise, ami-0abcd1234).
  • Root Device — main storage device jisse OS boot hota hai.
  • Block Device Mapping — dikhata hai kaunse volumes kis device names se attach hote hain.
  • EBS Snapshot — ek EBS volume ka backup/copy.
  • Architecture — instance x86, x86_64, ya ARM64 hai.
  • Virtualization Type — HVM (common) ya Paravirtual.
  • Kernel — OS ka core software (modern AMIs pe generally auto-managed).
  • Image Owner — AMI kisne create/register kiya.
  • Public AMI — sabke liye available.
  • Private AMI — sirf owner ke liye available.
  • Shared AMI — specific accounts ke saath shared AMI.
  • Marketplace AMI — third-party vendor ka AMI.
  • AMI Copy — AMI ko ek Region se doosre mein copy karna.
  • AMI Deregistration — AMI ka registration remove karna.

  • AMI ke andar kabhi secrets/API keys store mat karo.

🎯 AMI Important Interview Questions

Q1: AMI kya hai?

A: Ek pre-configured template jisme EC2 instance launch karne ke liye zaruri info (OS, software, configuration) hoti hai.

Q2: AMI kyu use karte hain?

A: Fast server creation, reusable configuration, easy replication, aur disaster recovery ke liye.

Q3: AMI mein kya hota hai?

A: OS, software, configuration, block device mapping, architecture, virtualization info, permissions, aur region info.

Q4: AMI aur EBS Snapshot mein kya difference hai?

A: Snapshot ek volume ka sirf block-level backup hai; AMI ek full instance template hai jo snapshots ko reference karta hai.

Q5: AMI aur EC2 mein kya difference hai?

A: AMI ek template/blueprint hai; EC2 instance us blueprint se banaya gaya actual running virtual server hai.

Q6: Public aur private AMIs kya hote hain?

A: Public AMI sabke liye available hota hai; private AMI sirf owner (ya specifically shared accounts) ke liye available hota hai.

Q7: AWS Marketplace AMI kya hai?

A: Third-party vendors dwara provide kiya gaya AMI, jisme extra software, licensing, ya support include ho sakta hai.

Q8: AMI kaise banate hain?

A: EC2 → Instances → Actions → Image and templates → Create image.

Q9: AMI use karke EC2 kaise launch karte hain?

A: EC2 → AMIs → AMI select karo → Launch instance from AMI → settings fill karo → Launch.

Q10: Kya AMI doosre Region mein use ho sakta hai?

A: Directly nahi — AMIs Region-specific hote hain; pehle destination Region mein copy karna padega.

Q11: AMI ko doosre Region mein kaise copy karte hain?

A: AMI select karo → Actions → Copy AMI → destination Region choose karo → copy start karo.

Q12: Kya private AMI share ho sakta hai?

A: Haan — Edit AMI permissions ke through, specific AWS account IDs ke saath share kiya ja sakta hai.

Q13: AMI deregister karne pe kya hota hai?

A: AMI ka registration remove ho jaata hai, aur usse naye instances launch nahi kiye ja sakte.

Q14: Kya AMI deregister karne se snapshots automatically delete ho jaate hain?

A: Nahi — snapshots alag se delete karne padte hain.

Q15: Create Image aur Create Launch Template mein kya difference hai?

A: Create Image ek AMI (server snapshot) banata hai; Launch Template EC2 instances launch karne ki configuration store karta hai.

Q16: AMI Auto Scaling ke saath kaise kaam karta hai?

A: Auto Scaling Group same AMI reference karne wale Launch Template ka use karke multiple identical EC2 instances banata hai.

Q17: AMI Load Balancer ke saath kaise kaam karta hai?

A: AMI khud traffic distribute nahi karta — Load Balancer AMI se banaye gaye multiple EC2 instances ke beech traffic distribute karta hai.

Q18: AMI ID kya hai?

A: Har AMI ko diya gaya unique identifier, jo instance launch karte waqt use hota hai.

Q19: Secrets AMI mein store kyu nahi karne chahiye?

A: Kyunki AMI share ya copy ho sakta hai, aur stored secrets/API keys leak ho sakte hain, jisse security risk ban jaata hai.

Q20: Marketplace AMI aur standard public AMI mein kya difference hai?

A: Standard public AMI generally ek free OS image hota hai; Marketplace AMI mein extra software/licensing/support include ho sakta hai, jispe additional charge lag sakta hai.

🗺️ Quick Revision

AMI = EC2 launch karne ke liye Template/Image EC2 = Virtual Server EBS = Storage Snapshot = EBS volume data ka Backup/copy Launch Template = EC2 launch configuration Auto Scaling Group = EC2 instances ko automatically manage karta hai Load Balancer = Traffic distribute karta hai AMI + Launch Template + ASG = Scalable EC2 deployment ke liye common pattern
