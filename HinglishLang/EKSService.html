1. Amazon EKS Kya Hai? (Introduction) Theory

Simple Definition in Hinglish:
"Amazon EKS (Elastic Kubernetes Service) AWS ki ek fully managed service hai jo humein AWS cloud par bina kisi manual server installation ke official Kubernetes clusters chalane aur scale karne ki suvidha deti hai."

Core Terms in Simple Hinglish:

  • AWS (Amazon Web Services): Duniya ka sabse bada cloud provider jahan servers aur storage on-demand milte hain.
  • Docker / Container: Ek aisi packaging technique jisme code, libraries aur dependencies pack ho jati hain taaki software har computer par seamlessly chale.
  • Container Orchestration: Jab 100+ containers chalte hain, to unhe automatically start karna, load balance karna, crash hone par restart karna Orchestration kehlata hai.
  • Kubernetes (K8s): Google dwara banaya gaya duniya ka sabse popular open-source container orchestration software.
  • Amazon EKS: AWS dwara manage kiya gaya certified Kubernetes service jo IAM, VPC, ALB aur CloudWatch ke sath natively integrated hai.
  • Cluster: Control plane (master nodes) aur worker nodes (jahan actual app chalti hai) ka pura group.

Manual Container Management vs Kubernetes:

MANUAL DOCKER (Bina Kubernetes ke): Developer ──> Launch EC2 ──> SSH ──> docker run ──> Container [Problems: Container crash hua to raat ko 2 baje manual restart karna padega. No auto-scaling. Updates par downtime.] WITH KUBERNETES & EKS: Developer ──> kubectl apply ──> EKS Control Plane ──> Pods / Nodes ──> Highly Available App [Benefits: Self-healing auto-restart, Zero-downtime rolling updates, Horizontal Pod Auto-scaling, Native Load Balancing.]

2 & 3. Kubernetes Kya Hai & Iski Zaroorat Kyu Hai? Theory

Kubernetes (K8s) ek open-source system hai jo containerized applications ko automatically deploy, scale aur manage karta hai.

Kubernetes Ke Main Fayde (Features):

1. Automated Deployments: Application ke naye versions ko zero downtime ke sath release karna.
2. Self-Healing: Agar koi container crash hota hai to K8s turant naya container spin up kar deta hai.
3. Auto Scaling: Traffic badhne par Pods ki sankhya 2 se 10 automatically badha deta hai.
4. Load Balancing: Dynamic Pod IP addresses ke beech incoming web traffic ko equally baant-na.
5. Secrets & Config: Database passwords aur API keys ko code se alag securely manage karna.
6. Storage Orchestration: AWS EBS volumes ya EFS file systems ko Pods ke sath auto-mount karna.

5, 6, 7. EKS Architecture: Control Plane & Data Plane Architecture

================================== AMAZON EKS ARCHITECTURE ================================== [ AWS MANAGED CONTROL PLANE ] (Highly Available across 3 AZs) ┌────────────────────────────────────────────────────────────────────────┐ │ │ │ [ kube-apiserver ] ◄──── kubectl / eksctl commands │ │ │ │ │ ├────────► [ kube-scheduler ] (Decides which node runs Pods) │ │ ├────────► [ kube-controller-manager ] (Reconciles state) │ │ └────────► [ etcd ] (Encrypted key-value database of cluster) │ │ │ └───────────────────────────────────┬────────────────────────────────────┘ │ Secure TLS Tunnel [ CUSTOMER DATA PLANE / WORKER NODES ] ┌───────────────────────────────────┴────────────────────────────────────┐ │ │ │ ┌──────────────────────────────┐ ┌──────────────────────────────┐ │ │ │ WORKER NODE 1 (EC2 / Spot) │ │ WORKER NODE 2 (EC2 / Spot) │ │ │ │ ┌────────────────────────┐ │ │ ┌────────────────────────┐ │ │ │ │ │ kubelet & kube-proxy │ │ │ │ kubelet & kube-proxy │ │ │ │ │ ├────────────────────────┤ │ │ ├────────────────────────┤ │ │ │ │ │ Container Runtime │ │ │ │ Container Runtime │ │ │ │ │ │ (containerd) │ │ │ │ (containerd) │ │ │ │ │ ├────────────────────────┤ │ │ ├────────────────────────┤ │ │ │ │ │ [ Pod A ] [ Pod B ] │ │ │ │ [ Pod C ] [ Pod D ] │ │ │ │ │ │ (Node.js) (React) │ │ │ │ (Express) (Nginx) │ │ │ │ │ └────────────────────────┘ │ │ └────────────────────────┘ │ │ │ └──────────────────────────────┘ └──────────────────────────────┘ │ │ │ └────────────────────────────────────────────────────────────────────────┘ =============================================================================================

Control Plane Ke 4 Main Components:

  • kube-apiserver: Kubernetes ka central gatekeeper jo saare kubectl requests ko authenticate aur process karta hai.
  • etcd: Cluster ka database jisme saari configurations aur running state securely store hoti hai.
  • kube-scheduler: Check karta hai ki naya Pod kaun se worker node par chalega jahan CPU/RAM available ho.
  • kube-controller-manager: Cluster ke actual state ko desired state ke barabar maintain karta hai (e.g. agar 3 pods maange hain to 3 hi chalenge).

Worker Node Ke 3 Main Components:

  • Kubelet: Har worker node par chalne wala agent jo API server se order lekar containers ko start/stop karta hai.
  • Kube-proxy: Node par IP routing rules maintain karta hai taaki Services ke through traffic Pods tak pahuche.
  • Container Runtime (containerd): Actual engine jo container images ko run karta hai.

9 to 15. Pods, Deployments, Services, Ingress, ConfigMaps & Secrets Core Concepts

1. Pod: The Atomic Unit

Kubernetes mein direct container nahi bante; containers hamesha ek Pod ke andar wrap hote hain. Har Pod ko apna dedicated IP address milta hai.

Golden Rule: Production mein kabhi bhi direct kind: Pod create nahi karte! Hamesha Deployments banayein taaki self-healing aur auto-replication mile.

2. Kubernetes Service Types Explained:

Service Type Kaise Kaam Karta Hai? Kahan Accessible Hai? Kahan Use Karein?
ClusterIP (Default)Cluster ke andar ek internal static IP banata hai.Sirf cluster ke andar.Backend APIs, internal microservices, databases.
NodePortHar Worker Node ke static port (30000-32767) par app expose karta hai.Node IP:NodePort par.Direct debugging ya testing.
LoadBalancerAWS par ek dedicated Cloud Load Balancer (NLB/CLB) create karta hai.Public Internet par.Direct internet facing services.
ExternalNameService ko external DNS name (CNAME) se bind karta hai.External DNS mapping.Cluster ke bahar chal rahe RDS database ko call karna.

3. Ingress vs LoadBalancer Service

Agar aapke paas 10 microservices hain, aur aap type: LoadBalancer use karenge to AWS 10 alag-alag Load Balancers banayega (Bahut mehenga bill aayega!). Ingress ke dwara sirf 1 Application Load Balancer (ALB) banta hai aur path/domain ke hisaab se 10 services par traffic route ho jata hai.

30 to 36. Practical 6 to 11 – EKS Cluster Setup via eksctl & Kubeconfig Setup

eksctl: AWS aur Weaveworks ka official CLI tool jo 1 single command se VPC, Subnets, IAM Roles, Security Groups, Control Plane aur EC2 Managed Node Group sab automatically bana deta hai!

1. Create EKS Cluster:

Bash / PowerShell
# Create 2-node managed cluster in your AWS region (Takes ~12-15 minutes)
eksctl create cluster \
  --name eks-demo-cluster \
  --region YOUR-REGION \
  --nodegroup-name standard-workers \
  --node-type t3.medium \
  --nodes 2 \
  --nodes-min 1 \
  --nodes-max 4 \
  --managed

2. Update kubeconfig & Verify Nodes:

Bash / PowerShell
# Update local kubeconfig
aws eks update-kubeconfig --region YOUR-REGION --name eks-demo-cluster

# Verify nodes are active and Ready
kubectl get nodes -o wide

61, 62, 63. Troubleshooting 20 Common EKS Errors Troubleshooting

Error / Status Possible Root Cause Diagnostic Command How to Fix (Solution)
CrashLoopBackOff App startup par crash ho rahi hai (missing env var, code syntax error, DB unreachable). kubectl logs <pod> Logs check karein aur application runtime error ya missing ConfigMap/Secret fix karein.
ImagePullBackOff / ErrImagePull ECR Repository URI galat hai, tag typo hai, ya Node IAM role ke paas ECR read permission nahi hai. kubectl describe pod <pod> Image URI check karein aur Node IAM Role par AmazonEC2ContainerRegistryReadOnly policy verify karein.
Pending Pods Worker nodes par CPU/RAM khatam ho gaya hai ya nodes ready nahi hain. kubectl describe pod <pod> Node group scale karein ya container ke CPU/RAM resource requests kam karein.
CreateContainerConfigError Deployment mein mention kiya gaya ConfigMap ya Secret namespace mein exist nahi karta. kubectl describe pod <pod> Missing ConfigMap ya Secret create karein.
ALB Target Unhealthy (502 / 504) Container /health path par 200 OK nahi de raha ya Security group traffic block kar raha hai. Target Group Console / kubectl logs Health check path verify karein aur Node security group mein ALB SG se traffic allow karein.

16IRSA (IAM Roles for Service Accounts) kya hai?Pod ke ServiceAccount ko direct AWS IAM Role assign karne ka secure OIDC feature.

18EKS Managed Node Group kya hai?EC2 worker nodes jinka lifecycle, provisioning aur AMI updates AWS automatically sambhalta hai.
19EKS on AWS Fargate kya hai?Serverless Kubernetes compute jahan har Pod apni dedicated microVM par chalta hai bina EC2 nodes ke.
20Horizontal Pod Autoscaler (HPA) kya hai?CPU/RAM utilization ke basis par Pod replicas ko automatically scale-out ya scale-in karta hai.
21CrashLoopBackOff ka kya matlab hai?Container start hote hi crash ho raha hai aur Kubernetes baar-baar restart karne ki koshish kar raha hai.
22ImagePullBackOff ka main reason kya hota hai?Galat ECR image URI, invalid image tag, ya Node IAM role ke paas ECR permissions na hona.
23Pending Pod ko kaise debug karein?kubectl describe pod <pod-name> chala kar Events section mein resource shortage check karein.
24Previous crashed container ke logs kaise dekhein?kubectl logs <pod-name> --previous command se.
25Liveness Probe kya karta hai?Check karta hai container chal raha hai ya dead; fail hone par container restart karta hai.
26Readiness Probe kya karta hai?Check karta hai container traffic accept karne ke liye ready hai ya nahi; fail hone par traffic divert karta hai.
27Rolling Update kya hota hai?Purane pods ko ek-ek karke naye version ke pods se replace karna zero downtime ke sath.
28Failed deployment rollback kaise karein?kubectl rollout undo deployment/<deployment-name> se.
29Helm kya hai?Kubernetes applications ka package manager jo manifests ko reusable charts mein package karta hai.
30AWS Load Balancer Controller kya hai?K8s controller jo Ingress aur Service objects ke liye AWS ALBs aur NLBs provision karta hai.
31Kubernetes RBAC kya hai?Role-Based Access Control jo decide karta hai kaun sa user/service account API resources access kar sakta hai.
32NetworkPolicy kya karti hai?Pods ke beech network traffic rules define karke Pod-to-Pod communication restrict karti hai.
33DaemonSet kya hai?Controller jo ensure karta hai ki har node par ek specific Pod (jaise logging agent) zaroor chale.
34StatefulSet kya hai?Controller jo databases ko stable network identities aur persistent disks ke sath run karta hai.
35EKS RDS se kaise securely connect karta hai?Private VPC subnets aur Security Groups ke through allowing port 5432/3306 from node SG.
36EKS S3 mein file upload kaise karta hai?IRSA / Pod Identity ke through bina container mein hardcoded access keys dale.
37Static AWS keys container mein kyu nahi dalni chahiye?Security risk aur credential leak hone ka khatra; IAM role assumption temporary aur auto-rotated hota hai.
38EKS vs ECS: EKS kab choose karein?Multi-cloud portability, massive CNCF ecosystem (Helm, Istio), aur advanced Kubernetes features ke liye.
39EKS vs ECS: ECS kab choose karein?Simple AWS native architecture, kam complexity, aur zero control plane cost ke liye.
40kubeconfig file kya hoti hai?Configuration file jisme cluster API endpoint, certificates aur authentication context store hota hai.
41Container resource request vs limit kya hai?Request = guaranteed minimum CPU/RAM; Limit = maximum limit jisse zyada container use nahi kar sakta.
42Container memory limit exceed kare to kya hota hai?Linux OOM (Out Of Memory) killer container ko terminate kar deta hai with Exit Code 137.
43Kubernetes self-healing kaise karta hai?Controller manager continuously actual state ko desired state se match karta rehta hai.
44EKS cluster upgrade kaise hota hai?EKS Console/CLI se control plane version update karein, phir node group AMIs aur add-ons update karein.
45Karpenter kya hai?High-performance open-source node autoscaling engine for Kubernetes on AWS.
46EKS control plane ka cost kitna hota hai?$0.10 per hour per cluster (~$73/month).
47EKS add-ons kya hote hain?VPC CNI, CoreDNS, kube-proxy, aur EBS CSI driver jaise essential cluster plugins.
48Pod eviction kya hoti hai?Jab node par memory/disk space khatam ho jaye to K8s kam priority wale pods ko terminate kar deta hai.
49Node Affinity kya hoti hai?Rules jo specify karte hain ki kaun sa Pod kis specific type ke node par schedule hoga.
50Taints aur Tolerations kya hain?Nodes par Taints lagaye jaate hain taaki unauthorized Pods wahan schedule na ho sakein jab tak unke paas matching Toleration na ho.

83 to 86. Quick Revision & Final Architecture Summary

Kubernetes = Open-source container orchestration platform
Amazon EKS = Managed Kubernetes on AWS
Pod = Smallest deployable unit (1+ containers)
Deployment = Manages Pod replicas, updates & self-healing
Service = Stable network endpoint for Pods
Ingress = HTTP/HTTPS routing via AWS ALB
Amazon ECR = Private Docker container registry
IRSA / Pod Identity = Direct IAM permissions for Pods
kubectl = Command line tool for Kubernetes
HPA = Horizontal Pod Autoscaling via CPU/RAM

Final Complete Flow:

Code ➔ Dockerfile ➔ docker build ➔ Amazon ECR ➔ EKS Cluster ➔ Deployment ➔ ReplicaSet ➔ Pods ➔ Service ➔ Ingress (ALB) ➔ Happy Users! 🚀
