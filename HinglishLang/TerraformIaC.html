Infrastructure as Code (IaC)

"AWS Cloud Resources ko Code se Automate aur Manage Karein"

1. Infrastructure as Code (IaC) Kya Hai? Theory

Infrastructure as Code (IaC) ka matlab hota hai apne cloud servers, networks, databases aur storage ko AWS Console mein manually click karke banane ke bajaye code (configuration files) likhkar automatically create aur manage karna.

MANUAL CONSOLE APPROACH (Slow & Mistakes ka khatra): AWS Console ──> Click EC2 ──> Click VPC ──> Click Security Group ──> Click RDS [Problems: 1 ghanta lagta hai, setting bhoolne ka risk, dev aur prod alag ban sakte hain] IaC / TERRAFORM APPROACH (Fast, Automated & Version Controlled): Terraform Code (main.tf) ──> terraform apply ──> AWS creates VPC, EC2, S3, RDS in 2 Minutes! [Benefits: 100% Automated, Git version control, Dev/Prod exact replica, Instant disaster recovery]

2 & 3. Terraform Kya Hai & Core Workflow Workflow

Simple Definition in Hinglish:
"Terraform HashiCorp company dwara banaya gaya ek open-source declarative IaC tool hai jisse hum simple HCL (HashiCorp Configuration Language) code likhkar AWS, Azure, GCP jaise kisi bhi cloud par resources create, update aur destroy kar sakte hain."

Terraform Ke 4 Main Lifecycle Steps:

============================== TERRAFORM CORE WORKFLOW ============================== 1. Write Code (main.tf) │ ▼ 2. terraform init ──────► AWS Provider plugin download karta hai aur backend ready karta hai │ ▼ 3. terraform plan ──────► Preview dikhata hai ki kya create, update ya delete hone wala hai │ ▼ 4. terraform apply ─────► AWS API call karke actual cloud resources create karta hai │ ▼ 5. terraform destroy ───► Kaam khatam hone par sabhi resources ko clean/delete karta hai =====================================================================================

4, 5, 6. Architecture, Installation & AWS Authentication Setup

How Terraform Talks to AWS:

Terraform CLI (.tf code) ──► AWS Provider Plugin ──► AWS HTTPS REST APIs ──► AWS Cloud (EC2, S3, RDS)

Safe AWS Credentials Setup (Never Hardcode Keys!):

Security Rule: Kabhi bhi apni Access Key ya Secret Key ko .tf file ke andar hardcode mat karein. Hamesha aws configure command use karein.
AWS CLI Config
# 1. Check Terraform version
terraform -version

# 2. Configure AWS credentials securely
aws configure
# AWS Access Key ID: YOUR_ACCESS_KEY
# AWS Secret Access Key: YOUR_SECRET_KEY
# Default region: ap-south-1 (or us-east-1)

# 3. Verify AWS authentication
aws sts get-caller-identity

7 to 12. First Project: S3 Bucket Resource, Plan & Apply Practical

1. main.tf (Provider & Resource):

HCL (main.tf)
terraform {
  required_version = ">= 1.5.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.aws_region
}

# Create AWS S3 Bucket
resource "aws_s3_bucket" "demo_bucket" {
  bucket = "my-unique-tf-demo-bucket-${var.environment}"

  tags = {
    Name        = "MyDemoBucket"
    Environment = var.environment
    ManagedBy   = "Terraform"
  }
}

2. variables.tf & outputs.tf:

HCL (variables.tf & outputs.tf)
# variables.tf
variable "aws_region" {
  type    = string
  default = "ap-south-1"
}

variable "environment" {
  type    = string
  default = "dev"
}

# outputs.tf
output "s3_bucket_name" {
  value = aws_s3_bucket.demo_bucket.id
}

3. Running Commands:

Terminal
# 1. Initialize
terraform init

# 2. Check Plan
terraform plan

# 3. Apply changes
terraform apply -auto-approve

# 4. View Outputs
terraform output

13 to 19. State File (tfstate), Drift, Locals & Data Sources Core Concepts

What is terraform.tfstate?
Yeh ek JSON file hoti hai jisme Terraform record rakhta hai ki usne AWS par kaun kaun se actual resources banaye hain aur unke IDs kya hain. Is file ko kabhi manually edit nahi karte!

Data Source Example (Fetching dynamic AMI):

HCL Data Source
data "aws_ami" "latest_amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

20, 21, 22. Practical: Complete VPC, EC2 Web Server & Security Group Infrastructure Lab

HCL (infrastructure.tf)
# 1. VPC
resource "aws_vpc" "custom_vpc" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  tags                 = { Name = "Terraform-VPC" }
}

# 2. Public Subnet
resource "aws_subnet" "public_subnet" {
  vpc_id                  = aws_vpc.custom_vpc.id
  cidr_block              = "10.0.1.0/24"
  availability_zone       = "ap-south-1a"
  map_public_ip_on_launch = true
  tags                    = { Name = "Public-Subnet" }
}

# 3. Internet Gateway & Route Table
resource "aws_internet_gateway" "igw" {
  vpc_id = aws_vpc.custom_vpc.id
}

resource "aws_route_table" "public_rt" {
  vpc_id = aws_vpc.custom_vpc.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.igw.id
  }
}

resource "aws_route_table_association" "public_assoc" {
  subnet_id      = aws_subnet.public_subnet.id
  route_table_id = aws_route_table.public_rt.id
}

# 4. Security Group
resource "aws_security_group" "web_sg" {
  name   = "web-server-sg"
  vpc_id = aws_vpc.custom_vpc.id

  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

# 5. EC2 Web Server Instance
resource "aws_instance" "web_server" {
  ami                    = data.aws_ami.latest_amazon_linux.id
  instance_type          = "t3.micro"
  subnet_id              = aws_subnet.public_subnet.id
  vpc_security_group_ids = [aws_security_group.web_sg.id]

  user_data = <<-EOF
              #!/bin/bash
              yum install -y httpd
              systemctl start httpd
              systemctl enable httpd
              echo "
Deployed via Terraform on AWS
" > /var/www/html/index.html
              EOF

  tags = { Name = "Terraform-WebServer" }
}

23 to 28. Modules, S3 Remote State & DynamoDB Locking Enterprise Patterns

HCL Remote State Backend
terraform {
  backend "s3" {
    bucket         = "my-company-tf-state-bucket"
    key            = "prod/terraform.tfstate"
    region         = "ap-south-1"
    dynamodb_table = "terraform-state-locks"
    encrypt        = true
  }
}
Remote Backend Ka Fayda: Multiple developers ek saath kaam kar sakte hain aur DynamoDB state locking se koi doosra developer same time par apply karke state corrupt nahi kar sakta.

33. 50+ Terraform Interview Questions & Answers Interview Q&A

# Question Short & Clear Technical Answer (Hinglish)
1Terraform kya hai?HashiCorp ka open-source Infrastructure as Code tool jo cloud resources ko code se create karta hai.
2IaC kya hota hai?Infrastructure ko manually click karne ke bajaye code files ke dwara automate karna.
3State file (terraform.tfstate) kya hai?JSON database jo code mein likhe resources ko actual AWS cloud resource IDs se map karta hai.
4terraform init kya karta hai?Working directory initialize karta hai aur required provider plugins download karta hai.
5terraform plan kya karta hai?Changes ka dry-run preview dikhata hai bina actual cloud modify kiye.
6terraform apply kya karta hai?Code ke according actual cloud resources create ya update karta hai.
7terraform destroy kya karta hai?State file mein tracked saare cloud resources ko delete kar deta hai.
8Terraform Provider kya hota hai?Plugin jo Terraform ko AWS, Azure ya GCP ke APIs se connect karta hai.
9Data Source kya hota hai?Pehle se bane cloud resources (jaise existing VPC ya latest AMI) ka data read karna.
10Terraform Module kya hai?Reusable aur parameterized code block jo standard infrastructure banata hai.
11Remote State kyu use karte hain?Team collaboration, centralized state storage (S3) aur security ke liye.
12DynamoDB state locking kyu zaroori hai?Taaki do developers ek saath apply karke state file ko corrupt na karein.
13State Drift kya hota hai?Jab koi AWS Console mein manually resource change kar deta hai aur state code se mismatch ho jati hai.
14depends_on kab use karte hain?Jab do resources ke beech explicit dependency define karni ho jo Terraform auto-detect na kar paaye.
15terraform.tfvars file kya karti hai?Variables ke actual values assign karne ke liye use hoti hai.
16terraform fmt kya karta hai?HCL code ko automatically standard clean indentation format mein format karta hai.
17terraform import kya karta hai?Pehle se manually bane AWS resources ko Terraform state ke andar lekar aata hai.
18Workspace kya hota hai?Same code se multiple isolated environments (dev, stage, prod) manage karna.
19count vs for_each?count integer numbers par chalta hai; for_each maps ya unique string sets par chalta hai.
20Terraform vs CloudFormation?Terraform multi-cloud hai aur HCL use karta hai; CloudFormation sirf AWS ke liye hai aur JSON/YAML use karta hai.

34. Quick Revision Summary Summary

Terraform = Multi-cloud declarative IaC provisioning tool
Provider = Plugin connecting Terraform to AWS APIs
Resource = Infrastructure component (EC2, S3, VPC)
State = Single source of truth mapping code to cloud resources
Module = Reusable, parameterized Terraform component
