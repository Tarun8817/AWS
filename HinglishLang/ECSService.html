AWS ECS

Elastic Container Service

"Run, Deploy, Scale and Manage Docker Containers on AWS"

1. Amazon ECS Kya Hai? (Introduction) Theory

Amazon ECS (Elastic Container Service) ek highly scalable, fast, aur fully managed AWS container orchestration service hai jiska use Docker containers ko run, manage aur scale karne ke liye kiya jata hai.

Simple Definition:
"Amazon ECS ek aisi AWS service hai jo aapke Docker containers ko cloud mein automatically chalati hai, unki health monitor karti hai, fail hone par auto-restart karti hai, aur traffic badhne par scale karti hai bina kisi manual headache ke."

Core Concepts in Simple Words:

  • Docker Container: Ek lightweight, standalone executable package jisme aapka code, runtime, libraries aur dependencies bandhi hoti hain taaki application har environment mein same chale.
  • Container Orchestration: Jab 1 container ki jagah 50 ya 100 containers chalane ho, to kaun sa container kab start hoga, kaun se server par chalega, crash hone par restart kaun karega — ye saara automated management Container Orchestration kehlata hai.
  • Cluster: ECS resources ka logical grouping jahan Tasks aur Services run hote hain.
  • Task Definition: Ek JSON blueprint (recipe) jo ECS ko batati hai ki kaun si Docker image use karni hai, kitna CPU/Memory dena hai, aur kaun sa port open karna hai.
  • Task: Task Definition ka ek live running instance (actual running container).
  • Service: ECS ka controller jo ensure karta hai ki aapke specified number of tasks (Desired Count) hamesha 24/7 chalte rahein aur ALB se connected rahein.

Manual Docker vs Amazon ECS Problem & Solution

WITHOUT ECS (Manual Management - Complex & Risky): Developer ──> Launch EC2 Instance ──> SSH Login ──> Install Docker ──> docker run ──> Container [Problems: If server crashes, container dies. No auto-restart, manual scaling, zero HA] WITH ECS (Automated Orchestration): Docker Image ──> Amazon ECR ──> Amazon ECS (Cluster + Service) ──> Task (Fargate/EC2) ──> Live Application [Benefits: Auto-restart on crash, Auto-scaling on load, Zero-downtime rolling updates, ALB integration]

2. Container Orchestration Kya Hota Hai? Theory

Jab aap locally kaam karte hain, to docker run se 1 container chalana asan hota hai. Lekin real-world production systems mein:

  • 1 Container: Manually manage ho sakta hai. Agar crash hua to aapko pata nahi chalega jab tak customer complaint na kare.
  • 10 Containers: Port conflicts hone lagenge, CPU/RAM monitoring mushkil ho jayegi, updates ke time downtime aayega.
  • 100+ Containers: Impossible to manage manually! Multi-server networking, auto-scaling, load balancing aur zero-downtime deployments automate karni hi padengi.

ECS In Sabhi Cheezon Ko Automate Karta Hai:

1. Auto Starting & Stopping: Task definition ke hisaab se containers ko automated launch karna.
2. Self-Healing (Auto-Restart): Agar container crash ho jaye, to ECS turant naya container spin up kar deta hai.
3. Auto Scaling: CPU/RAM ya web request load badhne par tasks 2 se 10 automatically badha deta hai.
4. Load Balancing: Application Load Balancer (ALB) ke sath automatically targets register aur deregister karta hai.
5. Health Checks: Dead containers ko traffic bhejna band karke replace karta hai.
6. Zero-Downtime Deployments: Naya version pehle launch karta hai, healthy hone ke baad purane ko kill karta hai (Rolling Update).

5. ECS vs Docker Comparison

Bahut se beginners confuse hote hain ki Docker aur ECS mein kya difference hai. Docker ek tool hai container build aur run karne ke liye, jabki ECS ek AWS service hai un hazaron Docker containers ko enterprise scale par orchestrate karne ke liye.

Feature Docker (Standalone) Amazon ECS
Primary RoleContainer engine (Build & Run containers locally).Container Orchestrator on AWS cloud.
ScopeSingle machine / Laptop.Fleet of servers / Cloud scale.
High AvailabilityNo (Single host fail hua to container dead).Yes (Multi-AZ tasks distribution).
Auto-ScalingManual.Automated via CloudWatch & Target Tracking.
Load BalancerManual Nginx setup.Native AWS Application Load Balancer integration.
DeploymentManual docker stop / run.Automated Zero-downtime rolling update.

6. ECS vs EC2 Comparison

OS PatchingCustomer ki responsibility hoti hai.Fargate mein AWS sambhalta hai, EC2 launch type mein customer.

7 & 8. ECS Launch Types & AWS Fargate Compute

Amazon ECS mein containers ko run karne ke do primary compute modes hote hain:

TRADITIONAL EC2 LAUNCH TYPE: [ ECS Cluster ] ──> [ EC2 Instance (OS, Docker, ECS Agent) ] ──> [ Container ] (You manage OS updates, EC2 patching, capacity, and scaling) MODERN FARGATE LAUNCH TYPE (Serverless): [ ECS Cluster ] ──> [ AWS Fargate (Managed Compute) ] ──> [ Container ] (Zero EC2 management! Specify CPU/RAM, AWS manages everything underneath)
Feature ECS on EC2 ECS on AWS Fargate (Serverless)
Server ManagementManual (EC2 provisioning, OS updates, Docker daemon).None (Serverless — AWS handles everything).
Pricing ModelPay for EC2 instances 24/7 (regardless of container usage).Pay only for exact vCPU & Memory per second used by task.
Scaling SpeedSlow (New EC2 instance boot takes 2-5 minutes).Fast (Directly provisions ENI and spins up container).
OS / Host AccessFull SSH / root access to host VM.No host access (Task level logging & ECS Exec).
Beginner FriendlyModerate to Complex.Extremely Beginner Friendly (Recommended).
Best Use CaseConsistent predictable 24/7 load, GPU instances, custom kernels.Microservices, APIs, bursty traffic, web apps, rapid CI/CD.

11, 12, 13. Practical 1, 2, 3 – Local Docker App Practical

Sabse pehle hum ek clean Node.js Express application banayenge, Dockerfile likhenge, image build karenge aur locally test karenge.

Step 1: server.js

JavaScript (server.js) 
const express = require("express");
const app = express();
const PORT = process.env.PORT || 3000;

app.get("/", (req, res) => {
  res.send("Hello from ECS!");
});

app.get("/health", (req, res) => {
  res.status(200).json({ status: "healthy", timestamp: new Date().toISOString() });
});

app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});

Step 2: package.json

JSON (package.json) 
{
  "name": "ecs-demo-app",
  "version": "1.0.0",
  "description": "AWS ECS Beginner Demo App",
  "main": "server.js",
  "scripts": {
    "start": "node server.js"
  },
  "dependencies": {
    "express": "^4.19.2"
  }
}

Step 3: Dockerfile

Dockerfile 
# Base Image: Lightweight Node.js 20 on Alpine Linux
FROM node:20-alpine

# Set working directory inside container
WORKDIR /app

# Copy dependency files first (Leverage Docker layer caching)
COPY package*.json ./

# Install production dependencies
RUN npm install --only=production

# Copy application source code
COPY . .

# Document that container listens on port 3000
EXPOSE 3000

# Command to execute when container starts
CMD ["node", "server.js"]

Step 4: Build & Test Locally

Bash / PowerShell 
# 1. Build the Docker image
docker build -t ecs-demo .

# 2. Verify image was built
docker images

# 3. Run container locally mapping host port 3000 to container port 3000
docker run -d -p 3000:3000 --name my-local-app ecs-demo

# 4. Test in browser or curl
curl http://localhost:3000
# Output: Hello from ECS!

# 5. Stop local container
docker stop my-local-app

Feature Task Execution Role (executionRoleArn) Task Role (taskRoleArn)

When is it used?Task start hone se pehle (Startup time).Task chalte waqt runtime par (Application execution).

Step 3: Task Definition Configuration (JSON)

JSON (task-definition.json) 
{
  "family": "ecs-demo-task",
  "networkMode": "awsvpc",
  "requiresCompatibilities": ["FARGATE"],
  "cpu": "256",
  "memory": "512",
  "executionRoleArn": "arn:aws:iam::YOUR-AWS-ACCOUNT-ID:role/ecsTaskExecutionRole",
  "containerDefinitions": [
    {
      "name": "ecs-demo-container",
      "image": "YOUR-AWS-ACCOUNT-ID.dkr.ecr.YOUR-REGION.amazonaws.com/ecs-demo:latest",
      "essential": true,
      "portMappings": [
        {
          "containerPort": 3000,
          "hostPort": 3000,
          "protocol": "tcp"
        }
      ],
      "logConfiguration": {
        "logDriver": "awslogs",
        "options": {
          "awslogs-group": "/ecs/ecs-demo",
          "awslogs-region": "YOUR-REGION",
          "awslogs-stream-prefix": "ecs",
          "awslogs-create-group": "true"
        }
      }
    }
  ]
}

Key JSON Fields Explained:

  • family: Task definition ka unique name / family group.
  • networkMode: "awsvpc": Har Fargate task ko VPC ka apna dedicated Elastic Network Interface (ENI) aur Private IP milta hai.
  • requiresCompatibilities: Specifying FARGATE serverless compute.
  • cpu: "256": 0.25 vCPU (256 CPU units).
  • memory: "512": 512 MB RAM.
  • essential: true: Agar ye container fail hua to pura task terminate ho jayega aur restart hoga.

23 to 27. Create ECS Service & Access App Deployment

Task Definition banne ke baad hum ECS Service banate hain jo continuously tasks ko maintain karegi.

ECS SERVICE AUTO-HEALING WORKFLOW: Desired Count = 2 Service monitors: [ Task 1 (Healthy) ] and [ Task 2 (Healthy) ] │ (Task 2 crashes due to memory error) ▼ Service detects crash ──> Automatically terminates dead Task 2 │ ▼ Service provisions [ Task 3 (Brand new Task) ] ──> Desired count restored to 2!

Create Service in AWS Console:

  1. ECS Console mein apne cluster ecs-demo-cluster ko open karein.
  2. Services tab mein Create button click karein.
  3. Compute options mein Launch type: FARGATE select karein.
  4. Application type: Service select karein.
  5. Task definition: ecs-demo-task, Revision: 1 (latest) select karein.
  6. Service name: ecs-demo-service dein.
  7. Desired tasks: 1 (lab test ke liye) ya 2 (high availability ke liye).
  8. Networking: Default VPC ya custom VPC select karein, 2 public subnets select karein.
  9. Security Group: Naya create karein — Type Custom TCP, Port 3000, Source 0.0.0.0/0 (Lab testing purpose).
  10. Public IP: TURNED ON (Taaki direct test kiya ja sake agar ALB nahi hai).
  11. Click Create.

Accessing Direct Task IP (Practical 12):

Jab task ka status RUNNING ho jaye:

  • Service ke andar Tasks tab par click karein.
  • Running task par click karein aur Configuration / Networking tab dekhein.
  • Public IP copy karein aur browser mein open karein: http://<TASK-PUBLIC-IP>:3000
  • Screen par dikhai dega: Hello from ECS!

28 to 32. ECS + Application Load Balancer & Auto Scaling Production

Direct Task Public IP se production apps nahi chalayi jaati kyunki task restart hone par IP badal jata hai. Production mein hum Application Load Balancer (ALB) use karte hain.

=========================== ALB + ECS ARCHITECTURE =========================== Internet Traffic (Port 80/443) │ ▼ Application Load Balancer (ALB) │ ▼ Listener (Port 80) Target Group (Target Type = IP, Port 3000, Health Check: GET /health) │ ┌────┴────────────────────────┐ ▼ ▼ ECS Fargate Task 1 ECS Fargate Task 2 (IP: 10.0.1.45:3000) (IP: 10.0.2.78:3000) ==============================================================================

Step-by-Step ALB Setup:

  1. Create Target Group: EC2 Console -> Target Groups -> Create Target Group. Target type IP addresses select karein. Protocol HTTP, Port 3000. Health check path: /health.
  2. Create Application Load Balancer: Name ecs-demo-alb, Scheme Internet-facing, select VPC & minimum 2 public subnets in different AZs.
  3. Security Group for ALB: Inbound HTTP Port 80 from 0.0.0.0/0.
  4. Security Group for ECS Tasks: Inbound Port 3000 ONLY from ALB Security Group (Security Group Chaining).
  5. Attach ALB to ECS Service: ECS Service Update -> Load balancing -> Select ALB, container name, container port 3000, Target Group.

ECS Auto Scaling Setup (Practical 14):

Auto Scaling Policy: Target Tracking Scaling Policy
Metric: ECSServiceAverageCPUUtilization
Target Value: 60%
Min Capacity: 1 Task | Max Capacity: 4 Tasks
Jaise hi continuous traffic ki wajah se average CPU 60% se upar jayega, ECS automatically naye Fargate tasks launch kar dega.

33, 34, 35. ECS Deployment & Version Updates CI/CD

Golden Rule: ECR mein nayi image push kar dene se already running ECS tasks automatically update nahi hote. ECS ko batana padta hai ek New Task Definition Revision create karke ya Force New Deployment trigger karke.

Step-by-Step Application Update (Practical 15):

  1. server.js file edit karein: res.send("Hello from ECS Version 2!");
  2. Nayi image build karein: docker build -t ecs-demo:v2 .
  3. Image tag karein aur push karein:
    Bash
    docker tag ecs-demo:v2 YOUR-ACCOUNT-ID.dkr.ecr.YOUR-REGION.amazonaws.com/ecs-demo:v2
docker push YOUR-ACCOUNT-ID.dkr.ecr.YOUR-REGION.amazonaws.com/ecs-demo:v2
  4. ECS Console mein Task Definition ka naya revision (Revision 2) create karein jisme image URI :v2 ho.
  5. ECS Service ko update karein Revision 2 par -> Update Service.
  6. ECS automatically Rolling Deployment karega: Pehle naya V2 task launch karega, jab V2 ALB health check pass karega, tab purane V1 task ko terminate karega (Zero Downtime).

Rolling vs Blue/Green Deployments:

Deployment Type Kaise Kaam Karta Hai? Rollback Speed Cost During Deploy
Rolling Deployment (Default) Purane tasks ko step-by-step naye tasks se replace karta hai (minHealthyPercent & maxPercent ke mutabiq). Moderate (Purane version par re-deploy karna padta hai). Kam (Thode extra temporary tasks bante hain).
Blue/Green (AWS CodeDeploy) Ek pura separate Green task set banata hai, validation test ke baad ALB listener traffic ek saath switch karta hai. Instant (Traffic turant Blue environment par revert ho jata hai). Zyada (Deploy ke waqt 2x tasks parallel chalte hain).

44 to 49. Advanced ECS Features & Comparisons Deep Dive

ECS Service Discovery (AWS Cloud Map):
Microservices communication ke liye useful. Agar Frontend container ko Backend container call karna ho, to load balancer ki zaroorat nahi hoti; direct internal DNS http://backend.internal:5000 se call ho jata hai.
ECS Fargate Spot:
AWS ki unused compute capacity par Fargate tasks chalana. Regular Fargate se upar tak discount milta hai. Lekin AWS 2-minute notice dekar task reclaim kar sakta hai, isliye ye batch jobs aur stateless fault-tolerant apps ke liye best hai.

Task stops immediately (Essential container exited) Application startup crash (e.g. missing environment variable, syntax error in JS). CloudWatch Logs /ecs/ecs-demo. Container logs check karein. Local machine par same env vars ke sath docker run karke debug karein.
Task stuck in PENDING / PROVISIONING Subnet mein ENI IP capacity khatam ho gayi hai ya NAT Gateway / IGW route missing hai. VPC Route tables & Subnet available IPs. Public subnet mein Auto-assign public IP ON karein ya private subnet mein NAT Gateway route verify karein.

How to Check Stopped Reason in AWS Console:

  1. ECS Console -> Clusters -> ecs-demo-cluster -> Tasks tab.
  2. Filter mein Desired status: Stopped select karein.
  3. Stopped task par click karein.
  4. Stopped reason field padhein (e.g., OutOfMemoryError, CannotPullContainerError, Essential container in task exited).
  5. Niche Containers section expand karke Exit Code dekhein (Exit code 1 = App crash, 137 = Out of Memory kill).

56 & 57. ECS Cost Basics & Resource Cleanup Cost & Cleanup

CRITICAL COST WARNING: Practical lab finish hone ke baad sabhi AWS resources ko step-by-step delete karein, nahi to running ALB, NAT Gateway aur Fargate tasks ka unnecessary bill aayega!

Resource Pricing Components:

  • ECS Fargate: Per-second billing based on allocated vCPU and Memory.
  • Application Load Balancer (ALB): Hourly base charge + LCU (Load Balancer Capacity Units).
  • Amazon ECR: Standard S3 storage cost per GB of stored Docker images.
  • CloudWatch Logs: Ingestion & Storage per GB.

Clean Up Order (Deletion Steps):

  1. Delete ECS Service: ECS Service par click karke Delete karein (Force delete check karein).
  2. Delete ECS Cluster: Jab sabhi services aur tasks terminate ho jayein, cluster delete karein.
  3. Delete ALB & Target Group: EC2 Console -> Load Balancers -> Delete ALB -> Delete Target Group.
  4. Delete ECR Repository: ECR Console -> Repositories -> Select ecs-demo -> Delete.
  5. Delete CloudWatch Log Group: CloudWatch -> Log Groups -> /ecs/ecs-demo -> Delete.
  6. Delete Security Groups: EC2 Console -> Security Groups -> Delete lab specific security groups.

58 & 59. ECS Best Practices & Security Guidelines Best Practices

1. Use Versioned Image Tags: Production mein kabhi bhi sirf :latest tag par depend na karein. Hamesha Git commit SHA ya semantic version (v1.2.4) use karein.
2. Multi-Stage Docker Builds: Docker images ko lightweight banayein (Alpine base images) taaki image size 100MB se kam ho aur container jaldi launch ho.
3. Principle of Least Privilege: Task Role aur Execution Role mein strictly necessary permissions hi dein.
4. Keep Databases in Private Subnets: RDS / MongoDB instances ko kabhi public subnets mein na rakhein. Security Group chaining use karein.
5. Enable ECR Image Scanning: ECR mein Scan on push enable karein taaki container images ki vulnerabilities detect ho sakein.
6. Multi-AZ Deployment: High availability ke liye minimum 2 Availability Zones mein tasks distribute karein.

60. 40+ ECS Interview Questions & Answers Interview Q&A

# Question Answer (Short, Simple & Interview-Ready)
1Amazon ECS kya hai?AWS ki fully managed container orchestration service jo Docker containers ko cloud par run, manage aur scale karti hai.
2AWS Fargate kya hai?Serverless compute engine for ECS jisme EC2 servers manage kiye bina direct container chalaye ja sakte hain.
3ECS Cluster kya hota hai?ECS Tasks aur Services ka ek logical boundary grouping.
4ECS Task kya hai?Task Definition ka ek single live running instance (actual container execution).
5Task Definition kya hoti hai?JSON blueprint jo container image, CPU, RAM, ports aur environment variables define karti hai.
6ECS Service kya karti hai?Specified Desired Count tasks ko 24/7 maintain karti hai, crash hone par restart karti hai aur ALB se connect karti hai.
7Task aur Service mein kya antar hai?Task ek temporary running container hai; Service ek continuous controller hai jo tasks ko maintain aur scale karta hai.
8Amazon ECR kya hai?AWS ki private Docker container image registry.
9ECS aur ECR mein kya relation hai?ECR mein image store hoti hai; ECS us image ko pull karke container run karta hai.
10ECS on EC2 vs Fargate mein kya difference hai?EC2 mein underlying servers aap manage karte hain; Fargate mein AWS underlying infrastructure sambhalta hai (Serverless).
11Desired Count kya hota hai?Vo number jo batata hai ki kitne tasks hamesha live aur running rehne chahiye.
12Task Execution Role kya hota hai?Role jo ECS agent ko ECR se image pull karne aur CloudWatch mein logs bhejne ki permission deta hai.
13Task Role kya hota hai?Role jo container ke andar chalne wale code ko AWS services (S3, DynamoDB) access karne ki permission deta hai.
14Execution Role vs Task Role ka main difference?Execution Role = ECS agent ke liye (Startup time); Task Role = Application code ke liye (Runtime).
15awsvpc network mode kya hai?Network mode jisme har ECS task ko VPC ka apna dedicated ENI aur Private IP milta hai.
16Port Mapping kya hoti hai?Host port aur container port ke beech connection banana taaki bahar se traffic container tak pahuche.
17ECS mein health check kaise kaam karta hai?ALB target group regular HTTP requests (e.g. GET /health) bhejkar check karta hai ki container 200 OK de raha hai ya nahi.
18Agar ECS task crash ho jaye to kya hoga?ECS Service crash ko detect karegi aur turant desired count maintain karne ke liye naya task launch kar degi.
19Application Load Balancer (ALB) ECS ke sath kyu use karte hain?Dynamic task IPs par traffic distribute karne, HTTPS terminate karne aur zero-downtime rolling updates ke liye.
20Target Group kya hota hai?ALB ke targets (ECS Task IPs) ki logical grouping jahan requests forward hoti hain.
21ECS Service Auto Scaling kaise kaam karti hai?CloudWatch metrics (CPU/RAM utilization) ke basis par desired task count automatically badhati ya ghatati hai.
22Stopped task ka reason kaise check karte hain?ECS Console -> Tasks -> Stopped Tasks -> Stopped reason aur container Exit code dekhkar.
23Task Exit Code 137 ka kya matlab hai?Container ne allocated memory limit cross kar di aur Linux OOM (Out of Memory) killer ne usko kill kar diya.
24CannotPullContainerError ka main reason kya hota hai?Galat ECR image URI, missing internet route/NAT Gateway ya Execution Role permissions missing.
25Fargate Spot kya hai?AWS ki spare compute capacity par tasks chalana deep discounts ke sath (stateless/fault-tolerant apps ke liye).
26Capacity Provider kya hota hai?ECS cluster ke liye compute infrastructure (Fargate, Spot, EC2 ASG) management provider.
27ECS Service Discovery kya hai?AWS Cloud Map ke through microservices ko internal DNS names (e.g. api.local) se communicate karwana.
28ECS vs EKS kab choose karein?Agar simple AWS native serverless container chahiye to ECS; agar multi-cloud standard Kubernetes chahiye to EKS.
29ECS container logs kahan jate hain?Task definition mein configure kiye gaye Amazon CloudWatch Log Group (awslogs) mein.
30Secrets ko ECS mein securely kaise inject karein?AWS Secrets Manager ya SSM Parameter Store ke through Task Definition ke secrets block mein define karke.
31Rolling Deployment kya hota hai?Naye container version ko step-by-step launch karna aur purane ko terminate karna bina application downtime ke.
32Blue/Green deployment ECS mein kaise hoti hai?AWS CodeDeploy ke through Green environment launch karke validation ke baad ALB listener traffic shift kiya jata hai.
33Kya ECR mein image push karne se task auto-update hota hai?Nahi, ECS Service mein new task definition revision deploy karna ya --force-new-deployment run karna padta hai.
34Essential Container ka kya matlab hai?Agar essential container fail hota hai, to ECS pura task stop kar deta hai.
35ECS Task Definitions versioned hoti hain?Haan, har edit par naya Revision number (e.g. :1, :2, :3) create hota hai.
36ECS Task S3 ko access kaise karta hai?Task Role mein S3 policy attach karke, bina kisi hardcoded AWS access key ke.
37ECS task RDS database se kaise connect karta hai?Task Security group ko RDS Security group ke inbound rules mein allow karke via private subnets.
38Fargate task ko private subnet mein internet kaise milta hai?VPC ke public subnet mein lage NAT Gateway ke through.
39ECS Exec kya hota hai?Running Fargate/EC2 container ke andar bina SSH ke direct interactive shell access (debugging) lene ka feature.
40ECS deployment rollback kaise karte hain?ECS Service update karke previous working Task Definition revision (e.g. Revision 1) select kar lete hain.
