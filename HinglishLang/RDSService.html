AWS RDS (Relational Database Service)

Beginner-friendly study note — Hinglish edition — padhai, revision, interview aur print ke liye.

1. AWS RDS kya hai?

AWS RDS = Amazon Relational Database Service

Aasaan definition RDS AWS ka managed database service hai. Isme hume database server ki bahut saari manual administration khud nahi karni padti. AWS backups, patching, monitoring, maintenance aur scaling jaise kaam manage karne mein help karta hai.

Matlab RDS ki help se relational databases ko banana, chalana, manage karna, backup lena, monitor karna aur scale karna aasaan ho jata hai.

Database kya hota hai?

Database ek organised jagah hai jahan application apna data store karti hai, taaki baad mein us data ko save, search, update aur delete kar sake. Jaise: users, orders, products.

Relational database kya hota hai?

Relational database mein data tables (rows aur columns) mein hota hai, aur tables ek doosre se keys ke through connected ho sakti hain. Isse baat karne ke liye SQL language use hoti hai. Examples: MySQL, PostgreSQL.

idnameemail
1Taruntarun@example.com
2Riyariya@example.com

“Managed service” ka matlab kya hai?

Managed service ka matlab hai ki server, hardware, OS-level maintenance, backup features jaise bahut saare infrastructure ke kaam AWS sambhalta hai, aur hum apni application par focus kar sakte hain. Lekin data, settings aur security configuration ki responsibility abhi bhi hamari hoti hai.

RDS kyun use karte hain? Ye kaunsi problem solve karta hai?

RDS ke bina (khud server par MySQL)RDS ke saath
MySQL install karo, server configure karo, backups, updates, security, monitoring sab khud manage karo. Infrastructure aur database administration ka bahut saara kaam AWS karta hai. Hum mainly database create, configure aur use karte hain.
Dhyan rakho RDS har DBA ka kaam khatam nahi karta. Table design, achhi queries likhna, users banana, performance tuning aur security config abhi bhi hamari zimmedari hai.

DB engine asli database software hota hai. RDS mein aap inme se choose kar sakte ho:

PostgreSQLOpen-source relational database, advanced features ke liye famous.
MariaDBMySQL se nikla hua open-source database, kaafi had tak MySQL-compatible.

MERN aur RDS Normal MERN application mein MongoDB use hota hai, RDS nahi, kyunki MongoDB ek NoSQL database hai. Lekin agar MERN application ke backend ko relational MySQL/PostgreSQL database chahiye, to RDS use kar sakte hain.

RDS in administrative kaamon ko handle karta hai ya unme help karta hai:

Automated backupsDaily backup aur logs automatically bante hain; kitne din rakhna hai (retention period) wo hum set karte hain.
Software patchingEngine ke updates aur security patches maintenance window mein lag sakte hain.
MonitoringCPU, memory, storage, connections ko CloudWatch mein dekh sakte hain.

Yaad rakho Ye features available hote hain, aur kai baar inhe hume khud enable ya configure karna padta hai (jaise Multi-AZ, backup retention, encryption). RDS har administration task apne aap nahi kar deta.

6. AWS RDS MySQL Database Kaise Banayein

Console ki screens thodi badal sakti hain, lekin flow wahi rehta hai.

  1. AWS Console mein login karo.
  2. Search bar mein RDS type karo.
  3. Amazon RDS kholo.
  4. Create database par click karo.
  5. Standard create choose karo (saare options milte hain). Easy create simple hai, kam options aur default settings ke saath — pehli baar try karne ke liye theek hai.
  6. Engine select karo: MySQL.
  7. Agar aapke account/region mein available ho to Free Tier template choose karo.
  8. Sahi DB instance size choose karo (learning ke liye chhota burstable class jaise db.t3.micro common hai).
  9. DB instance identifier set karo: my-mysql-db
  10. Master username set karo: admin
  11. Ek strong password set karo.
  12. Sahi storage choose karo (learning ke liye default chhota size theek hai).
  13. Connectivity configure karo.
  14. VPC: sahi VPC use karo (practice ke liye default VPC chalta hai).
  15. Public access: neeche explanation dekho.
  16. Security group: naya banao, jaise rds-mysql-sg.
  17. Port: 3306.
  18. Create database par click karo aur status Available hone tak wait karo.
Username aur password ke rules AWS kuch username/password formats ko restrict kar sakta hai (length, kuch characters). Console jo password requirements dikhaye, unhe follow karo. Exact rules selected RDS engine aur configuration par depend karte hain, isliye ye mat maano ki special characters hamesha allowed ya hamesha forbidden hain. Agar console kisi character ko reject kare, to password badal do.

“Public access = Yes” ka matlab kya hai?

Iska matlab hai ki DB instance ko publicly resolvable address mil sakta hai, taaki VPC ke bahar se use reach kiya ja sake. Sirf isse database sabke liye khul nahi jata. Public access tabhi DB ko publicly reachable network path deta hai jab VPC/subnet/security configuration bhi allow kare (internet gateway ka route, security group rules, network ACLs).

Practice setup summary (sirf learning ke liye) Engine: MySQL • Template: Free tier (agar available ho) • ID: my-mysql-db • Username: admin • Public access: Yes (sirf tab jab laptop se connect karna ho) • Naya SG: rds-mysql-sg • Port: 3306.

Port 3306 kya hai?

Port server ka ek numbered darwaza hai. MySQL default rup se darwaza number 3306 par sunta hai, isliye client ko isi port par connect karna hota hai.

7. Security Group

Security Group aapke AWS resource ke liye ek virtual firewall jaisa kaam karta hai. Ye tay karta hai ki kaun, kis port aur protocol par connect kar sakta hai.

MySQL ke liye inbound rule

x.x.x.x/32 (My IP)Bilkul ek IP address — aapka apnaLocal testing ke liye better.

Rule Production database ko bina zarurat public internet par expose mat karo.

9. AWS ke Bahar Se RDS MySQL Kaise Access Karein

A) Apne local laptop se

Requirements:

  • Agar direct public connectivity chahiye, to RDS ka Public access enable hona chahiye.
  • Security Group mein aapke current public IP se TCP 3306 allow hona chahiye.
  • Network ACL / route table / subnet configuration connectivity allow kare (public subnet, internet gateway ka route).
  • Laptop par MySQL client installed ho.

Ye security group rule prefer karo:

Type: MySQL/Aurora   Protocol: TCP   Port: 3306
Source: My IP  →  x.x.x.x/32

0.0.0.0/0 ke bajay.

Kyun? /32 ka matlab bilkul ek IP, isliye sirf aapki machine DB port tak pahunch sakti hai. 0.0.0.0/0 ka matlab koi bhi IPv4 address, yani koi bhi connect karne aur password guess karne ki koshish kar sakta hai. Ghar ke internet ka IP aksar badalta rehta hai, isliye achanak timeout aaye to rule mein naya IP update karo.

Command:

mysql -h <RDS-ENDPOINT> -P 3306 -u admin -p

Example:

mysql -h my-mysql-db.xxxxxxxxx.eu-north-1.rds.amazonaws.com -P 3306 -u admin -p

Enter dabane ke baad MySQL password maangta hai (Enter password:). Password type karo (screen par dikhega nahi) aur Enter dabao.

B) EC2 se (applications ke liye recommended)

Agar EC2 aur RDS same VPC mein hain, to application normally RDS endpoint se connect ho jati hai, database ko public banaye bina.

Internet | v EC2 / Application | v (VPC ke andar private connection) RDS MySQL RDS Security Group: TCP 3306 allow Source = EC2 Security Group

Ye poore internet ke liye MySQL kholne se kaafi safe hai.

Tip Agar connect na ho paye, to Common Connection Errors dekho.

10. Node.js se RDS Connect Karna

Pehle package install karo:

npm install mysql2
const mysql = require("mysql2");

const connection = mysql.createConnection({
  host: process.env.DB_HOST,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  port: 3306
});

connection.connect((err) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log("Connected to RDS MySQL");
});

Line-by-line Hinglish explanation

  • require("mysql2") — mysql2 library import karta hai, jo Node.js ko MySQL se baat karne deti hai.
  • createConnection({...}) — connection ki settings banata hai (abhi connect nahi hota).
  • host: process.env.DB_HOST — RDS endpoint. Code mein likhne ke bajay environment variable se aata hai.
  • user aur password — DB ka username/password, ye bhi environment variables se.
  • database — kaunsa database use karna hai (jaise myapp).
  • port: 3306 — MySQL ka port. (Aap process.env.DB_PORT bhi use kar sakte ho.)
  • connection.connect((err) => {...}) — ab actual connection try karta hai. Agar err hai to connection fail hua, aur error print hota hai.
  • console.log("Connected to RDS MySQL") — success ka message.
Source code mein password hard-code mat karo Environment variables use karo. Asli password kabhi aisi file mein mat likho jo GitHub par jaati hai.

Example .env file (.env ko .gitignore mein daalo):

DB_HOST=
DB_USER=
DB_PASSWORD=
DB_NAME=
DB_PORT=3306

Values jaanbujhkar khali chhodi hain: inhe apni machine ya server par bharo. Node.js mein .env file load karne ke liye dotenv package use kar sakte ho; Docker mein inhe -e flags se pass karte hain.

11. EC2 + Docker + RDS

EC2 instance par aapki Node.js app Docker container mein chal sakti hai, jabki database RDS par rehta hai.

Internet | v EC2 | v Docker Container | v Node.js + Express | v AWS RDS MySQL
Main idea Database ko Docker container ke andar chalane ki zarurat NAHI hai. Application container RDS endpoint use karke RDS se connect hota hai.

Ye achha kyun hai? Container ko aasani se stop, replace ya rebuild kar sakte hain, aur data RDS mein safe rehta hai (backups aur monitoring ke saath).

12. EC2 Commands

Ye commands apne EC2 instance (Amazon Linux) par chalao. Rough notes ki spelling correct ki gayi hai (jaise usermod, “usermond” nahi).

1) Docker install karo

sudo yum install -y docker

yum package manager se Docker install hota hai. -y ka matlab har sawal par automatically “yes”. (Naye Amazon Linux 2023 mein dnf bhi use hota hai; wahan yum bhi chalta hai.)

2) Docker start karo

sudo systemctl start docker

Docker service ko abhi start karta hai. Purane notes mein sudo service docker start dikhta hai, jo kai Amazon Linux systems par bhi chalta hai; systemctl modern tareeka hai.

3) Reboot ke baad bhi Docker enable rakho

sudo systemctl enable docker

Server restart hone par Docker apne aap start ho jayega.

4) ec2-user ko docker group mein add karo

sudo usermod -aG docker ec2-user

-aG matlab append to Group. Iske baad ec2-user bina sudo ke Docker chala sakta hai, lekin change apply hone ke liye pehle logout karke phir login karna pad sakta hai.

5) Docker version check karo

docker --version

6) Docker service status check karo

sudo systemctl status docker

active (running) dikhna chahiye. Bahar nikalne ke liye q dabao.

7) Example image pull karo

docker pull philippaul/node-mysql-app:02
Important philippaul/node-mysql-app:02 sirf ek example image hai jo public Docker Hub account se hai. Ye official AWS image nahi hai. Sirf wahi images chalao jin par aapko bharosa ho ya jo aapne khud banayi ho, aur dekho ki image kaunse environment variables expect karti hai.

8) Container chalao

Ise tabhi chalao jab aapko RDS endpoint, credentials aur app ke expected variable names pata hon. Application ko RDS endpoint aur credentials ke saath configure karna zaroori hai. Agla section dekho.

14. Database / Table Banana

Pehle mysql client se connect karo, phir ye chalao:

CREATE DATABASE myapp;

USE myapp;

CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(150) UNIQUE,
    password VARCHAR(255)
);

-- Insert example (password hash hai, plain text nahi)
INSERT INTO users (name, email, password)
VALUES ('Tarun', 'tarun@example.com', '$2b$10$exampleHashedPasswordHere');

-- Select example
SELECT id, name, email FROM users;

Hinglish explanation

  • CREATE DATABASE myapp; — myapp naam ka naya database banata hai.
  • USE myapp; — MySQL ko batata hai ki ab isi database mein kaam karna hai.
  • CREATE TABLE users (...) — users naam ki table banata hai.
  • id INT AUTO_INCREMENT PRIMARY KEY — har row ka unique number, jo apne aap badhta hai.
  • name VARCHAR(100) — naam text ke roop mein, max 100 characters.
  • email VARCHAR(150) UNIQUE — same email do baar save nahi ho sakta.
  • password VARCHAR(255) — yahan password hash store hota hai (hash lamba hota hai, isliye 255).
  • INSERT INTO ... VALUES ... — nayi row (user) add karta hai.
  • SELECT ... FROM users; — table se data dikhata hai. Password column select karna aksar zaruri nahi hota.

15. RDS Storage

  • Storage type: disk ka type (jaise General Purpose SSD ya Provisioned IOPS SSD). Ye speed aur cost par asar daalta hai.
  • Allocated storage: creation ke time kitne GB reserve kiye, jaise 20 GB.
  • Storage autoscaling: data badhe to storage automatically badhne ke liye configure kiya ja sakta hai, lekin aapke set kiye hue maximum limit ke andar.

Example: Aap 20 GB se shuru karte ho aur maximum 100 GB set karte ho. App badhne par storage bina manual kaam ke 100 GB tak ja sakta hai.

Storage scaling aur compute scaling alag hain Zyada storage se sirf disk space badhta hai. CPU ya RAM nahi badhti. CPU/RAM ke liye DB instance class badalni padti hai (Scaling dekho).

16. RDS Backups

Automated backups

RDS roz backup le sakta hai aur transaction logs automatically save karta hai, jo aapke chune hue retention period tak rehte hain. Isse us period ke andar point-in-time recovery ho sakti hai, yani kisi purane time par database wapas la sakte hain.

Manual snapshots

Snapshot wo backup hai jo aap khud kisi khaas moment par banate ho (jaise “update se pehle ki photo”). Ye tab tak rehta hai jab tak aap ise delete na karo.

Backup vs Snapshot

Automated BackupManual Snapshot
Kaun banata haiRDS automaticallyAap khud
RetentionAapke set kiye retention period takJab tak aap delete na karo
Restore optionPoint-in-time recoveryUs snapshot ke moment tak restore
Kab kaam aata haiRoz ki safetyBade change se pehle, DB delete karne se pehle

Restore karne par naya DB instance banta hai; phir aapko app ko naye endpoint par point karna padta hai.

17. RDS Multi-AZ

Multi-AZ ka matlab hai ki RDS aapke database ki ek standby copy doosri Availability Zone (AZ) mein rakhta hai. Primary mein problem aaye to RDS standby par failover kar sakta hai.

Yaad rakho Multi-AZ mainly high availability aur failover ke liye hai. Ye reads ko fast karne ke liye nahi hai.
Availability Zone A Availability Zone B +---------------+ sync +---------------+ | Primary DB | ------> | Standby DB | +---------------+ copy +---------------+ App ek hi endpoint use karti hai; failure par wo standby par point hota hai

Simple example: Zone A mein aapke main database server mein hardware problem aa gayi. Multi-AZ ke saath RDS Zone B ke standby par switch kar deta hai, aur thodi der ke interruption ke baad aapki app chalti rehti hai.

Multi-AZ mein extra standby capacity ka paisa lagta hai, isliye cost zyada hoti hai.

18. Read Replica

Read Replica database ki ek extra copy hai jo read queries (SELECT) serve karti hai, jisse main DB par load kam hota hai.

Main DB -> writes (INSERT / UPDATE / DELETE) Read Replica -> reads (SELECT)

Example: Ek blog site par lakhon readers hain lekin writers bahut kam. Reads replicas ko bhejo aur main DB ko writes ke liye rakho. Replica main DB se thoda peeche (lag) ho sakta hai.

Multi-AZ vs Read Replica

FeatureMulti-AZRead Replica
Main purposeHigh availability aur failoverRead scaling / performance
Reads ke liye?Standby normally failover ke liye hota hai, app ke reads ke liye nahi (standard single-standby setup mein)Haan, app SELECT queries iske paas bhejti hai
Data copySynchronous (standby sath-sath update)Asynchronous (thoda lag ho sakta hai)
Automatic failoverHaan, isi ke liye bana haiIska purpose nahi; promotion alag action hai
EndpointApp ke liye wahi endpointIska apna endpoint
Dono ko mix mat karo Multi-AZ = safety / uptime. Read Replica = extra read capacity. Ye alag features hain aur dono ek saath bhi use ho sakte hain.

21. RDS Security

  • Security Groups: firewall rules; 3306 par sirf zaroori sources allow karo.
  • Private subnets: DB ko aisi jagah rakho jahan internet ka direct route na ho.
  • IAM (jahan applicable ho): AWS mein RDS ko kaun manage kar sakta hai ye control karta hai; kuch engines ke liye IAM database authentication bhi milta hai.
  • Encryption: data at rest (storage, backups, snapshots) AWS KMS se encrypt karo. Ise creation ke time choose karna best hai.
  • SSL/TLS connections: app aur DB ke beech travel karte data ko encrypt karta hai.
  • Secrets Manager: DB credentials code mein rakhne ke bajay yahan store aur rotate karo.
  • Strong passwords: lambe aur unique, console ke rules follow karte hue.
  • Least privilege: app users ko sirf zaroori permissions do, admin power nahi.
  • Production mein public access avoid karo jab uski zarurat na ho.
Production ke liye preference EC2 → Private RDS  na ki  Internet → Public RDS

  2. Dekho ki RDS security group aapke public IP ko TCP 3306 par allow karta hai aur DB publicly accessible hai.
  3. Command Prompt ya PowerShell kholo aur ye chalao:
mysql -h <RDS-ENDPOINT> -P 3306 -u admin -p

-Pport (capital P = 3306)
-uusername
-ppassword maango (small p)

Dhyan rakho: -P (capital) port hai aur -p (small) password prompt. Dono alag hain.

Ye cheezein connection rok sakti hain Windows Firewall, aapka local network, ISP restrictions, AWS networking, security group rules, subnet routing aur RDS public accessibility — sab connectivity par asar daal sakte hain.

24. Common Connection Errors

1) Connection timed out

Request DB tak pahunchi hi nahi ya jawab nahi mila. Possible causes:

  • Security Group aapke IP / EC2-SG ko 3306 par allow nahi karta
  • Public access disabled hai (bahar se connect karte time)
  • Network routing / subnet / NACL problem
  • Galat endpoint
  • Galat port

2) Access denied for user

DB tak pahunch gaye, lekin login fail hua. Possible causes:

  • Galat username
  • Galat password
  • User ke paas us database/host ki permission nahi hai

3) Unknown host

  • Galat endpoint (typo, extra space, galat region)
  • Aapki taraf DNS / network issue

4) Can’t connect to MySQL server

Ye ek general error hai. Check karo: DB status Available hai, endpoint aur port sahi hain, security group aur public access settings sahi hain, aapka network outbound 3306 allow karta hai, aur client hostname resolve kar pa raha hai.

Troubleshooting checklist

  • DB status Available hai?
  • Sahi endpoint use kar raha hoon (koi typo nahi)?
  • Port 3306 hai?
  • RDS security group sahi source (mera current IP ya EC2-SG) se TCP 3306 allow karta hai?
  • Laptop se connect kar raha hoon to Public access enabled hai aur subnet ka internet route hai?
  • Mera public IP abhi bhi wahi hai jo rule mein hai?
  • Username aur password sahi hain?
  • Kya mera Windows Firewall / office / ISP network outbound 3306 block kar raha hai?
  • EC2 se connect karte time: EC2 aur RDS same VPC mein hain, aur EC2-SG source set hai?

25. RDS Delete / Stop / Cost

Kya RDS ko stop kar sakte hain?

Kai configurations mein haan: DB instance ko temporarily stop kar sakte hain. Stop temporary hota hai, aur ek maximum period ke baad (jaise lagbhag 7 din) RDS instance ko apne aap dobara start kar sakta hai. Kuch configurations (jaise kuch Multi-AZ ya read-replica setups) mein restrictions ho sakti hain.

ActionKya hota hai
StopInstance temporarily pause hota hai. Compute charges ruk jaate hain, lekin storage (aur backup storage) ka charge lag sakta hai.
DeleteInstance permanently hat jata hai. Pehle final snapshot bana sakte ho. Snapshot ke bina data lost ho sakta hai.
SnapshotKisi moment par DB ka saved backup. Baad mein restore ke kaam aata hai aur storage charges bhi lag sakte hain.
Cost warning RDS resources par configuration aur usage ke hisaab se charges lag sakte hain (instance hours, storage, backups, data transfer, Multi-AZ, replicas). Free Tier eligibility aapke AWS account, service configuration, region aur AWS ke current terms par depend karti hai. Ye mat maano ki har RDS configuration free hai. Current AWS Free Tier page aur billing dashboard check karte raho, aur practice ke baad kaam ke na rahe databases delete kar do.

26. Interview Questions & Answers

Q1. AWS RDS kya hai?
AWS ka managed relational database service, jo MySQL, PostgreSQL jaise databases ko banana, chalana, backup, monitor aur scale karna aasaan banata hai.
Q2. Hum RDS kyun use karte hain?
Manual database administration kam karne ke liye: AWS setup, backups, patching, monitoring, availability aur scaling mein help karta hai, taaki developers application par focus kar sakein.
Q3. Kya RDS ek database hai?
Nahi. RDS ek service hai jo database engines (MySQL, PostgreSQL, etc.) ko chalati aur manage karti hai. Engine hi asli database hota hai.
Q4. Managed database service kya hoti hai?
Aisi service jisme provider infrastructure aur routine administration ka bahut kaam sambhalta hai, aur hum apna data, schema, access aur configuration manage karte hain.
Q5. RDS endpoint kya hai?
Wo hostname jisse applications DB instance se connect karti hain. RDS console mein Connectivity & security mein dikhta hai.
Q6. MySQL kaunsa port use karta hai?
Default 3306.
Q7. EC2 instance RDS se kaise connect ho sakta hai?
Dono same VPC (ya connected networks) mein rakho, RDS security group mein EC2 security group se TCP 3306 allow karo, aur app se RDS endpoint, port, username aur password use karke connect karo.
Q8. Multi-AZ kya hai?
Doosri Availability Zone mein standby DB rakhne ka setup, high availability aur automatic failover ke liye. Ye read scaling ke liye nahi hai.
Q9. Read Replica kya hai?
DB ki ek copy jo read queries serve karti hai aur main DB ka load kam karti hai. Ye read scaling ke liye hai.
Q10. RDS aur EC2 par host kiye MySQL mein kya difference hai?
RDS mein AWS managed features deta hai (backups, patching options, monitoring, Multi-AZ options) aur hume kam infrastructure manage karna padta hai. EC2 par MySQL mein OS, MySQL, backups, updates aur HA sab khud manage karna padta hai: control zyada, mehnat bhi zyada.
Q11. Production mein 3306 ko 0.0.0.0/0 se allow kyun nahi karna chahiye?
Isse koi bhi IPv4 address connect karne ki koshish kar sakta hai, jisse brute-force attacks aur exploitation ka risk bahut badh jata hai. Sirf app security group ya trusted IPs allow karo.
Q12. Kya hum RDS ko apni local machine se access kar sakte hain?
Haan, agar DB publicly accessible ho, network path routed ho, aur security group aapke IP ko 3306 par allow kare, to MySQL client se. Production mein app/EC2, bastion host ya VPN ke through access prefer karo.
Q13. Security Group kya hai?
Ek virtual firewall jo protocol, port aur source ke hisaab se AWS resources ka inbound aur outbound traffic control karta hai.
Q14. Public aur private RDS mein kya difference hai?
Public RDS network aur security rules allow karein to internet se reachable ho sakta hai. Private RDS internet se direct reachable nahi hota, VPC ke andar se access hota hai — production ka common choice.
Q15. Node.js application ko RDS se kaise connect karoge?
mysql2 install karo, host, user, password, database aur port environment variables se lo, unse connection (ya pool) banao, aur ensure karo ki app ka security group RDS port 3306 par allowed hai.

27. Important Real-World Architecture

ComponentKaam
UsersBrowser ya phone par app use karne wale log.
React FrontendUser interface (screen); API requests bhejta hai.

Version 2: Production ke zyada kareeb

Users | v Load Balancer | v EC2 / ECS | v Private RDS | v Database
  • Load Balancer: traffic ko multiple app servers mein baant deta hai aur health checks kar sakta hai.
  • EC2 / ECS: multiple app instances ya containers.
  • Private RDS: database private subnets mein, sirf app ke security group se reachable.
Production mein RDS aksar private kyun hota hai? Users ko sirf app se baat karni hoti hai, database se direct kabhi nahi. Private DB ka internet par direct route nahi hota, isliye attack surface bahut chhota hota hai. Kisi ko endpoint pata chal bhi jaye, wo internet se connect nahi kar sakta.
