AWS CLI Configuration & Complete Guide

Terminal se AWS commands chalane ke liye AWS CLI install, configure aur use karna — beginner-friendly Hinglish notes.

1️⃣ AWS CLI Kya Hai?

Theory

AWS CLI (Command Line Interface) ek tool hai jisse aap apne terminal ya command prompt se AWS services (EC2, S3, IAM, Lambda, etc.) ko manage kar sakte ho — bina AWS Console (browser) khole.

Simple bhasha mein — jo kaam aap AWS Console mein click karke karte ho, wahi kaam aap ek command likh ke terminal se kar sakte ho.

Real-world example Agar aapko 50 S3 buckets ki list check karni ho, to Console mein baar baar click karna slow hoga. AWS CLI se sirf ek command aws s3 ls chala ke turant poori list mil jaati hai — aur ye script/automation mein bhi use ho sakta hai.

💡 AWS CLI Kyu Use Karein?

Theory
  • Automation — Scripts (bash/python) ke through AWS resources create/manage kiye ja sakte hain.
  • Speed — Console mein multiple clicks ki jagah ek command se kaam ho jaata hai.
  • Repeatability — Same command baar baar reliably chalaya ja sakta hai.
  • CI/CD Integration — Deployment pipelines (Jenkins, GitHub Actions) mein AWS CLI commonly use hota hai.
  • Bulk Operations — Multiple resources ek saath manage karna (jaise sabhi unused snapshots delete karna).
  • Remote Server Access — EC2/servers pe GUI nahi hoti, wahan CLI hi ek tarika hota hai AWS ko access karne ka.

📋 Prerequisites

Theory
  • Ek AWS Account hona chahiye.
  • Ek IAM User jiske paas programmatic access ho (Section 8 mein steps hain).
  • Computer pe internet connection aur terminal/command prompt access.
  • Basic terminal commands ki familiarity (cd, ls/dir).

🪟 Install AWS CLI (Windows)

Practical
  1. AWS ki official CLI installer page se AWS CLI MSI installer download karo.
  2. Downloaded .msi file pe double-click karo.
  3. Installation wizard ke instructions follow karo (Next → Next → Install).
  4. Installation complete hone ke baad, Command Prompt ya PowerShell naya window kholo.
  5. Verify karne ke liye niche diya command run karo (Section 7).

Alternative: agar winget installed hai, to seedha ye command bhi chala sakte ho:

winget install -e --id Amazon.AWSCLI

🍎 Install AWS CLI (macOS)

Practical

Terminal kholke ye command chalao (official .pkg installer download aur install karta hai):

curl "https://awscli.amazonaws.com/AWSCLIV2.pkg" -o "AWSCLIV2.pkg"
sudo installer -pkg AWSCLIV2.pkg -target /

Ya phir Homebrew use karke bhi install kar sakte ho:

brew install awscli
Command breakdown curl — file ko internet se download karta hai. -o "AWSCLIV2.pkg" — downloaded file ka naam set karta hai. sudo installer -pkg ... -target / — admin permission ke saath package install karta hai poore system pe.

🐧 Install AWS CLI (Linux)

Practical

Linux (64-bit) ke liye ye standard steps hain:

curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
unzip awscliv2.zip
sudo ./aws/install
Command breakdown curl ... -o "awscliv2.zip" — installer ki zip file download karta hai. unzip awscliv2.zip — zip file ko extract karta hai. sudo ./aws/install — extracted installer script ko admin rights se chalake CLI install karta hai.

Amazon Linux/RHEL/Fedora pe agar pehle se unzip nahi hai to pehle install karo:

sudo dnf install -y unzip

✅ Verify Installation

Practical

Installation successful hui ya nahi, ye check karne ke liye terminal mein run karo:

aws --version

Agar sahi se install hua hai, to output kuch aisa dikhega:

aws-cli/2.17.0 Python/3.11.6 Linux/6.5.0 exe/x86_64.amzn.2
Command not found error? Agar aws --version "command not found" bolta hai, to terminal band karke naya terminal window kholo (PATH refresh karne ke liye), ya installation dobara check karo.

🔑 IAM User Banake Access Key Generate Karna

Practical

AWS CLI use karne ke liye credentials chahiye — aur best practice ye hai ki root account ki jagah ek IAM User banake uski Access Key use karo.

  1. AWS Console mein IAM service kholo.
  2. Users pe jao, phir Create user pe click karo.
  3. User name daalo (e.g. cli-user).
  4. Zaruri permissions attach karo (jaise AdministratorAccess learning ke liye, ya specific policies production ke liye).
  5. User create hone ke baad, us user ko open karo.
  6. Security credentials tab pe jao.
  7. Access keys section mein Create access key pe click karo.
  8. Use case select karo: Command Line Interface (CLI).
  9. Access Key ID aur Secret Access Key ko copy ya download kar lo — Secret Key sirf ek baar dikhta hai.
Important Security Note Secret Access Key ko kabhi bhi kisi ke saath share mat karo, GitHub pe commit mat karo, ya screenshot mein mat dikhao. Agar leak ho jaye to turant IAM Console se us key ko deactivate/delete karo aur nayi key generate karo.

⚙️ aws configure — Full Setup

Practical

Terminal ya Command Prompt open karke yeh command run karein:

aws configure

Aap se 4 details mangi jayengi, ek ek karke:

FieldKya Daalna Hai
AWS Access Key IDApni IAM user ki Access Key ID (Section 8 se mili wali).
AWS Secret Access KeyApni Secret Access Key enter karein.
Default region nameJaise eu-north-1, ap-south-1, us-east-1 — jis region mein aap zyada kaam karte ho.
Default output formatjson (recommended), ya table/text/yaml.

Poora interaction terminal mein aisa dikhega:

$ aws configure
AWS Access Key ID [None]: AKIAxxxxxxxxxxxxxxxx
AWS Secret Access Key [None]: wJalrXUtnFEMI/xxxxxxxxxxxxxxxxxxxxxxxx
Default region name [None]: ap-south-1
Default output format [None]: json
Region kaise choose karein? Region wo choose karo jo aapke users/application ke sabse kareeb ho, taaki latency kam rahe. India ke liye ap-south-1 (Mumbai) common choice hai.

🔍 Verification Command — Connection Check Karo

Practical

Check karein ki connection sahi chal raha hai ya nahi:

aws sts get-caller-identity

Agar sab kuch sahi configured hai, to output kuch aisa aayega:

{
    "UserId": "AIDAxxxxxxxxxxxxxxxxx",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/cli-user"
}
Command breakdown sts — AWS Security Token Service, jo identity-related info deta hai. get-caller-identity — bataata hai ki abhi CLI kis AWS account aur user ke through connected hai — bina kisi resource ko touch kiye, sirf identity confirm karta hai.

📁 Config Aur Credentials Files

Theory

aws configure run karne pe, AWS CLI do files mein settings save karta hai:

FileLocationKya Store Hota Hai
credentials~/.aws/credentials (Linux/Mac)
C:\Users\USERNAME\.aws\credentials (Windows)		Access Key ID aur Secret Access Key
config~/.aws/config (Linux/Mac)
C:\Users\USERNAME\.aws\config (Windows)		Default region aur output format

credentials file ka structure:

[default]
aws_access_key_id = AKIAxxxxxxxxxxxxxxxx
aws_secret_access_key = wJalrXUtnFEMI/xxxxxxxxxxxxxxxxxxxxxxxx

config file ka structure:

[default]
region = ap-south-1
output = json
In files ko directly bhi edit kar sakte ho Agar aapko values manually change karni hain (jaise koi typo fix karna), to aws configure dobara chalane ki jagah in files ko text editor mein directly edit bhi kiya ja sakta hai.

👥 Multiple Profiles Configure Karna

Practical

Agar aapke paas multiple AWS accounts hain (jaise personal aur office/client), to alag alag named profiles banaye ja sakte hain.

aws configure --profile client-account

Isse ek naya profile client-account naam se ban jaayega. Ye credentials file mein aise dikhega:

[default]
aws_access_key_id = AKIA...default...
aws_secret_access_key = ...default...

[client-account]
aws_access_key_id = AKIA...client...
aws_secret_access_key = ...client...

Kisi specific profile se command chalane ke liye --profile flag use karo:

aws s3 ls --profile client-account
Profile permanently set karna Har command mein --profile likhne se bachne ke liye, ek terminal session ke liye environment variable set kar sakte ho: 
export AWS_PROFILE=client-account
(Windows PowerShell mein: $env:AWS_PROFILE="client-account")

🌐 Environment Variables Se Configure Karna

Theory

aws configure ke alawa, credentials ko environment variables ke through bhi set kiya ja sakta hai — ye tarika CI/CD pipelines aur temporary sessions ke liye useful hai.

Linux/Mac (bash):

export AWS_ACCESS_KEY_ID=AKIAxxxxxxxxxxxxxxxx
export AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/xxxxxxxxxxxxxxxxxxxxxxxx
export AWS_DEFAULT_REGION=ap-south-1

Windows (PowerShell):

$env:AWS_ACCESS_KEY_ID="AKIAxxxxxxxxxxxxxxxx"
$env:AWS_SECRET_ACCESS_KEY="wJalrXUtnFEMI/xxxxxxxxxxxxxxxxxxxxxxxx"
$env:AWS_DEFAULT_REGION="ap-south-1"
Priority order AWS CLI credentials ko is order mein check karta hai: (1) command-line options, (2) environment variables, (3) credentials/config files, (4) IAM Role (agar EC2 instance pe chal raha ho). Jo pehle mile, wahi use hota hai.

🖨️ Output Formats

Theory

AWS CLI commands ka output alag alag formats mein dikhaya ja sakta hai:

FormatKab Use Karein
jsonDefault aur most common — scripts mein parse karne ke liye best.
tableHuman-readable, terminal mein visually saaf dikhta hai.
textTab-separated plain text — grep/awk jaise Unix tools ke saath use karne ke liye.
yamlYAML format, kuch tools/configs ke saath compatibility ke liye.

Kisi ek command ke liye temporarily format change karna ho to --output flag use karo:

aws s3 ls --output table

🧯 Common Errors Aur Troubleshooting

Important

1. Unable to locate credentials

Kyu hota hai: aws configure abhi tak run nahi kiya, ya credentials file missing/galat hai.

Fix: aws configure dobara run karo aur sahi Access Key/Secret Key daalo.

2. An error occurred (UnrecognizedClientException)

Kyu hota hai: Access Key ya Secret Key galat hai ya expire/deactivate ho chuki hai.

Fix: IAM Console se nayi Access Key generate karo aur dobara aws configure run karo.

3. AccessDenied error

Kyu hota hai: IAM user ke paas us action/resource ke liye zaruri permission nahi hai.

Fix: IAM Console mein us user/role ko needed policy attach karo (least privilege follow karte hue).

4. Could not connect to the endpoint URL

Kyu hota hai: Galat region set hai, ya internet connection issue hai.

Fix: aws configure se region check karo (aws configure list), aur internet connection verify karo.

5. command not found: aws

Kyu hota hai: AWS CLI properly install nahi hua, ya PATH mein add nahi hua.

Fix: Installation steps (Section 4-6) dobara follow karo, aur naya terminal window kholo.

6. Region not specified

Kyu hota hai: Config file mein default region set nahi hai, aur command mein bhi region nahi diya.

Fix: aws configure se default region set karo, ya command mein --region ap-south-1 flag add karo.

🔒 Security Best Practices

Important
⚠️ Zaroori Baatein
  • Root account ki Access Key kabhi generate/use mat karo — hamesha IAM user use karo.
  • Access Key aur Secret Key ko kabhi GitHub ya kisi public jagah commit mat karo.
  • Har user/service ko sirf wahi permissions do jo unhe chahiye (least privilege).
  • Purani ya unused Access Keys ko regularly rotate/delete karo.
  • Jahan possible ho, IAM Roles use karo instead of long-term Access Keys (jaise EC2 pe).
  • MFA (Multi-Factor Authentication) enable karo apne IAM users ke liye.
  • .aws/credentials file ko kabhi version control mein add mat karo — .gitignore mein rakho.
  • Alag alag projects/clients ke liye alag profiles use karo, taaki keys mix na ho.

🎯 Interview Questions & Answers

Interview
Q1: AWS CLI kya hai?
A: Ek command-line tool jisse AWS services ko terminal se manage kiya ja sakta hai, bina Console khole.
Q2: aws configure kya karta hai?
A: Ye Access Key, Secret Key, default region, aur output format set karta hai, aur inhe local files mein save karta hai.
Q3: Credentials file kaha store hoti hai?
A: ~/.aws/credentials (Linux/Mac) ya C:\Users\USERNAME\.aws\credentials (Windows) mein.
Q4: aws sts get-caller-identity kis liye use hota hai?
A: Confirm karne ke liye ki CLI kis AWS account/user ke through connected hai.
Q5: Multiple AWS profiles kaise banate hain?
A: aws configure --profile profile-name command se, aur use karte waqt --profile profile-name flag lagate hain.
Q6: Root account credentials use karna kyu risky hai?
A: Root ke paas unrestricted access hota hai; agar leak ho jaye to poora account compromise ho sakta hai. Isliye IAM user use karna best practice hai.
Q7: AWS CLI credentials priority order kya hai?
A: Command-line options → Environment variables → Config/credentials files → IAM Role (agar applicable ho).
Q8: Default output format kya options hote hain?
A: json, table, text, aur yaml.
Q9: "Unable to locate credentials" error kyu aata hai?
A: Jab CLI configure nahi kiya gaya ho, ya credentials file missing/corrupt ho.
Q10: IAM Role vs Access Key mein kya difference hai?
A: Access Key ek long-term static credential hai; IAM Role temporary credentials provide karta hai (jaise EC2 instance ko attach karke), jo zyada secure maana jaata hai.
