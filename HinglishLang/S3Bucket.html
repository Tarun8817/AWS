1️⃣ What is AWS S3?

Amazon S3 (Simple Storage Service) is an AWS object storage service used to store and retrieve files/data from anywhere over the internet.

S3 ko hum files/data store karne ke liye use karte hain, jaise:

  • Images
  • Videos
  • Documents
  • PDFs
  • Backups
  • Logs
  • Static website files
  • Application files
  • Data archives
Local Computer ↓ S3 ↓ Images / Videos / PDFs / Backups
Real-world example

Socho tumhare phone mein 1000 photos hain aur phone ka storage full ho raha hai. Tum un sabko S3 pe upload kar sakte ho — ab wo internet ke through kahin se bhi accessible hongi, aur phone ka space bhi bach jaayega.

💡 Why Do We Use S3?

  • File storage — kisi bhi type ki file store karna
  • Backup — important data ka backup rakhna
  • Static website hosting — HTML/CSS/JS files serve karna
  • Application data storage — app ke uploads, media store karna
  • Log storage — server/application logs rakhna
  • Data lakes — large-scale analytics data store karna
  • Media storage — images, videos, audio
  • Disaster recovery — critical data ka safe copy
  • Sharing files — links ke through data share karna
  • Storing build/deployment files — CI/CD artifacts

S3 EC2 server pe directly files store karne se alag hai kyunki S3 durable, highly scalable, aur EC2 instance se independent hota hai — agar EC2 instance delete/fail ho jaaye, S3 mein data safe rehta hai. S3 practically unlimited storage deta hai, jabki EC2 ki disk limited hoti hai.

🧩 Important S3 Terms

Bucket

Bucket is a container in S3 where objects/files are stored.
S3 ↓ Bucket ↓ Files / Objects

Object

Object is the actual file stored inside an S3 bucket.
photo.jpg resume.pdf video.mp4 index.html

Ek S3 object mein data (actual file content) plus metadata (jaise content type, size, custom tags) hota hai, aur har object ki ek unique key hoti hai.

Object Key

Object key wo naam/path hai jisse ek object ko bucket ke andar identify kiya jaata hai.

images/profile.jpg documents/resume.pdf

Region

Ek S3 bucket kisi specific AWS Region mein create hota hai — data usi Region ke data centers mein store hota hai.

Prefix

images/ documents/ videos/ backups/

S3 asal mein ek flat object namespace use karta hai — matlab andar koi real "folders" nahi hote. Console mein images/ jaisa prefix ek folder ki tarah dikhta hai, lekin actually ye poora string sirf object key ka ek part hota hai.

AWS Account ↓ S3 ↓ Bucket ↓ Objects ↓ Files

🏷️ S3 Storage Classes

S3 Standard

Frequently accessed data ke liye — high durability aur availability ke saath.

S3 Intelligent-Tiering

Jab access pattern unknown ya changing ho — S3 khud data ko cost-effective tier mein move karta rehta hai.

S3 Standard-IA

Infrequently accessed data ke liye jise multi-AZ resilience chahiye.

S3 One Zone-IA

Infrequently accessed data jo single-AZ storage tolerate kar sake (thoda kam durable, thoda sasta).

S3 Glacier Instant Retrieval

Archive data jise fast retrieval chahiye (milliseconds mein access).

S3 Glacier Flexible Retrieval

Long-term archive, retrieval time mein flexibility ke saath (minutes se hours).

S3 Glacier Deep Archive

Bahut long-term archive ke liye — sabse sasta storage, lekin retrieval mein zyada time lagta hai (hours).

🔐 S3 Encryption

Encryption important hai kyunki ye ensure karta hai ki data — chahe rest mein ho (storage mein) — unauthorized access se protected rahe.

Server-Side Encryption

  • SSE-S3 — AWS khud encryption keys manage karta hai; simple aur default option.
  • SSE-KMS — AWS KMS (Key Management Service) use karta hai, jo extra control aur audit logging deta hai key usage ke liye.
  • DSSE-KMS — dual-layer server-side encryption with KMS, extra-sensitive data ke liye.

SSE-S3 vs SSE-KMS: SSE-S3 simpler hai — AWS sab kuch automatically manage karta hai. SSE-KMS mein tumhe zyada control milta hai (kaun keys use kar sakta hai, key rotation, detailed audit trail) lekin thoda zyada configuration aur cost involve hoti hai.

User ↓ Upload File ↓ S3 ↓ Encrypted at Rest

Client-side encryption mein data ko upload karne se pehle hi client (application) khud encrypt kar deta hai — S3 sirf already-encrypted data store karta hai.

🚫 S3 Block Public Access

Block Public Access helps prevent unintended public access to S3 buckets and objects.

Iske chaar high-level settings hote hain jo control karti hain ki:

  • New ACLs se public access allow ho ya nahi
  • Any ACLs se public access allow ho ya nahi
  • New public bucket policies allow ho ya nahi
  • Public access ko bucket policies ke through cross-account access sahit block kiya jaaye ya nahi

Normally public access blocked rehna chahiye jab tak koi specific requirement (jaise static website hosting) na ho.

Private Bucket ↓ Only authorized users/services ↓ Access S3 Objects

Public website hosting ek special use case hai jise deliberately, sochh samajh kar configure karna chahiye — accidental public exposure se sensitive data leak ho sakta hai.

📜 S3 Bucket Policy

Bucket Policy is a resource-based JSON policy attached to an S3 bucket that controls access to the bucket and its objects.
  • Principal — kaun (user/account/service) is policy se affect hota hai
  • Action — kaunsa operation (jaise s3:GetObject) allow/deny hota hai
  • Resource — kaunsa bucket/object is policy se affect hota hai
  • Effect — Allow ya Deny
  • Condition — additional rules jo policy ko apply hone se pehle check hoti hain
Yaad rakho: Koi bhi policy example use karte waqt, placeholder bucket names/ARNs ko apne actual values se replace karna zaroori hai.

IAM Policy vs Bucket Policy: IAM Policy ek identity (user/role/group) se attach hoti hai aur batati hai wo identity kya kar sakti hai. Bucket Policy ek resource (bucket) se attach hoti hai aur batati hai us bucket ko kaun access kar sakta hai — chahe wo request kisi bhi identity se aaye.

🔗 IAM + S3

IAM users, roles, aur policies S3 ko access control karne ke liye use hote hain.

EC2 ↓ IAM Role ↓ IAM Policy ↓ S3 Bucket ↓ Object

EC2 instance pe long-lived AWS access keys rakhne ke bajaye IAM Role attach karna generally better hai kyunki:

  • Keys kabhi hardcode ya leak nahi hoti
  • Credentials automatically rotate hoti hain
  • Access ko easily revoke ya modify kiya ja sakta hai
Practical example

Ek EC2 server ko application backups S3 pe upload karne hain. Recommended architecture: EC2 → IAM Role (jisme S3 upload permission ho) → Permission → S3. Isse server code mein koi access key store nahi karna padta.

🔑 S3 Access Control

  • IAM policies — identity-based permissions
  • Bucket policies — resource-based permissions
  • Block Public Access — accidental public exposure rokta hai
  • Object Ownership — decide karta hai bucket owner ya uploader object ko control karega
  • ACLs — legacy access control mechanism

Modern S3 configurations generally Bucket owner enforced Object Ownership use karte hain aur ACL-based access control avoid karte hain, jab tak koi specific legacy/integration requirement na ho — ye access management ko simpler aur zyada secure banata hai.

🚀 S3 + CloudFront

User ↓ CloudFront ↓ S3 Bucket ↓ Website Files
  • CDN — content globally distributed edge locations se serve hota hai
  • Lower latency — user ke nazdeek se content serve hota hai
  • Caching — repeated requests fast hoti hain
  • HTTPS — encrypted connection asaan se enable ho jaati hai
  • Global distribution — duniya bhar mein fast access
  • Reduced direct access to S3 — S3 ko public expose karne ki zaroorat kam ho jaati hai

Modern recommended pattern ye hai ki CloudFront ko S3 ke saath restricted access ke saath use kiya jaaye — matlab sirf CloudFront hi S3 bucket ko access kar sake, general public directly bucket access na kar sake.

Day 0 ↓ S3 Standard After 30 days ↓ Infrequent Access After 90 days ↓ Glacier After 365 days ↓ Delete

🔁 S3 Replication

Same-Region Replication (SRR)

Ek hi AWS Region ke andar do buckets ke beech objects replicate karne ke liye use hota hai.

Cross-Region Replication (CRR)

Alag-alag AWS Regions ke buckets ke beech objects replicate karne ke liye use hota hai.

Bucket A ↓ Replication ↓ Bucket B
  • Disaster recovery
  • Compliance
  • Data locality
  • Backup
  • Multi-region architectures

Important prerequisite: Replication ke liye source aur destination dono buckets pe versioning enabled hona zaroori hai.

🔒 S3 Object Lock

S3 Object Lock helps prevent objects from being deleted or overwritten for a defined retention period or until a legal hold is removed.
  • Retention period — kitne time tak object protected rahega
  • Governance mode — special permissions ke saath override kiya ja sakta hai
  • Compliance mode — retention period ke dauraan kisi ke bhi through override nahi ho sakta, root user tak nahi
  • Legal hold — retention period se independent, jab tak explicitly remove na ho tab tak lock rehta hai
Real-world example

Ek company ke financial records ko regulation ke according 7 saal tak modify/delete nahi kiya ja sakta. Object Lock (Compliance mode) enable karke ye guarantee kiya ja sakta hai ki koi bhi — accidentally ya intentionally — un records ko delete/overwrite nahi kar payega.

🔗 S3 Presigned URL

A presigned URL provides temporary access to a specific S3 object without making the object publicly accessible.
Private S3 Object ↓ Presigned URL ↓ Temporary Access
  • Private file downloads
  • User uploads — bina application server ke through file route kiye, seedha S3 pe upload
  • Temporary sharing
  • Application file access

Har presigned URL ka ek expiration time hota hai — us time ke baad URL kaam karna band kar deta hai, isliye object hamesha ke liye publicly exposed nahi hota.

📦 S3 Multipart Upload

Large files ko multiple parts mein upload kiya ja sakta hai.

Large File ↓ Part 1 Part 2 Part 3 Part 4 ↓ S3 ↓ Complete Object
  • Better handling of large files — bade files ko chote-chote parts mein todkar upload karna aasan hota hai
  • Parallel uploads — multiple parts ek saath upload ho sakte hain, jisse speed badhti hai
  • Ability to retry failed parts — agar ek part fail ho jaaye, sirf usi part ko dobara upload karna padta hai, poori file nahi

🧯 S3 Permissions Troubleshooting

AccessDenied Error

Possible reasons:

  • IAM policy missing hai
  • Bucket policy access deny kar rahi hai
  • Block Public Access enabled hai

Request ↓ IAM permissions? ↓ Bucket policy? ↓ Block Public Access? ↓ Object Ownership / ACL? ↓ Correct resource ARN?

✅ S3 Security Best Practices

⚠️ IMPORTANT
  • Block Public Access enabled rakho, jab tak public access explicitly required na ho.
  • Least-privilege IAM permissions use karo.
  • Encryption use karo.
  • Important data ke liye versioning enable karo.
  • Lifecycle rules use karo.
  • Auditing ke liye CloudTrail/data events use karo jaha appropriate ho.
  • Secrets ko directly S3 mein store karne se bacho.

🆚 S3 vs EC2 Storage

EC2 storage

EC2 ↓ EBS ↓ Application Files

S3

Application ↓ S3 API ↓ Bucket ↓ Object

S3 durable object storage ke liye useful hai jo EC2 instance se independent rehta hai — agar instance terminate ho jaaye, S3 mein stored data safe rehta hai. Isse compare mein, EBS volume generally ek specific EC2 instance se tightly linked hota hai.

  • Storage amount — kitna data store kiya gaya hai

  • Data transfer — S3 se internet pe data bhejna
  • Replication — extra copies rakhna
  • Lifecycle transitions — ek storage class se doosri mein move karna
  • Monitoring/analytics features
Note: Ye document specific outdated prices claim nahi karta, kyunki AWS pricing change hoti rehti hai — current pricing hamesha AWS ki official pricing page pe verify karo. Alag-alag storage classes ki storage aur retrieval economics alag-alag hoti hain.

🎯 Important S3 Interview Questions

Q1: What is Amazon S3?

A: Ek AWS object storage service jo internet ke through files/data store aur retrieve karne deti hai.

Q2: What is an S3 bucket?

A: Ek container jisme S3 objects/files store hote hain.

Q3: What is an S3 object?

A: Bucket ke andar store ki gayi actual file, data + metadata ke saath.

Q4: What is an object key?

A: Bucket ke andar object ko identify karne wala naam/path.

Q5: Is S3 a file system?

A: Nahi — S3 ek flat object storage hai, traditional hierarchical file system nahi.

Q6: What are S3 storage classes?

A: Alag-alag access-pattern/cost trade-offs ke liye storage tiers — jaise Standard, IA, Glacier.

Q7: What is S3 Versioning?

A: Ek feature jo ek hi bucket mein object ke multiple versions rakhne deta hai.

Q8: What is a delete marker?

A: Ek marker jo versioned bucket mein normal delete pe place hota hai, jabki previous version still exist karti hai.

Q9: What is S3 Lifecycle?

A: Rules jo objects ko automatically alag storage class mein transition ya expire karte hain.

Q10: What is S3 Bucket Policy?

A: Ek resource-based JSON policy jo bucket ke access ko control karti hai.

Q11: What is an IAM Policy?

A: Ek identity-based policy jo batati hai ek user/role/group kya kar sakta hai.

Q12: Difference between IAM Policy and Bucket Policy?

A: IAM Policy identity se attach hoti hai; Bucket Policy resource (bucket) se attach hoti hai.

Q13: What is Block Public Access?

A: Ek setting jo bucket/objects ko accidental public exposure se protect karti hai.

Q14: What is S3 encryption?

A: Data ko rest mein (storage mein) protect karne ka mechanism — server-side ya client-side.

Q15: Difference between SSE-S3 and SSE-KMS?

A: SSE-S3 mein AWS khud keys manage karta hai; SSE-KMS extra control aur audit logging ke saath KMS use karta hai.

Q16: What is S3 Static Website Hosting?

A: S3 ka feature jo HTML/CSS/JS jaisi static files ko directly website ki tarah serve karne deta hai.

Q17: What is a presigned URL?

A: Ek temporary URL jo private S3 object ko bina publicly expose kiye access karne deta hai.

Q18: What is S3 Replication?

A: Objects ko ek bucket se doosre bucket mein automatically copy karne ka feature.

Q19: Difference between SRR and CRR?

A: SRR same Region ke buckets ke beech replicate karta hai; CRR alag-alag Regions ke beech.

Q20: What is S3 Object Lock?

A: Ek feature jo objects ko ek retention period ke liye delete/overwrite hone se rokta hai.

Q21: What is Multipart Upload?

A: Large files ko multiple parts mein upload karne ka tareeka, jisse reliability aur speed improve hoti hai.

Q22: What is S3 Versioning used for?

A: Accidental delete/overwrite se protection, aur purani versions recover karne ke liye.

Q23: How do you upload a file using AWS CLI?

A: aws s3 cp file.txt s3://BUCKET-NAME/ command se.

Q24: How do you download an S3 object using CLI?

A: aws s3 cp s3://BUCKET-NAME/file.txt . command se.

Q25: How does EC2 access S3?

A: Generally ek IAM Role ke through jo EC2 instance ko attach kiya jaata hai.

Q26: Why should we use IAM Roles with EC2?

A: Kyunki ye long-lived access keys store karne se zyada secure hai — credentials temporary aur auto-rotating hoti hain.

Q27: What happens when Block Public Access is enabled?

A: Bucket/objects ko public banane wali policies/ACLs effectively block ho jaati hain, jab tak deliberately allow na kiya jaaye.

Q28: Why use CloudFront with S3?

A: Better performance (CDN, caching, lower latency), HTTPS, aur S3 ki direct public exposure kam karne ke liye.

Q29: Difference between S3, EBS, and EFS?

A: S3 object storage hai (independent), EBS block storage hai (ek EC2 se attached), EFS shared file storage hai (multiple EC2 se mount ho sakta hai).

Q30: How can S3 be used for backups?

A: Application/server data ko archive karke S3 pe upload kiya ja sakta hai, versioning/lifecycle ke saath.

Q31: How can S3 help with disaster recovery?

A: Cross-region replication ke through data ko alag Region mein bhi durable rakh kar.

Q32: What happens if an object is deleted from a versioned bucket?

A: Ek delete marker add ho jaata hai, aur previous version(s) still exist karti hain jab tak explicitly permanently delete na ki jaayein.

Q33: What causes an S3 AccessDenied error?

A: Missing IAM permission, restrictive bucket policy, Block Public Access, galat ARN, ya galat account/role.

Q34: How can you make an S3 object temporarily accessible?

A: Ek presigned URL generate karke, jiski expiration time hoti hai.

Q35: How can you reduce S3 storage costs?

A: Lifecycle rules use karke data ko cheaper storage classes mein move ya expire karke.
