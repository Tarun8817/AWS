1. AWS Route 53 — Naam aur Matlab

Full Form / Naam: Amazon Route 53

Amazon Route 53, AWS ki DNS service ka official naam hai. "Amazon" batata hai ki ye AWS ki service hai, aur "Route 53" product ka naam hai.

AWS Route 53 Kya Hai?

Ye kya hai?

Simple words mein, Route 53 AWS ki DNS service hai jo domain name ko correct server ya AWS resource ke saath connect karti hai.

Ye kaunsi problem solve karta hai?

Computers ek doosre se IP address (numbers) se baat karte hain, jo yaad rakhna mushkil hota hai. Route 53 hume aasan naam (jaise example.com) use karne deta hai.

Hum ise kyun use karte hain?

Hum Route 53 domain register karne, DNS records manage karne, traffic reliably route karne, aur domain ko EC2/ALB/S3 jaisi AWS services se jodne ke liye use karte hain.

Ye kaise kaam karta hai? (basic idea)

Aap browser mein domain naam type karte ho; Route 53 use lookup karta hai aur wo IP address (ya AWS resource) bata deta hai jisse connect karna hai.

Real-world example

Jab aap amazon.com visit karte ho, Route 53 (ya isi jaisi DNS service) us naam ko us server ke address mein badalti hai jo asal mein Amazon website serve karta hai.

Ise "Route 53" Kyun Kehte Hain?

"Route" ka matlab hai traffic ko sahi destination tak route (bhejna) karna. "53" DNS ke standard port number 53 ko refer karta hai. Naam se hi "DNS traffic ko route karna" wala idea milta hai.

DNS port 53 DNS servers network port 53 (TCP aur UDP dono) par communicate karte hain — ye ek globally standard convention hai, AWS ke liye kuch alag nahi.

2. DNS Kya Hai?

DNS ka matlab hai Domain Name System.

DNS ke bina: 13.62.102.238 (yaad rakhna mushkil) DNS ke saath: www.example.com | v 13.62.102.238 (DNS ye aapke liye dhundh deta hai)

DNS internet ki phonebook jaisa hai. Server ka numeric IP address yaad rakhne ke bajay, aap naam type karte ho, aur DNS uska matching IP address dhundh deta hai. Ye lookup har baar website kholte time automatically hota hai, aapko pata bhi nahi chalta.

3. Route 53 Kyun Chahiye?

User | v www.example.com | v Route 53 | v AWS Resource / Server | v Application

Step by step: user browser mein domain type karta hai. Browser Route 53 se us domain ko resolve karne ko kehta hai. Route 53 sahi AWS resource/server ka address bata deta hai. Browser wahan connect hota hai, aur application load hoti hai.

4. Route 53 Kya Handle Karta Hai

DNS

Route 53 DNS queries ka answer deta hai, domain names ko IP addresses ya doosri resource info mein convert karta hai.

Domain registration

Route 53 se aap seedha AWS ke through naya domain name buy/register bhi kar sakte ho.

DNS records

Route 53 DNS records store karta hai jo batate hain ki domain kaise resolve hoga (A, CNAME, MX waghera). Section 6 mein detail mein dekhein.

Traffic routing

Route 53 rules ke according traffic alag servers par bhej sakta hai — inhe routing policies kehte hain (weighted, latency-based, failover waghera).

Health checks

Route 53 check kar sakta hai ki server healthy hai ya nahi, aur unhealthy server se traffic automatically hata deta hai.

Domain-to-resource mapping

Route 53 domain ko real AWS resource se link karta hai jahan use point karna chahiye — EC2 instance, Load Balancer, S3 website waghera.

5. Hosted Zone

Hosted Zone Kya Hai?

Hosted Zone Route 53 ke andar ek container hota hai jisme ek domain (jaise example.com) ke saare DNS records hote hain.

Public Hosted Zone

Public Hosted Zone un domains ke DNS records manage karta hai jo public internet se reachable hote hain, jaise company ki website.

Private Hosted Zone

Private Hosted Zone sirf ek specific VPC ke andar visible DNS records manage karta hai, internal names ke liye jo internet par expose nahi hote.

Kab kaunsa use karein & real examples

Public use karo har us cheez ke liye jahan customers ya public ko pahunchna hai (e.g. www.example.com). Private use karo internal service names ke liye jo sirf aapki VPC ki applications use karti hain (e.g. internal-db.local).

Public vs Private Hosted Zone

FeaturePublic Hosted ZonePrivate Hosted Zone
ReachabilityPublic internet se reachable/accessible.Sirf specific VPC ke andar hi visible.

6. DNS Records

A Record

A record domain name ko seedha ek IPv4 address se map karta hai.

example.com -> 13.62.102.238

AAAA Record

AAAA record A record jaisa hi hai, lekin domain ko IPv4 ke bajay IPv6 address se map karta hai.

CNAME Record

CNAME record ek domain name ko doosre domain name par point karta hai (DNS terms mein alias), seedha IP par nahi.

Alias Record

Alias record Route 53 ka special feature hai jo CNAME ki tarah kaam karta hai lekin root domain (example.com) par bhi chal sakta hai aur AWS resources jaise ALB ya CloudFront par directly point karta hai.

MX Record

MX record internet ko batata hai ki us domain ke liye emails kaunsa mail server handle karega.

TXT Record

TXT record text store karta hai, jo aksar domain ownership verify karne ya email security (SPF/DKIM) ke liye kaam aata hai.

NS Record

NS (Name Server) records batate hain ki is domain ke DNS queries ka answer dene ke liye kaunse name servers responsible hain.

SOA Record

SOA (Start of Authority) record DNS zone ke baare mein administrative info rakhta hai, jaise primary name server aur refresh timing. Har hosted zone ke saath ye automatically banta hai.

7. Route 53 Routing Policies

1. Simple Routing

Simple routing saara traffic bina kisi special rule ke ek resource par bhejti hai.

Route 53 | v Server A (saara traffic)

Real-world example: ek single server wali choti personal website.

2. Weighted Routing

Weighted routing assigned weights (percentages) ke basis par multiple resources mein traffic baantti hai.

Route 53 | +----+----+ v v 90% 10% Server A Server B

Real-world example: naye app version ko test karne ke liye sirf 10% traffic bhejna (canary release) poore rollout se pehle.

3. Latency-Based Routing

Latency-based routing har user ko us AWS region par bhejti hai jo unhe sabse fast (lowest-latency) response deta hai.

User (India) -> Route 53 -> Mumbai region server User (USA) -> Route 53 -> N. Virginia region server

Real-world example: global app jo users ko nearest region par route karke fast speed deti hai.

4. Failover Routing

Failover routing traffic primary resource par bhejti hai, aur agar primary unhealthy ho jaye to automatically backup par switch kar deti hai.

Route 53 | v Primary Server --(healthy)--> used | v Secondary Server --(sirf tab used jab primary unhealthy ho)

Real-world example: production website jiska doosre region mein standby disaster-recovery server ho.

5. Geolocation Routing

Geolocation routing users ko unke geographic location (country/continent) ke basis par specific resources par bhejti hai (legal ya content requirements ke liye).

User in EU -> Route 53 -> EU-compliant server User in India -> Route 53 -> India-specific content server

Real-world example: region ke mutabiq pricing ya local language content show karna.

6. Geoproximity Routing

Geoproximity routing resources aur users ki physical location ke hisaab se traffic route karti hai, aur "bias" value use karke ek taraf traffic badha sakti hai (Route 53 Traffic Flow required).

7. IP-Based Routing

IP-based routing client ke IP address ranges ke according traffic route karti hai, jaise specific ISP/network ranges ko optimized endpoint par bhejna.

8. Route 53 Health Checks

Primary Server | v Health Check | Healthy -> Primary used Unhealthy -> Secondary used

Health check kya hai aur kyun chahiye?

Health check ek regular test hai jo Route 53 server/endpoint par karta hai confirm karne ke liye ki wo theek kaam kar raha hai. Iske bina Route 53 users ko crash hue server par bhejta rahega.

HTTP / HTTPS health check

Route 53 ek specific path par HTTP ya HTTPS request bhejta hai aur successful response expect karta hai.

TCP health check

TCP health check simply diye gaye port par TCP connection banata hai; connection succeed hone par healthy maana jata hai.

Failover kaise kaam karta hai

Route 53 failover setup mein primary resource ke saath health check link karta hai. Agar health check unhealthy report kare, to Route 53 traffic automatically secondary resource par shift kar deta hai.

9. Domain Registration

Domain kya hai?

Domain website ya service ka human-readable naam hota hai, jaise example.com.

Domain registration kya hai?

Domain registration apne liye officially ek domain name reserve karne ka process hota hai, usually yearly fee ke saath.

Registrar kya hai?

Registrar wo authorized company hoti hai jo domain names sell/register karti hai (Route 53 bhi registrar ki tarah kaam karta hai).

Nameservers kya hain?

Nameservers wo specific DNS servers hote hain jo aapke domain ke authoritative DNS records rakhte hain aur queries ka answer dete hain.

Route 53 ko domains ke saath kaise use karte hain / existing domain vs Route 53-registered domain

Aap ya to ek bilkul naya domain Route 53 se register kar sakte ho, ya kisi doosri jagah registered domain ko rakh kar uske nameservers Route 53 par point kar sakte ho, taaki DNS records wahin manage ho.

10. Practical: Route 53 Hosted Zone Banana

  1. AWS Console mein login karo.
  2. Route 53 search karo.
  3. Left menu se Hosted Zones kholo.
  4. "Create Hosted Zone" par click karo.
  5. Domain naam daalo (jaise example.com) aur Public ya Private Hosted Zone choose karo.
  6. Finish karne ke liye "Create hosted zone" par click karo.

Banane ke baad: NS aur SOA records

Route 53 automatically NS aur SOA records bana deta hai. NS record us hosted zone ko diye gaye 4 name servers ko list karta hai — agar domain kahin aur registered hai to inhe apne registrar mein copy karna hoga. SOA record zone ki administrative metadata rakhta hai aur usually edit karne ki zarurat nahi.

11. Practical: Route 53 Ko EC2 Se Connect Karna

Example: EC2 Public IP = 13.62.102.238, Domain = example.com

User | v example.com | v Route 53 | v A Record | v EC2 Public IP | v Apache/Nginx | v Website
  1. Route 53 mein example.com ka Hosted Zone kholo.
  2. "Create record" par click karo.
  3. Root domain ke liye record name khali chhodo, ya "www" jaisa subdomain daalo. Record type A choose karo.
  4. EC2 instance ka public IP address (jaise 13.62.102.238) value ke roop mein daalo.
  5. "Create records" par click karo aur DNS propagate hone ke liye kuch minute wait karo.
  6. Ensure karo ki EC2 Security Group port 80 (HTTP) par inbound traffic allow kare, phir test karne ke liye browser mein domain kholo.

12. Practical: Route 53 + Application Load Balancer

User | v Route 53 | v ALB | v Target Group | v EC2 | v Application

ALB ke saath Alias Record commonly kyun use hota hai?

ALB ka address ek DNS name hota hai, fixed IP nahi (wo badal sakta hai). CNAME root domain par use nahi ho sakta, lekin Alias record ho sakta hai — aur ALB ka underlying address badalne par bhi ye automatically update ho jata hai.

  1. Route 53 mein Hosted Zone kholo aur "Create record" par click karo.
  2. "Alias" ko on karo, aur record type A choose karo.
  3. "Alias to Application and Classic Load Balancer" select karo aur list mein se apna ALB choose karo.
  4. "Create records" par click karo aur browser mein domain khol kar verify karo.

13. Route 53 + ECS Fargate

User | v Route 53 | v ALB | v ECS | v Fargate | v Docker Container | v Node.js + Express | v Database

Yahan Route 53 ka role hamesha jaisa hi hai — wo Alias record use karke domain naam ko ALB ke address mein badalta hai. ALB phir traffic ko jo bhi ECS/Fargate container abhi app chala raha hai, uske paas forward karta hai.

14. Real MERN Application Example

Frontend: React • Backend: Node.js + Express.js • Database: MongoDB • Containerization: Docker • Image storage: ECR • Deployment: ECS Fargate • Load balancing: ALB • DNS/domain routing: Route 53

User | v Route 53 | v ALB | v ECS Fargate | v Node.js + Express | v MongoDB

React frontend alag se build aur serve hota hai (jaise S3/CloudFront ya Express server se). Users domain type karke app tak pahunchte hain; Route 53 use ALB tak resolve karta hai; ALB requests ko chalte hue Fargate container tak bhejta hai; us container ke andar ka Node.js/Express backend MongoDB se baat karke data return karta hai.

15. Subdomain Example

example.com -> Frontend www.example.com -> Frontend (same ya redirect) api.example.com -> Backend API admin.example.com -> Admin Panel

Ek domain ke kai subdomains ho sakte hain, har ek apne DNS record ke through alag service par point kar sakta hai — isse frontend, API aur admin panel ko alag servers/services par rakh sakte ho, phir bhi ek hi domain brand rehta hai.

16. Important Differences

Route 53 vs DNS

Route 53DNS
AWS ki service jo DNS (aur usse zyada) implement karti hai.Names ko addresses mein resolve karne ka general internet system/protocol.

Route 53 vs CloudFront

Route 53CloudFront
Domain names ko resources (DNS) tak resolve karta hai.Ek CDN jo content ko cache karke users ke kareeb tezi se deliver karta hai.

Route 53 vs ALB

Route 53ALB
Domain naam ko sahi entry point tak bhejta hai (DNS level par).Aane wale traffic ko kai servers/containers mein baantta hai (application level par).

Route 53 vs API Gateway

Route 53API Gateway
Domain naam ko ek endpoint tak resolve karta hai.HTTP APIs ko manage, route aur secure karta hai (routes, auth, throttling).

A Record vs CNAME

A RecordCNAME
Seedha ek IPv4 address ki taraf point karta hai.Doosre domain naam ki taraf point karta hai, IP ki taraf nahi.

CNAME vs Alias

CNAMEAlias
Standard DNS record; root domain par use nahi ho sakta.Route 53 ka special record; root domain par use ho sakta hai aur AWS resources ko seedha point karta hai, queries ke liye free.

Public Hosted Zone vs Private Hosted Zone

PublicPrivate
Public internet se reachable/visible.Sirf ek chune hue VPC ke andar visible.

17. Complete Production Architecture

User | v Route 53 | v CloudFront | v Application Load Balancer | v ECS Fargate | v Node.js / Express | v RDS / MongoDB

Pehle Route 53 domain resolve karta hai. Phir CloudFront content (khaaskar static assets) ko cache karke user ke kareeb tezi se deliver karta hai. ALB requests ko chal rahe containers mein baantta hai. ECS Fargate Node.js/Express backend containers chalata hai. Backend RDS ya MongoDB mein data read/write karta hai.

18. Route 53 Interview Questions & Answers

Q1. Route 53 kya hai?
Ek AWS DNS service jo domain names ko servers aur AWS resources se connect karti hai.
Q2. Hum Route 53 kyun use karte hain?
Domain register karne, DNS records manage karne, traffic ko reliably route karne, aur domains ko AWS resources se jodne ke liye.
Q3. DNS kya hai?
Domain Name System — internet ki phonebook, jo domain names ko IP addresses mein badalta hai.
Q4. Ise Route 53 kyun kehte hain?
"Route" traffic route karne ke liye, "53" DNS ke standard port number ke liye.
Q5. Hosted Zone kya hai?
Route 53 ka container jisme ek domain ke saare DNS records hote hain.
Q6. Public Hosted Zone kya hai?
Un domains ke liye hosted zone jo public internet se reachable hain.
Q7. Private Hosted Zone kya hai?
Ek hosted zone jo sirf ek specific VPC ke andar visible hoti hai.
Q8. A record kya hai?
Ek DNS record jo domain ko seedha ek IPv4 address se map karta hai.
Q9. CNAME kya hai?
Ek record jo ek domain naam ko doosre domain naam ki taraf point karta hai.
Q10. Alias record kya hai?
Route 53 ka khaas record jo CNAME jaisa kaam karta hai, lekin root domain par use ho sakta hai aur AWS resources ko seedha point karta hai.
Q11. A Record vs CNAME?
A record IP ki taraf point karta hai; CNAME doosre domain naam ki taraf.
Q12. CNAME vs Alias?
CNAME root domain par use nahi ho sakta; Alias ho sakta hai, aur AWS resources ke saath directly kaam karta hai.
Q13. NS record kya hai?
Ek record jo domain ke DNS ke zimmedar name servers ko list karta hai.
Q14. SOA record kya hai?
Ek record jo DNS zone ki administrative information rakhta hai.
Q15. Route 53 routing policies kya hain?
Ye rules hain jo control karte hain Route 53 traffic kaise bhejta hai: Simple, Weighted, Latency-based, Failover, Geolocation, Geoproximity, aur IP-based.
Q16. Weighted routing kya hai?
Diye gaye percentage weights ke hisaab se traffic ko resources mein baantna.
Q17. Latency-based routing kya hai?
Har user ko us region par bhejna jo unhe sabse fast response de.
Q18. Failover routing kya hai?
Traffic ko primary resource par bhejna aur agar health check fail ho to backup par switch karna.
Q19. Health check kya hai?
Ek regular test jo Route 53 chalata hai ye confirm karne ke liye ki resource kaam kar raha hai.
Q20. Route 53 ko EC2 se kaise connect karte hain?
Hosted zone mein ek A record banao jo EC2 instance ke public IP ki taraf point kare.
Q21. Route 53 ko ALB se kaise connect karte hain?
ALB ki taraf point karne wala ek Alias record banao, plain CNAME ke bajay.
Q22. Route 53, ECS ke saath kaise kaam karta hai?
Route 53 phir bhi Alias record se domain ko ALB tak resolve karta hai; ALB phir chal rahe ECS/Fargate containers tak route karta hai.
Q23. MERN application mein Route 53 kaise use karoge?
Route 53 se domain (aur api.example.com jaise subdomains) ko us ALB tak point karo jo containerized Node.js/Express backend ke aage hai, aur React frontend ke liye CloudFront/S3 use kar sakte ho.

19. Quick Revision

Route 53 definition

AWS ki DNS service jo domains ko resources se connect karti hai.

DNS

Domain names ko IP addresses mein badalta hai.

Hosted Zone

Ek domain ke DNS records ka container.

Record types

A, AAAA, CNAME, Alias, MX, TXT, NS, SOA.

Routing policies

Simple, Weighted, Latency-based, Failover, Geolocation, Geoproximity, IP-based.

Health checks

Confirm karta hai ki resource kaam kar raha hai; failover enable karta hai.

Domain registration

Registrar ke through domain naam reserve karna (Route 53 khud registrar ho sakta hai).

EC2 connection

A record → EC2 public IP.

ALB connection

Alias record → ALB.

ECS connection

Route 53 → ALB → ECS/Fargate containers.

MERN architecture

Route 53 → ALB → ECS Fargate (Node/Express) → MongoDB.

20. Final Question

Route 53 ko simple Hinglish mein explain karo.

Route 53 AWS ki DNS service hai. Ye domain naam ko sahi server ya AWS resource se connect karti hai, domain register karne, DNS records banane, traffic route karne aur health check karne mein help karti hai.
