1️⃣ Definition

Theory

AWS EC2 Kya Hai?
Amazon EC2 (Elastic Compute Cloud) AWS ki ek web service hai jo cloud mein resizable virtual computers ("servers") deti hai. Physical hardware kharidne ki jagah, aap AWS se ek computer rent pe lete ho aur usse internet ke through use karte ho.

EC2 ka full form kya hai?
Elastic Compute Cloud.

EC2 Instance Kya Hai?
Ek EC2 Instance ek single virtual server hai jo aap EC2 ke andar create aur run karte ho. Ise ek aisa computer samjho jo AWS aapko use karne ke liye deta hai.

Hum EC2 Kyu Use Karte Hain?
Isse aap minutes mein server chala sakte ho, jitna use karo utna hi pay karo, zarurat pe usse resize (kam/zyada CPU ya RAM) kar sakte ho, aur physical machines kharidne aur maintain karne ki cost aur effort se bach sakte ho.

Real-world example

Socho aapne apne laptop pe ek website banayi. Poori duniya ko use visit karwane ke liye, aapko ek aisa computer chahiye jo hamesha on aur internet se connected ho. Apna laptop 24/7 chalane ki jagah, aap AWS se ek EC2 instance rent pe lete ho, apni website usme daalte ho, aur ab duniya ka koi bhi banda uski public address use karke usse khol sakta hai.

🧭 EC2 Architecture / Basic Flow

Theory
User ↓ Internet ↓ Public IP ↓ Security Group ↓ EC2 Instance ↓ Application / Web Server
  • User — Wo insaan jo browser khol ke website ya application request kar raha hai.
  • Internet — Wo public network jo user ki request ko AWS tak le jaata hai.
  • Public IP — Aapke EC2 instance ka internet pe address; iske bina bahar ki duniya aapke server tak nahi pahunch sakti.
  • Security Group — Instance ke aage ek virtual firewall jo decide karta hai kaunsa traffic (ports) andar/bahar jaane diya jaaye.
  • EC2 Instance — Wo actual virtual server jo request receive karta hai.
  • Application / Web Server — Instance ke andar chal raha software (jaise Apache) jo request ko actually process karke response bhejta hai.

💡 Hum EC2 Kyu Use Karte Hain?

Theory
  • Website hosting — Company ya personal website chalao jo 24/7 reachable ho.
  • Backend/API hosting — REST/GraphQL APIs host karo jinhe mobile ya web apps call karte hain.
  • Application servers — CRMs ya internal tools jaisa business software chalao.
  • Development environments — Har developer ya team ko build aur test karne ke liye ek remote machine do.
  • Databases — MySQL, PostgreSQL, MongoDB, etc. ko dedicated server pe self-manage karo.
  • Docker workloads — Jab host machine pe full control chahiye ho tab containers chalao.
  • Business applications — ERP systems, reporting tools, internal dashboards, aur bhi bahut kuch.

🧩 Important EC2 Components

Theory

AMI (Amazon Machine Image)

Definition: AMI ek pre-built template hai jisme operating system aur kabhi kabhi pre-installed software hota hai. Ise ek "snapshot recipe" samjho jo EC2 instance create karne ke liye use hoti hai.

Purpose: Har baar server launch karte waqt OS scratch se install karne se ye aapko bacha leta hai.

Examples: Amazon Linux 2023, Ubuntu 22.04, Windows Server 2022, Red Hat Enterprise Linux.

Kaise use hota hai: Jab aap EC2 instance launch karte ho, sabse pehla choice hota hai kaunsa AMI se boot karna hai — isi se aapka operating system decide hota hai.

Instance Type

Definition: Instance type decide karta hai ki aapke virtual server ko kitna CPU, RAM, aur network performance milega.

CPU / RAM / Network: Har type ka naam (jaise t3.micro) ek fixed amount ke vCPUs, memory, aur network bandwidth se map hota hai.

Examples: t3.micro (2 vCPU, 1 GB RAM — learning/free tier ke liye best), t3.small (2 vCPU, 2 GB RAM), t3.medium (2 vCPU, 4 GB RAM).

Key Pair

Definition: Key Pair do cryptographic keys ka set hota hai — ek public key aur ek private key — jo aapke instance mein securely login karne ke liye use hoti hain.

Public key — AWS dwara automatically instance pe store ki jaati hai.

Private key — Ek baar aap dwara .pem file ke roop mein download ki jaati hai; kisi ke saath share nahi ki jaati.

Kyu zaruri hai: Linux EC2 instances default mein password use nahi karte — wo key-based login use karte hain, jo kaafi zyada secure hai.

SSH ise kaise use karta hai: Connect karte waqt, SSH proof karta hai ki aapke paas matching private key hai — bina use network pe bheje.

Key Pair Kaise Banaye

  1. EC2 Dashboard → Key Pairs pe jao.
  2. Create key pair pe click karo.
  3. Ek naam daalo (e.g., my-ec2-key).
  4. Type RSA aur format .pem (Linux/Mac ke liye) ya .ppk (Windows pe PuTTY ke liye) choose karo.
  5. Create key pair pe click karo — private key file automatically download ho jaayegi. Ise safe rakho; AWS iska copy store nahi karta.

Security Group

Definition: Security Group aapke EC2 instance se attached ek virtual firewall hai jo incoming aur outgoing traffic control karta hai.

Inbound rules — Instance ke andar aane wala traffic control karte hain (jaise SSH ya web traffic allow karna).

Outbound rules — Instance se bahar jaane wala traffic control karte hain (usually default mein open rehte hain).

PortProtocolPurpose
22SSHLinux servers pe remote terminal login
80HTTPNormal (unencrypted) website traffic
443HTTPSEncrypted, secure website traffic

Source IP concept: Har rule ka ek "source" bhi hota hai — kaunse IP addresses us port ko use kar sakte hain. 0.0.0.0/0 ka matlab hai "internet pe koi bhi," jabki My IP access ko sirf aapke current IP address tak restrict kar deta hai.

VPC (Virtual Private Cloud)

Definition: VPC AWS ke andar aapka apna private, isolated network hai jahan aapke resources (jaise EC2) rehte hain.

EC2 se relationship: Har EC2 instance ek VPC ke andar hi launch karna hota hai — ye private network boundaries aur IP ranges define karta hai jo instance use kar sakta hai.

Subnet

Definition: Subnet ek VPC ke IP address range ka chhota division hota hai.

Public subnet — Iska internet se route hota hai, isliye yahan instances ko public IP mil sakta hai.

Private subnet — Iska direct internet route nahi hota, isse databases ya internal-only servers ke liye use kiya jaata hai.

EC2 se relationship: Har EC2 instance ek specific subnet ke andar launch hota hai, jo decide karta hai ki wo internet se reach ho sakta hai ya nahi.

Availability Zone (AZ)

Definition: Availability Zone ek AWS Region ke andar ek physical, isolated data center location hoti hai.

EC2 AZ ke andar kyu chalta hai: Har instance ko physically kahin na kahin exist karna hota hai — usse ek specific AZ mein rakhna AWS ko fault isolation dene mein help karta hai (agar ek AZ mein issue ho, doosre unaffected rahte hain).

Region

Definition: Region ek geographic area hai (e.g., Mumbai, Singapore, N. Virginia) jisme multiple Availability Zones hote hain.

Relationship: Ek Region mein bahut saari Availability Zones hoti hain (usually 3 ya zyada), aur har AZ ke apne alag data centers hote hain.

EBS (Elastic Block Store)

Definition: EBS ek EC2 instance se attached persistent block storage hai, virtual hard drive ki tarah.

EC2 EBS kyu use karta hai: Ek EC2 instance ko OS aur data store karne ke liye disk chahiye hoti hai — EBS wo disk deta hai, aur instance stop hone pe bhi data survive karta hai.

Root volume — Primary EBS volume jisme operating system hota hai; instance launch karte waqt automatically create hota hai.

Additional EBS volumes — Baad mein zyada storage ke liye attach kiye jaane wale extra disks (e.g., application data ya databases ke liye).

Public IP

Definition: Public IP ek internet-routable address hai jo aapke instance ko diya jaata hai taaki AWS ke bahar se bhi usse reach kiya ja sake.

Kyu zaruri hai: Iske bina internet pe koi bhi aapke server se connect nahi kar sakta.

Kaise dhundhein: EC2 → Instances kholo, apna instance select karo, aur details panel mein Public IPv4 address field dekho.

Private IP

Definition: Private IP ek internal address hai jo sirf VPC ke andar use ho sakta hai.

Internal communication: Jab EC2 instances ko same network ke andar ek doosre se baat karni ho, bina public internet pe jaaye, tab ye use hota hai.

Elastic IP

Definition: Elastic IP ek static, fixed public IP address hai jo aap allocate karte aur control karte ho.

Kyu use hota hai: Normal Public IP har baar instance stop aur start hone pe change hota hai; Elastic IP same rehta hai.

Public IP se difference: Ek regular Public IP temporary hota hai aur auto-assign hota hai; Elastic IP tab tak permanent rehta hai jab tak aap manually release na karo.

User Data

Definition: User Data ek script hai jo aap instance se attach karte ho, jo instance ke pehli baar boot hone pe automatically run hota hai.

Purpose: Setup tasks automate karne ke liye — software install karna, services start karna, ya server configure karna — bina manual kaam ke.

Kaise use karein: Instance launch karte waqt Advanced Details ke under "User data" field mein ek shell script paste karo.

💰 EC2 Pricing Basics

Theory
  • On-Demand — Ghante/second ke hisaab se pay karo, koi long-term commitment nahi; sabse flexible, lekin per hour sabse mehnga.
  • Reserved Instances — 1 ya 3 saal commit karo aur kaafi kam hourly rate paao; predictable, steady workloads ke liye achha.
  • Savings Plans — 1-3 saal ke liye ek consistent compute usage amount ($/hour) commit karo kam prices ke badle, Reserved Instances se zyada flexible.
  • Spot Instances — AWS ki spare capacity bhaari discount pe use karo; AWS kabhi bhi short notice pe instance wapas le sakta hai, isliye ye fault-tolerant ya flexible workloads ke liye suit karta hai.
  • Free Tier — New AWS accounts har mahine limited hours ke liye t2.micro ya t3.micro instance free chala sakte hain, 12 mahino tak — learning ke liye perfect.

🚀 EC2 Instance Kaise Create Karein

Practical
AWS Console ↓ EC2 ↓ Launch Instance
  1. Instance Name — Ek recognizable naam do, e.g. my-web-server. Ye sirf ek label hai.
  2. AMI — Operating system choose karo. Beginner Linux web server ke liye, Amazon Linux 2023 (Free tier eligible) select karo.
  3. Instance Type — Learning ke liye t3.micro ya t2.micro choose karo (Free Tier eligible).
  4. Key Pair — Existing key pair select karo ya naya banao; .pem file download karke safe rakho.
  5. VPC — default VPC rehne do, jab tak aapke paas already custom network setup na ho.
  6. Subnet — Koi bhi public subnet (ya "No preference") choose karo taaki instance ko internet access mile.
  7. Auto-assign Public IP — Enable pe set karo taaki aap instance ko internet se reach kar sako.
  8. Security Group — Naya banao aur "My IP" se SSH (22) aur, web server ke liye, kahin se bhi HTTP (80) allow karo.
  9. Storage / EBS — Simple test server ke liye default 8 GB gp3 root volume rehne do.
  10. Advanced Details — Default rehne do, jab tak IAM roles ya specific settings chahiye ho.
  11. User Data — Optionally yahan ek startup script paste karo (Section 17 dekho).
  12. Launch Instance — Launch instance pe click karo; AWS ek do minute mein isse boot kar dega.

🔍 EC2 Instance Details Kaise Check Karein

Practical
  1. EC2 → Instances pe jao.
  2. Apne instance ki Instance ID pe click karo taaki details page khule.
  3. Details tab mein aapko ye milega: Instance ID, Instance State, Instance Type, AMI ID, Public IPv4 address, Private IPv4 address, Public IPv4 DNS, Private DNS, Availability Zone, VPC ID, Subnet ID, Security Group, aur Key pair name.
  4. Attached EBS Volume(s), unka size, aur device names dekhne ke liye Storage tab pe jao.

🔑 EC2 Access Kaise Karein

Practical

Method 1: SSH

SSH kya hai: Secure Shell (SSH) ek protocol hai jisse aap network ke through kisi doosre computer pe secure remote terminal session khol sakte ho.

Port 22 kyu: SSH convention ke hisaab se TCP port 22 pe communicate karta hai — isliye Security Group mein port 22 pe inbound traffic allow hona zaruri hai.

.pem file kahan use hoti hai: Ye SSH command ko diya jaata hai taaki password ki jagah aapki identity prove ho sake.

ssh -i "key.pem" ec2-user@PUBLIC-IP

ssh — command jo secure shell connection start karta hai.

-i "key.pem" — SSH ko batata hai ki authentication ke liye kaunsa private key file use karna hai.

ec2-user — Amazon Linux instances ke liye default username (Ubuntu ubuntu use karta hai).

@PUBLIC-IP — aapke EC2 instance ka public IPv4 address.

Method 2: EC2 Instance Connect

  1. EC2 → Instances pe jao aur apna instance select karo.
  2. Top pe Connect pe click karo.
  3. EC2 Instance Connect tab choose karo.
  4. Connect pe click karo — ek browser-based terminal directly khul jaayega, koi key file nahi chahiye.

SSH vs EC2 Instance Connect: SSH ko apna terminal aur private key file chahiye; EC2 Instance Connect temporary, AWS-managed credentials use karke seedha browser se kaam karta hai — quick access ke liye convenient hai lekin regular development work ke liye SSH zyada common hai.

🔄 EC2 Server Update Karna

Practical

Amazon Linux ke liye, run karo:

sudo dnf update -y

sudo — command ko administrator ki tarah run karta hai, system-level changes ke liye zaruri.

dnf — package manager jo Amazon Linux/Fedora/RHEL software install aur update karne ke liye use karte hain.

update — dnf ko batata hai ki saare installed packages ki latest versions fetch aur install kare.

-y — confirmation prompts ka automatically "yes" answer deta hai, taaki update bina rukavat ke chale.

🌐 Apache Web Server Install Karna

Practical 
sudo dnf install -y httpd
sudo systemctl start httpd
sudo systemctl enable httpd
sudo systemctl status httpd

sudo dnf install -y httpd — Apache web server package install karta hai (Amazon Linux pe httpd naam se jaana jaata hai).

sudo systemctl start httpd — Apache service ko turant start karta hai.

sudo systemctl enable httpd — Apache ko configure karta hai ki server reboot hone pe automatically start ho jaaye.

sudo systemctl status httpd — dikhata hai ki Apache abhi chal raha hai aur healthy hai ya nahi.

Apache kya hai? Apache HTTP Server free, widely-used software hai jo visitors ke browsers ko web pages serve karta hai.

Ise install kyu karein? Ek EC2 instance sirf ek bare server hai — website requests ka respond karne ke liye usse Apache jaisa web server software chahiye.

systemctl kya hai? Ye modern Linux systems pe services control karne ke liye use hone wala tool hai (start, stop, enable, status check).

start — service ko abhi turant on karta hai.

enable — har boot pe service ko automatically start karwata hai.

status — report karta hai ki service active hai ya nahi, aur recent log lines dikhata hai.

🛡️ Apache Ke Liye Security Group Configure Karna

Practical

Apache HTTP port 80 pe web pages serve karta hai. Agar ye port Security Group mein open nahi hai, to visitors kabhi bhi website tak nahi pahunch payenge, chahe Apache kitni bhi achhi tarah configure ho.

EC2 ↓ Security Groups ↓ Inbound Rules ↓ Edit Inbound Rules ↓ Add HTTP ↓ Port 80 ↓ Source 0.0.0.0/0
  1. EC2 → Instances pe jao, apna instance select karo, aur Security tab kholo.
  2. Attached Security Group pe click karo.
  3. Inbound rules → Edit inbound rules pe jao.
  4. Add rule pe click karo, type HTTP choose karo (ye automatically port 80 fill kar deta hai).
  5. Source ko 0.0.0.0/0 set karo taaki kahin se bhi traffic allow ho.
  6. Save rules pe click karo.
Security note: 0.0.0.0/0 ka matlab hai internet pe literally koi bhi is port tak pahunch sakta hai. Ye ek public website ke liye port 80/443 pe normal aur expected hai, lekin sensitive ports jaise 22 (SSH) ya database ports (3306, 5432) ko kabhi 0.0.0.0/0 ke liye open mat karo — inhe apne IP ya trusted network tak hi restrict karo.

📜 EC2 User Data

Theory Practical

Ye kya hai: Launch time pe instance se attach ki gayi ek shell script.

Ye kab run hoti hai: Automatically, sirf ek baar, jab instance pehli baar boot hota hai.

Kyu useful hai: Ye setup ko poori tarah automate kar deta hai — launch ke baad koi manual SSH steps ki zarurat nahi.

Kaise add karein: Instance launch karte waqt Advanced details ke under User data box mein script paste karo.

#!/bin/bash

dnf update -y
dnf install -y httpd
systemctl start httpd
systemctl enable httpd
echo "<h1>Welcome to AWS EC2</h1>" > /var/www/html/index.html

#!/bin/bash — system ko batata hai ki ye script Bash shell use karke run honi chahiye.

dnf update -y — kuch bhi setup karne se pehle saare installed packages update karta hai.

dnf install -y httpd — Apache install karta hai.

systemctl start httpd — Apache ko turant start karta hai.

systemctl enable httpd — ensure karta hai ki reboot pe Apache automatically restart ho.

echo "..." > /var/www/html/index.html — ek simple welcome heading directly homepage file mein likh deta hai, taaki instance boot hote hi website live ho jaaye.

⏯️ Stop, Start, Reboot Aur Terminate

Theory Practical

Stop

Instance shutdown ho jaata hai lekin delete nahi hota. EBS root volume aur uska data intact rehta hai. Isse baad mein dobara start kiya ja sakta hai. Compute usage ka billing ruk jaata hai, lekin EBS storage charges chalte rehte hain.

Start

Ek stopped instance ko dobara boot karta hai. Usually ye naya Public IPv4 address paata hai, jab tak Elastic IP attached na ho.

Reboot

Instance ko poori tarah stop kiye bina operating system restart karta hai. Public IP same rehta hai, aur ye physical computer restart karne jaisa hi hai.

Terminate

Instance ko permanently delete karta hai. Default mein, root EBS volume bhi delete ho jaata hai (jab tak "Delete on Termination" disable na ho). Ye undo nahi ho sakta — instance recover nahi kiya ja sakta.

AWS Console Steps (chaaron actions)

  1. EC2 → Instances pe jao.
  2. Apne instance ke aage checkbox select karo.
  3. Top pe Instance state pe click karo.
  4. Stop instance, Start instance, Reboot instance, ya Terminate instance choose karo.
  5. Popup dialog mein action confirm karo.
ActionData Rehta Hai?Public IPReversible?
StopHaanNext start pe change hota haiHaan — dobara start kiya ja sakta hai
RebootHaanSame rehta haiN/A — instance chalta rehta hai
TerminateNahi (root volume usually delete ho jaata hai)Permanently release ho jaata haiNahi — permanent

🌐 Public IP Behavior

Theory

Default mein, EC2 instance ko diya gaya normal Public IPv4 address permanent nahi hota — jab bhi instance stop karke dobara start kiya jaata hai, ye change ho jaata hai. Reboot karne se ye change nahi hota, lekin full stop/start cycle se hota hai.

Isi liye jab bhi fixed public address chahiye ho — jaise agar aapne ek domain name (DNS) apne server pe point kiya hai, ya agar doosre systems specific IP se connect karne ke liye hardcoded hain — tab Elastic IP use kiya jaata hai.

💾 EBS Volume Create Aur Attach Karna

Practical

EBS kya hai? Elastic Block Store EC2 instances ke liye persistent, network-attached disk storage hai.

Additional storage kyu? Default root volume application data, logs, ya databases ke liye kaafi na ho, isliye us data ke liye ek second volume attach kiya jaata hai.

Same Availability Zone rule: Ek EBS volume physically ek Availability Zone ke andar hi rehta hai, isliye ye sirf usi AZ mein chal rahe EC2 instance se attach ho sakta hai.

  1. EC2 → Elastic Block Store → Volumes pe jao.
  2. Create volume pe click karo.
  3. Volume type (e.g., gp3), Size, aur apne EC2 instance jaisi hi Availability Zone choose karo.
  4. Create volume pe click karo.
  5. Naya volume select karo, Actions → Attach volume pe click karo.
  6. Apna EC2 instance choose karo aur Device name confirm karo (e.g., /dev/xvdf).
  7. Attach volume pe click karo.

Disk attach hui ya nahi confirm karne ke liye, instance se connect karke run karo:

lsblk

lsblk saare block devices list karta hai; naya volume ek extra disk ki tarah dikhega (e.g., xvdf) jiska abhi tak koi mount point nahi hoga — isi se aap ise identify kar sakte ho.

🗂️ EBS Volume Format Aur Mount Karna

Practical 
sudo mkfs -t xfs /dev/xvdf

sudo mkdir /data

sudo mount /dev/xvdf /data

df -h

sudo mkfs -t xfs /dev/xvdf — raw naye volume ko XFS filesystem se format karta hai taaki Linux usme files store kar sake. Ye step sirf ek baar, naye khaali volume pe zaruri hota hai.

sudo mkdir /data — ek empty folder banata hai jo naye disk ke access point ki tarah kaam karega.

sudo mount /dev/xvdf /data — formatted volume ko /data folder se attach ("mount") karta hai, isliye /data ke andar save kiya gaya kuch bhi actually EBS volume pe store hota hai.

df -h — disk usage dikhake mount work karne ki confirmation deta hai, jisme naya /data entry bhi shamil hoga.

Note: Device name aapke instance type ke hisaab se /dev/xvdf se alag ho sakta hai. Format ya mount karne se pehle hamesha lsblk se actual naam check karo.

📸 EBS Snapshot Create Karna

Practical

Snapshot kya hai? Ek EBS volume ka point-in-time backup copy, jo Amazon S3 mein store hota hai.

Kyu use hota hai? Risky changes se pehle data protect karne ke liye, ya kahin aur identical volumes banane ke liye.

EBS se relation: Ek snapshot ek EBS volume *se* liya jaata hai, aur baad mein usi data ke saath ek bilkul naya EBS volume *banane* ke liye use ho sakta hai.

  1. EC2 → Elastic Block Store → Volumes pe jao.
  2. Jo volume backup karna hai use select karo.
  3. Actions → Create snapshot pe click karo.
  4. Ek description daalo aur Create snapshot pe click karo.
  5. Elastic Block Store → Snapshots ke under ise dekho.

🔒 EC2 Security Best Practices

Theory
⚠️ IMPORTANT
  • SSH (port 22) ko bina zarurat sabke liye expose mat karo.
  • Jahan appropriate ho, SSH rules ke liye source My IP use karo.
  • Strong key-pair management use karo — .pem files organized aur securely backed up rakho.
  • Apni .pem private key files kabhi kisi ke saath share mat karo.
  • Scripts ya code ke andar passwords ya secrets hardcode mat karo.
  • Long-lived credentials ki jagah IAM roles aur policies properly use karo.
  • Operating system aur packages regularly update rakho.
  • Sirf wahi ports open karo jo aapke application ko actually chahiye.
  • Kisi bhi production website ke liye HTTPS (port 443) use karo.
  • Unnecessary charges avoid karne ke liye unused resources stop ya terminate karo.

🧯 EC2 Troubleshooting

Practical

EC2 Mein SSH Nahi Ho Pa Raha

Order mein ye check karo:

  • Instance running state mein hai?
  • Public IP sahi aur current hai?
  • Security Group aapke IP se inbound port 22 allow karta hai?
  • Aap sahi username use kar rahe ho (e.g., ec2-user)?
  • Aap sahi .pem file point kar rahe ho?
  • Aapki taraf koi network/firewall issue outbound SSH ko block kar raha hai?

Website Nahi Khul Rahi

  • Instance running hai?
  • Apache chal raha hai (sudo systemctl status httpd)?
  • Security Group inbound port 80 allow karta hai?
  • Aap sahi Public IP use kar rahe ho?
  • /var/www/html/index.html actually exist karti hai?
  • Koi doosra Security Group rule silently traffic block kar raha hai?

Apache Chal Nahi Raha

sudo systemctl status httpd
sudo systemctl restart httpd

Pehle error dekhne ke liye status check karo, phir recovery try karne ke liye service restart karo.

Port Check Karna

sudo ss -tulpn

ss -tulpn saare listening TCP/UDP ports aur unhe use karne wale process ke saath list karta hai — ye confirm karne ke liye useful hai ki Apache actually port 80 pe listen kar raha hai.

Apache Logs Check Karna

sudo journalctl -u httpd

journalctl -u httpd specifically httpd (Apache) service ke system log entries dikhata hai — startup errors ya crashes spot karne mein helpful hota hai.

📏 Vertical Scaling

Theory
t3.micro ↓ t3.medium

Vertical scaling ka matlab hai kisi existing instance ko bade (ya chhote) instance type mein badalna taaki usse zyada (ya kam) CPU aur RAM mile — same single server bas zyada powerful ban jaata hai.

↔️ Horizontal Scaling

Theory
Load Balancer ↓ ┌────┼────┐ ↓ ↓ ↓ EC2 EC2 EC2

Horizontal scaling ka matlab hai workload share karne ke liye ek instance ko bada karne ki jagah zyada EC2 instances add karna. Ye useful hai kyunki isse traffic multiple servers mein spread hota hai, jisse performance aur reliability dono improve hoti hain — agar ek instance fail ho jaaye, to baaki traffic serve karte rehte hain.

⚖️ EC2 + Load Balancer

Theory

Ek Load Balancer multiple EC2 instances ke aage baitha hota hai aur incoming traffic ko unme evenly distribute karta hai. Users hamesha Load Balancer ke address se connect hote hain, aur ye har request ko peeche khade healthy EC2 instances mein se kisi ek ko forward kar deta hai — individual servers ko hide karke, aur users ko affect kiye bina instances add/remove karna aasan bana deta hai.

📈 EC2 + Auto Scaling

Theory

Auto Scaling kya hai? Ek feature jo demand (jaise CPU usage ya traffic levels) ke hisaab se automatically EC2 instances add ya remove karta hai.

Kyu use hota hai? Taaki aapka application traffic spikes ko automatically handle kar sake, aur jab traffic kam ho to shrink hoke paise bhi bache.

Low Traffic → Few EC2 Instances High Traffic → Auto Scaling adds more EC2 Instances Traffic drops → Auto Scaling removes extra instances

Auto Scaling ek Launch Template ke saath kaam karta hai (exactly janne ke liye ki naye instances kaise banaye jaayein) aur typically ek Load Balancer ke saath (jo bhi instances abhi exist karte hain unme traffic distribute karne ke liye).

🎯 EC2 Interview Questions

Interview Prep

Q: EC2 kya hai?

A: Ek web service jo cloud mein resizable virtual servers provide karti hai.

Q: EC2 instance kya hai?

A: EC2 ke andar create aur run kiya gaya ek single virtual server.

Q: AMI kya hai?

A: Ek template jisme OS aur optionally pre-installed software hota hai, instances launch karne ke liye use hota hai.

Q: Instance Type kya hai?

A: Ek configuration jo instance ki CPU, RAM, aur network performance define karti hai.

Q: Key Pair kya hai?

A: Ek public/private key combination jo instance mein secure, passwordless login ke liye use hoti hai.

Q: Security Group kya hai?

A: Ek virtual, instance-level firewall jo inbound aur outbound traffic control karta hai.

Q: EBS kya hai?

A: Elastic Block Store — EC2 instances se attached persistent block storage.

Q: Public IP kya hai?

A: Instance ko diya gaya internet-reachable address, usually stop/start pe change hota hai.

Q: Private IP kya hai?

A: VPC ke andar communication ke liye use hone wala internal address.

Q: Elastic IP kya hai?

A: Ek static, permanent public IP address jo aap allocate aur control karte ho.

Q: User Data kya hai?

A: Ek script jo instance ke pehli baar boot hone pe automatically run hoti hai, setup automate karne ke liye.

Q: Stop aur Terminate mein kya difference hai?

A: Stop instance aur data ko rakhta hai, reversible hai; Terminate permanently delete kar deta hai.

Q: Stop aur Reboot mein kya difference hai?

A: Stop instance ko poori tarah shutdown karta hai; Reboot OS restart karta hai jabki instance chalta rehta hai.

Q: AMI aur Snapshot mein kya difference hai?

A: AMI ek full instance template hai; Snapshot ek single EBS volume ka backup hota hai.

Q: Launch Template kya hai?

A: EC2 instances ko consistently launch karne ke liye ek saved, reusable configuration.

Q: Availability Zone kya hai?

A: Ek AWS Region ke andar ek isolated physical data center location.

Q: AWS Region kya hai?

A: Multiple Availability Zones wala ek geographic area.

Q: Linux EC2 instance se kaise connect karte hain?

A: Public IP aur private key ke saath SSH ke through, ya browser se EC2 Instance Connect ke through.

Q: EC2 pe website kaise host karte hain?

A: Ek web server (jaise Apache) install karke, website files ko uske web root mein daalke, aur Security Group mein port 80/443 open karke.

Q: Agar EC2 server access nahi ho raha to kaise troubleshoot karein?

A: Instance state, Public IP, Security Group rules, sahi username, aur sahi key file check karein.

Q: Port 22 kyu use hota hai?

A: Ye SSH remote terminal access ka standard port hai.

Q: Port 80 kyu use hota hai?

A: Ye unencrypted HTTP web traffic ka standard port hai.

Q: Port 443 kyu use hota hai?

A: Ye encrypted HTTPS web traffic ka standard port hai.

Q: EC2 instance stop karne ke baad Public IP ka kya hota hai?

A: Ye release ho jaata hai aur instance dobara start hone pe naya assign hota hai (jab tak Elastic IP attached na ho).

Q: Hum Elastic IP kyu use karte hain?

A: Instance ke liye ek fixed, unchanging public address paane ke liye.

Q: Vertical scaling kya hai?

A: Ek existing single instance ke resources (CPU/RAM) ko badhana.

Q: Horizontal scaling kya hai?

A: Workload share karne ke liye zyada instances add karna.
