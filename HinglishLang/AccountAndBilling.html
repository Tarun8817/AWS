⚠️ Real-World Pricing & Free Tier Note

AWS pricing aur Free Tier limits time ke sath update hoti rehti hain aur different regions mein thoda farak ho sakta hai. Production decisions lene se pehle hamesha official AWS Pricing page check karein. Ye notes aapko core concepts, governance aur practical operations sikhane ke liye hain.

THEORY 1. AWS Account Kya Hai?

"AWS Account ek secure aur logically isolated container hai jiske andar aapke saare AWS resources (servers, databases, storage), logins (users) aur billing ka sara hisaab rehta hai."

Aasan shabdon mein: Maan lijiye AWS ek bohot bada corporate complex hai. AWS Account us complex ke andar aapka apna private safe locker hai. Jo kuch bhi aap banate hain — EC2 server, S3 bucket, database — wo isi locker ke andar safe rehta hai aur sara bill isi account se link hota hai.

AWS Account ke Main Elements:

  • AWS Account ID: Ek unique 12-digit number (jaise 123456789012) jo aapke account ki official identity hai.
  • Root User: Signup ke time banne wala master owner login jiske paas unlimited powers hoti hain.
  • IAM Users & Roles: Team members aur services ke liye banaye gaye limited-access accounts.
  • AWS Services: Wo actual tools jo aap run karte hain (EC2, S3, RDS, Lambda).
  • Billing: Wo system jo usage track karke monthly invoice generate karta hai.

THEORY 3. Root User & MFA Security

Root User account ka super-owner login hota hai jo initial signup ke time banta hai. Iske paas account ki har service, billing aur resources par 100% full, unrestricted control hota hai.

Root User ko Daily Use Kyun Nahi Karna Chahiye?

  • Unlimited Power: Root access ko IAM policies se roka nahi ja sakta. Ek galat click se poora production database ya account delete ho sakta hai.
  • Hacking Danger: Agar Root User ka password leak ho gaya, toh hacker hazaron expensive mining servers chala kar aapka lakhon ka bill bana sakta hai.
🔒 Root User Security Best Practices:
  • MFA Enable Karein: Google Authenticator ya physical hardware key (YubiKey) se login par extra OTP lagayein.
  • Strong Password: 20+ characters ka strong unique password use karein.
  • Root Access Keys KABHI na banayein: CLI ke liye Root User ki access keys mat banayein.
  • Daily Work ke liye IAM: Daily coding aur management ke liye IAM Users ya IAM Roles use karein.

THEORY 4. IAM User & Least Privilege

IAM (Identity and Access Management) User ek alag login identity hai jo aap apne team members ya apps ke liye banate hain jisme sirf utni hi permissions hoti hain jitni kaam ke liye zaroori hon.

Root User vs IAM User (Difference Table):

5. Account ID vs Account Alias

Account ID ek 12-digit number hota hai (jaise 123456789012). Account Alias ek friendly naam hota hai (jaise mycompany-prod) jo console login link ko yaad rakhna aasan banata hai:

Alias Login URL: https://mycompany-prod.signin.aws.amazon.com/console

6. Regions aur Availability Zones ka Billing par Asar

AWS ki pricing har Region mein thodi alag hoti hai (kyunki har country mein data center, bijli aur tax costs alag hote hain). Stockholm (eu-north-1) ya Mumbai (ap-south-1) ka hourly rate dusre regions se thoda alag ho sakta hai.

THEORY 7 & 8. AWS Billing Basics & Billing Dashboard

AWS Billing ek Pay-as-you-go model par chalta hai — yani aap sirf utna hi pay karte hain jitna aapne actually use kiya hai (per-second compute, per-GB storage).

8. Billing Dashboard Console Guide:

  • Current Month-to-Date: Ab tak is mahine kitna kharcha ho chuka hai.
  • Forecast: Month ke end tak machine learning estimate ki kitna bill ban sakta hai.
  • Spend by Service: Kaunsi service sabse zyada paise le rahi hai (EC2, RDS, S3).

Billing Dashboard Kholne ke Steps:

  1. AWS Console mein login karein.
  2. Top-right corner mein apne account name par click karein.
  3. Billing and Cost Management select karein.

THEORY 9 & 10. AWS Free Tier Limits & Pricing Models

9. Free Tier ke 3 Types:

Free Tier Model Yeh Kaise Kaam Karta Hai? Popular Examples
12-Months Free Account signup ke pehle 12 mahine tak free milta hai. 750 hrs/month t2.micro / t3.micro EC2, 5 GB S3 Storage, 750 hrs RDS.
Always Free Kahi expire nahi hota; sabhi accounts ke liye hamesha free rehta hai. 1,000,000 Lambda requests/month, 25 GB DynamoDB storage, 10 CloudWatch metrics.
Short-Term Trials Service activate karne ke din se fixed dino ka trial (e.g. 15 to 60 days). Amazon Redshift 2-month trial, Amazon Inspector 15-day trial.

10. AWS Pricing ke 5 Main Pillars:

  • 1. Compute: Server jitne ghante/seconds chalega (EC2, Lambda).
  • 2. Storage: Jitna GB data disk par save rahega (EBS, S3).
  • 3. Data Transfer OUT: AWS se bahar internet par data bhejne ka per-GB charge.
  • 4. API Requests: S3 PUT/GET ya database read/write requests.
  • 5. Gateways & Static IPs: NAT Gateway ka hourly fee ya khali padi Elastic IP ka charge.

18. 10 Golden Rules: AWS Ka Bill Kaise Bachayein:

  • 1. Faltu EC2 Stop/Terminate Karein: Idle server bhi chalne ka paisa leta hai.
  • 2. Unattached EBS Disks Delete Karein: EC2 delete hone ke baad unke piche bache EBS volumes bill badhate hain.
  • 3. Unused Elastic IPs Release Karein: Khali padi Elastic IP par hourly charge lagta hai.
  • 4. NAT Gateways Delete Karein: NAT Gateway ~$32/month ka base charge leta hai; lab ke baad turant delete karein.
  • 5. Load Balancer Clean Karein: Empty test ALBs ko delete karein.
  • 6. S3 Data Clean Karein: Purane test files aur snapshots ko delete karein.
  • 7. Sahi Size Choose Karein (Right-Sizing): Chhote task ke liye bada instance na chalayein.
  • 8. S3 Lifecycle Rules: Purana data automatically Glacier archive mein bhejein.
  • 9. Reserved / Savings Plans: 1 ya 3 saal ke steady production servers par 72% tak discount paayein.
  • 10. Night/Weekend Shutdown: Dev servers ko raat mein automatically stop karein.

23. Chalti Hui Hidden Resources Ko Dhoond Kar Band Karein:

  1. EC2 Console: Instances → filter karein Instance state = running. Unused servers stop karein.

INTERVIEW 26. TOP 25+ AWS BILLING & ACCOUNT INTERVIEW QUESTIONS & ANSWERS

Q1. AWS Account kya hai aur ye isolation boundary ki tarah kaise kaam karta hai?

AWS Account cloud ke andar aapka ek dedicated, secure container hai jisme aapke saare virtual servers, databases, security configurations aur billing details store hoti hain. Default roop se ek account ke resources kisi doosre account ke resources se baat ya connect nahi kar sakte jab tak cross-account IAM roles ya VPC Peering configure na kiya jaye.

Key takeaway: AWS Account boundary security aur billing ka 100% blast-radius protection provide karti hai.
Q2. AWS Root User kya hai aur isko daily engineering tasks ke liye kyun avoid karna chahiye?

Jab aap pehli baar email aur password se AWS account banate hain, toh Root User banta hai. Iske paas poore account aur billing ka unrestricted master access hota hai. Agar iska password leak ho jaye ya galti se galat command chal jaye, toh poora infrastructure delete ho sakta hai jiska koi backup ya audit trail nahi bachta.

Key takeaway: Root User par MFA enable karke lock kar dein aur daily kaam ke liye scoped IAM Users/Roles banayein.
Q3. IAM mein Principle of Least Privilege kya hai aur ye billing protection mein kaise madad karta hai?

Principle of Least Privilege ka matlab hai kisi user, developer ya application ko sirf utni hi limited permissions dena jitni uske kaam ke liye strictly zaroori ho. Cost perspective se ye kisi intern ya script ko galti se mehnge GPU instances, enterprise databases ya heavy NAT Gateways launch karne se rokta hai.

Key takeaway: Zero permissions se start karein aur specific ARNs par hi actions allow karein.
Q4. Pay-As-You-Go pricing model kya hai aur AWS billing calculate kaise karta hai?

Pay-as-you-go ka matlab hai aap jitna cloud capacity (compute seconds, storage GB, ya network egress) actually consume karte hain, sirf usi ka payment karte hain bina kisi advance security deposit ya upfront investment ke. Jab aap instance stop ya terminate kar dete hain, uska hourly compute bill turant band ho jata hai.

Key takeaway: Ye heavy capital expense (CapEx) ko flexible operational expense (OpEx) mein badalta hai.
Q5. AWS Budgets aur AWS Cost Explorer mein kya exact difference hai?

Cost Explorer ek reactive reporting tool hai jo purane kharche ka graph, breakdown aur future prediction dikhata hai. AWS Budgets ek proactive tool hai jisme aap spending limit set karte hain (e.g. $50/month) aur limit reach hote hi automatic email/SNS alert ya corrective action trigger hota hai.

Key takeaway: Cost Explorer batata hai paise kahan kharch hue; AWS Budgets alert karta hai overspend hone se pehle.
Q6. AWS Free Tier ke 3 alag-alag types kaunse hain?

1) 12-Months Free: Account signup ke baad 1 saal tak valid (e.g. 750 hrs/month t2.micro/t3.micro EC2, 5 GB S3 Standard storage).
2) Always Free: Jo hamesha free rehte hain sabhi accounts ke liye (e.g. 1 Million Lambda requests/month, 25 GB DynamoDB NoSQL storage).
3) Short-Term Trials: Kisi service ko pehli baar activate karne par limited time trial (e.g. GuardDuty 30-day trial).

Key takeaway: Free Tier monthly limits par chalta hai; limit cross hote hi standard On-Demand rate lagta hai.
Q7. AWS Data Transfer (Inbound vs Outbound vs Inter-Region) par paise kaise leta hai?

Inbound Data: Internet se AWS ke andar data upload karna 100% FREE hota hai. Outbound Data: AWS se bahar internet par data bhejna per-GB charge hota hai (pehle 100 GB/month globally free, phir ~$0.09/GB). Do alag AWS Regions ke beech data transfer ~$0.02/GB hota hai, aur same region ke do alag AZs ke beech data transfer ~$0.01/GB charge hota hai.

Key takeaway: Heavy downloads ke liye EC2 ke aage Amazon CloudFront CDN lagane se bandwidth kharcha kaafi kam ho jata hai.
Q8. Unattached ya unused Elastic IP (EIP) par paise kyun lagte hain?

Public IPv4 addresses internet par limited aur scarce resources hain. Developers inko allocate karke bina use kiye block na karein (hoarding na karein), isliye AWS unallocated ya stopped instance se judhi Elastic IP par hourly charge (~$0.005/hour) lagata hai.

Key takeaway: Jo Elastic IP use mein na ho, use turant VPC Console se Release kar dena chahiye.
Q9. Cost Allocation Tags kya hote hain aur unhe reports mein dekhne ke liye kya karna padta hai?

Cost Allocation Tags resources par lagaye gaye key-value labels hote hain (jaise Project: MERN-App, Env: Production). Ye automatically Cost Explorer mein nahi aate; administrator ko Billing Console → Cost Allocation Tags mein jaakar unhe Activate karna padta hai, jiske 24 ghante baad tagging data reports mein show hota hai.

Key takeaway: Company ke alag-alag projects aur teams ka kharcha separate track karne ke liye tags zaroori hain.
Q10. Agar monthly AWS invoice ka payment fail ho jaye toh kya hota hai?

Payment fail hote hi AWS account owner ko alert emails bhejta hai aur agle kuch dino mein transaction retry karta hai. Agar 30 se 60 din tak bill pay na ho, toh AWS account par naye resources banana block kar deta hai, running servers stop kar deta hai aur aakhirkar account suspend kar deta hai.

Key takeaway: Billing settings mein Alternate Contacts add karein aur backup card zaroor attach rakhein.
Q11. IAM User aur IAM Role mein kya basic difference hai?

IAM User ek permanent login identity hai jisme long-term credentials (password ya access keys) hote hain jo insaan ya external system use karta hai. IAM Role ke paas koi permanent password ya key nahi hoti; ise EC2 server, Lambda function ya authorized users temporarily assume karke short-term STS credentials lete hain.

Key takeaway: Application code ke andar permanent keys na daalein; compute resources par IAM Role attach karein.
Q12. AWS par surprise/unexpected billing se bachne ke top best practices kya hain?

1) $10, $50 ke multi-tier AWS Budgets alerts set karein.
2) Global us-east-1 region mein CloudWatch Billing Alarms on karein.
3) Root aur IAM par mandatory MFA enable karein.
4) Khali pade EBS volumes, unattached Elastic IPs aur idle NAT Gateways ko delete karein.
5) AWS Cost Anomaly Detection activate karein.
6) Practical labs ke turant baad test resources terminate karein.

Key takeaway: Automated budget alerts aur clean-up habits se 99% billing shocks se bacha ja sakta hai.
Q13. Cost Explorer mein kaise pata karein ki sabse zyada kharcha kis service ya operation par ho raha hai?

AWS Cost Explorer kholein, time filter ko "Daily" par set karein, aur Group By option use karein: Service wise dekhne ke liye Service select karein, location ke liye Region select karein, aur exact line-item (jaise NatGateway-Hours ya t3.xlarge) dekhne ke liye Usage Type select karein.

Key takeaway: "Usage Type" filter lagate hi bill ka sabse micro component saaf dikh jata hai.
Q14. Agar NAT Gateway par koi traffic na aa raha ho, fir bhi uska kharcha kyun lagta hai?

NAT Gateway ek fully managed, high-availability dedicated networking component hai. AWS ise zone ke andar 24/7 run karne ke liye fixed hourly provisioning charge (~$0.045/hour = lagbhag $32.40/month per NAT Gateway) leta hai, chahe data transfer zero ho.

Key takeaway: Multi-AZ VPC mein 3 NAT Gateways ka idle kharcha ~$100/month hota hai; practical ke baad NAT Gateway delete karein.
Q15. Kisi IAM User ko Billing & Cost Management Console ka access kaise diya jata hai?

Iske liye 2 mandatory steps hote hain:
1) Root User login karke Account Settings mein jayega aur IAM User and Role Access to Billing Information ko Activate karega.
2) Uske baad administrator IAM User/Group par billing policy (jaise BillingReadOnlyAccess) attach karega.

Key takeaway: Bina Root User ke step 1 activate kiye, IAM user ko billing policy dene par bhi Access Denied error aayega.
Q16. AWS Account Alias kya hota hai aur iska kya fayda hai?

Account Alias ek custom, aasan naam hota hai jo aapke login URL mein 12-digit ke random Account ID ko replace kar deta hai (jaise https://my-company-dev.signin.aws.amazon.com/console). Isse engineers ko login URL yaad rehta hai aur Dev/Prod accounts mein confusion nahi hota.

Key takeaway: Account Alias poore AWS globe mein unique hona chahiye.
Q17. On-Demand Instances, Reserved Instances (RI), aur Savings Plans mein kya farak hai?

On-Demand: Full flexibility, per-second payment, zero commitment, sabse costly rate.
Reserved Instances (RI): Specific instance family aur region ke liye 1 ya 3 saal ka commitment, jisme up to 72% discount milta hai.
Compute Savings Plans: Hourly spend (e.g. $10/hour) ka 1 ya 3 saal ka commitment; ye automatic EC2, Fargate aur Lambda par up to 66% discount apply kar deta hai chahe region ya OS change ho.

Key takeaway: Modern workloads aur containers ke liye Compute Savings Plans sabse best aur flexible hote hain.
Q18. AWS Pricing Calculator kya hai aur ise kab use karte hain?

AWS Pricing Calculator (calculator.aws) ek free online tool hai jisse production architecture build karne se pehle har service (EC2, S3, RDS, Bandwidth) ka monthly aur annual cost estimate calculate kiya ja sakta hai aur management approval ke liye export kiya ja sakta hai.

Key takeaway: Infrastructure live karne se pehle Pricing Calculator se budget planning karna zaroori standard hai.
Q19. AWS Organizations mein Consolidated Billing kya hota hai aur iske kya fayde hain?

Consolidated Billing ek master management account ke zariye company ke multiple sub-accounts ke bills ko combine kar deta hai. Iske fayde: 1) Single unified invoice aur payment method. 2) Volume Tier Discounts: saare accounts ka S3 storage combine hoke saste tier mein jaldi enter hota hai. 3) Shared Reserved/Savings discounts.

Key takeaway: Organization level par company ke overall cloud expenses ko drastically reduce karta hai.
Q20. AWS Cost Anomaly Detection kya hai aur ye achanak badhe kharche ko kaise pakadta hai?

Ye ek free Machine Learning service hai jo aapke account ke daily spending patterns ko monitor karti hai. Agar koi script galti se loop mein 50 instances launch kar de ya koi key hack ho jaye, toh ye turant anomaly detect karke root cause batata hai aur email/Slack par alert trigger karta hai.

Key takeaway: Runaway billing accidents ko early stage par hi rok deta hai.
Q21. AWS Compute Optimizer kya hai aur ye over-provisioning kaise rokta hai?

Compute Optimizer CloudWatch metrics (CPU, RAM, Disk I/O) ko pichhle 14 dino tak analyze karke AI recommendations deta hai ki kaunsa EC2 instance over-provisioned (bada size) hai aur use chhota karke kitna paisa bachaya ja sakta hai bina application slow hue.

Key takeaway: Right-sizing suggestions se server bill 20% se 50% tak kam ho jata hai.
Q22. Amazon S3 Lifecycle Rules storage cost ko kaise optimize karte hain?

S3 Lifecycle Rules files ki age ke hisab se unhe saste storage tiers mein auto-move karte hain: S3 Standard ($0.023/GB) → 30 din baad Standard-IA ($0.0125/GB) → 90 din baad Glacier Flexible ($0.0036/GB) → 180 din baad Glacier Deep Archive ($0.00099/GB).

Key takeaway: Purane compliance logs ko Deep Archive mein rakhne se storage bill mein 95% tak ki bachat hoti hai.
Q23. Service Control Policies (SCPs) kya hote hain aur cost guardrails kaise lagate hain?

SCPs AWS Organizations level par lagne wali central guardrails hain jo poore account ki maximum allowed permissions tay karti hain. Admin SCP laga sakta hai jisse sub-accounts mein koi bhi developer mehnge instance families launch na kar sake ya unauthorized expensive regions use na kar sake.

Key takeaway: Member account ka Root User bhi SCP guardrail ko bypass nahi kar sakta.
Q24. Service Quotas (Hard Limits) aur Billing Alarms mein kya antar hai?

Billing Alarms: Sirf notification bhejte hain jab spending limit cross hoti hai; ye servers ko chalne se nahi rokte.
Service Quotas: AWS dwara set kiye gaye physical resource limits hote hain (jaise max 32 vCPUs). Limit reach hone par AWS naye instances ka creation actively reject kar deta hai jab tak quota increase approve na ho.

Key takeaway: Quotas runaway automated scripts ke damage ko physical level par cap karte hain.
Q25. Unused AWS Account ko securely close kaise karein taaki aage koi charge na lage?

1) Root User login karein.
2) Saare regions se running EC2, EBS volumes, Elastic IPs, NAT Gateways, S3 buckets aur RDS databases manually delete karein.
3) Account Settings mein scroll down karke Close Account par click karein aur acknowledgments confirm karein.
Account 90 dino ke post-closure period mein chala jata hai jisme koi naya charge nahi banta.

Key takeaway: Account band karne se pehle resources clean karna mandatory hai taaki final invoice zero aaye.
