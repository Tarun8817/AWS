Level 1: AWS IAM (Identity & Access Management)

AWS account ki security, users, groups, roles aur JSON policies ko aasan Hinglish mein samjhein.

1. IAM kya hai? (Simple Explanation)

IAM (Identity and Access Management) AWS ki ek free service hai jisse aap yeh control karte hain ki kaun aapke AWS account mein login kar sakta hai aur unhe kin resources (EC2, S3, RDS) ka access milega.

  • Root User: Account banate waqt jo email use hota hai. Isko daily use nahi karna chahiye.
  • IAM Users: Har team member ke liye alag user account banayein.
  • IAM Groups: Ek jaise permissions wale users ko group mein rakhein (e.g. Developers, Admins).
  • IAM Roles: Temporary permissions jo EC2 instances ya Lambda functions ko assign hoti hain.

2. JSON Policies ka Basic Structure

IAM permissions JSON format mein likhi jaati hain jisme 4 main elements hote hain: Effect, Action, Resource, aur Condition:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::my-bucket-name"
    }
  ]
}

3. IAM Users & User Groups

Users individual identities hain jabki Groups multiple users ko ek saath permissions assign karne ke liye use hote hain:

  • Admin Group: AdministratorAccess policy ke sath management tasks ke liye.
  • Developers Group: Sirf EC2, S3, RDS read/write permissions ke sath.
  • MFA (Multi-Factor Authentication): Har user ke liye zaroori enable karein.

4. IAM Roles vs IAM Policies

Policies permission documents hain, jabki Roles identities hain jinhe temporary credentials ke through assume kiya jata hai (jaise EC2 instance ko S3 access dena bina secret keys hardcode kiye).

5. Security Best Practices

  • Principle of Least Privilege: Sirf utna access dein jitna kaam ke liye zaroori ho.
  • Root User Lock: Root account par MFA lagayein aur access keys delete karein.
  • Rotate Credentials: Regular intervals par passwords aur keys change karein.
