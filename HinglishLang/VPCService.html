THEORY 1. INTRODUCTION — AWS VPC Kya Hai?

"AWS VPC (Virtual Private Cloud) AWS ke andar aapka ek logically isolated virtual private network hota hai, jahan aap apne compute resources (jaise EC2 instances), databases (RDS), aur load balancers ko securely launch aur control karte hain."

Agar aap networking mein bilkul beginner hain, toh ise aasan bhasha mein samjhein: Maan lijiye AWS ek bohot bada corporate building hai. AWS VPC us building ke andar aapka apna rented, locked private office floor hai! Sirf wahi log andar aa sakte hain jinko aap permission dete hain, aur poore floor ke darwaze, security guard aur cameras aapke control mein hote hain.

Key Terms Ko Simple Hindi/Hinglish Mein Samjhein:

  • AWS (Amazon Web Services): Duniya ka sabse bada cloud provider jo humein on-demand servers, storage aur networking services provide karta hai.
  • Network: Jab do ya do se zyada computers aapas mein data ya files share karne ke liye jude hote hain, use network kehte hain.
  • Virtual Network: Physical cables aur hardware switches ke bina, software ke through banaya gaya network.
  • Private Network: Aisa network jo public internet par khula nahi hota; bahar ka koi bhi unknown user bina permission ke access nahi kar sakta.
  • VPC (Virtual Private Cloud): AWS account ke andar aapka dedicated, boundary-secured virtual network.

VPC Ki Zaroorat Kyun Hoti Hai?

Real-world projects mein bina security boundary ke kaam karna suicidal hai. VPC aapko complete control deta hai:

  • IP Address Range: Aap khud decide karte hain ki aapke network ka IP scheme kya hoga (e.g., 10.0.0.0/16).
  • Subnets: Network ko public aur private parts mein divide karne ki azadi.
  • Route Tables: Data packets kis raste travel karenge, ye tay karna.
  • Security Firewalls: Security Groups aur NACLs ke zariye multiple protection layers lagana.
⚠️ Agar AWS mein VPC Isolation na ho toh kya hoga?
  • Direct Internet Attacks: Har EC2 instance aur database ka direct public IP hoga, jisse hackers aur bots 24/7 unpar attacks karenge.
  • No Internal Security: Agar ek frontend web server hack ho gaya, toh hacker seedhe internal customer database ko bina kisi rukawat ke download kar lega.
  • IP Conflicts: Aap on-premises office network ya VPN ke sath connect nahi kar payenge kyunki IP addresses conflict karenge.

THEORY 2. VPC KYUN ZAROORI HAI? (Real-World MERN Stack Example)

Chaliye ek practical MERN (MongoDB/MySQL, Express, React, Node.js) application ka example lete hain.

Ek production application mein 3 main layers hoti hain:

  1. Frontend (React / Next.js): Ise internet ke normal users browse karenge.
  2. Backend API (Node.js / Express): Business logic run karega aur database se connect karega.
  3. Database (MongoDB / Amazon RDS PostgreSQL): Isme confidential customer data, passwords aur payment details save hoti hain.
Golden Security Rule: Database ko KABHI BHI direct public internet par expose nahi kiya jata! Database ka koi public IP nahi hona chahiye.

VPC Is Problem Ko Kaise Solve Karta Hai?

+-------------------------------------------------------------------------+ | PUBLIC INTERNET | | (End-Users Browsing) | +-------------------------------------------------------------------------+ │ ▼ +-------------------------------------------------------------------------+ | Application Load Balancer (ALB) | | (Accepts HTTPS Requests on Port 443) | +-------------------------------------------------------------------------+ │ ▼ +-------------------------------------------------------------------------+ | PUBLIC SUBNET (Frontend / ALB) | | Internet Gateway se connected hai (Publicly Accessible) | +-------------------------------------------------------------------------+ │ (Internal Private Traffic Only) ▼ +-------------------------------------------------------------------------+ | PRIVATE SUBNET 1 (Backend EC2) | | Node.js API — No Public IP — Internet se direct access BAND | +-------------------------------------------------------------------------+ │ (Database Port Only e.g., 5432/27017) ▼ +-------------------------------------------------------------------------+ | PRIVATE SUBNET 2 (RDS Database) | | Database Server — Completely isolated inside private network | +-------------------------------------------------------------------------+

Yeh Architecture Kyun Best Hai?

  • Zero Direct Database Access: Internet par baitha koi bhi hacker direct database ko ping tak nahi kar sakta kyunki database ke paas public IP hi nahi hai!
  • Single Entry Point: Sirf Load Balancer bahar ki duniya se baat karta hai aur SSL certificate check karta hai.
  • Strict Communication: Backend sirf ALB ki baatein sunta hai, aur Database sirf Backend ki baatein sunta hai.

THEORY 4. 19 IMPORTANT VPC COMPONENTS (Complete Reference)

VPC ke sabhi 19 important components ka aasan Hindi/Hinglish explanation aur practical use:

Component Yeh Kya Hai? Kyun Use Hota Hai? Real Practical Example
1. VPC Aapka dedicated, logically isolated cloud network. Resources ko complete boundary isolation aur control dene ke liye. Company ke production infrastructure ko 10.0.0.0/16 par chalana.
2. CIDR Block IP address range likhne ka standardized format. VPC ya subnet mein kitne IP addresses honge, yeh decide karta hai. 10.0.0.0/16 se VPC ko 65,536 total IPs milte hain.
3. Subnet VPC ka chhota hissa jo 1 Availability Zone ke andar rehta hai. Traffic aur security ke hisab se servers ko alag-alag group karne ke liye. AZ-a ke andar 10.0.1.0/24 subnet banana frontend ke liye.
4. Public Subnet Wo subnet jiska route table Internet Gateway (0.0.0.0/0 → igw) se juda ho. Internet-facing servers (Web, ALB, Bastion) host karne ke liye. E-commerce frontend website ka Apache/Nginx web server.
5. Private Subnet Wo subnet jiska Internet Gateway se direct koi route nahi hota. Crucial data ko hackers aur internet scanning se bachane ke liye. Amazon RDS PostgreSQL database server.
6. Availability Zone (AZ) Region ke andar isolated physical data center clusters. High Availability (HA) ke liye. Ek AZ fail ho toh doosra chal sake. Instances ko eu-north-1a aur eu-north-1b dono mein launch karna.
7. Route Table Network rules ka set jo traffic ka rasta (routing) tay karta hai. Network traffic police/GPS ka kaam karta hai. Rule: Bahar ka sara traffic 0.0.0.0/0 Internet Gateway ko bhejo.
8. Internet Gateway (IGW) VPC ko public internet se jodne wala border gateway. VPC aur public internet ke beech 2-way communication allow karta hai. Users ka browser se aapki website ko request bhejna.
9. NAT Gateway Public subnet mein lagne wali Network Address Translation service. Private instances ko internet se package/updates download karne deta hai bina inbound allow kiye. Private backend EC2 ka sudo dnf update chalana.
10. Security Group (SG) Instance/ENI level par lagne wala virtual stateful firewall. Specific port aur IP par traffic ko ALLOW karne ke liye. Web server par sirf Port 80 (HTTP) aur Port 443 (HTTPS) allow karna.
11. Network ACL (NACL) Subnet boundary level par lagne wala stateless firewall. Subnet level par explicit ALLOW aur DENY rules lagane ke liye. Kisi malicious hacker ke IP address ko direct BLOCK (DENY) karna.
12. Elastic IP (EIP) Aapke AWS account ka static, permanent public IPv4 address. Instance stop/start hone par bhi IP change nahi hota. NAT Gateway ke sath attach karke outbound internet chalana.
13. VPC Peering Do alag VPCs ke beech direct private connection. Private IPs ke through do VPCs ko aapas mein communicate karwane ke liye. Production VPC aur Analytics VPC ko privately jodna.
14. VPC Endpoint AWS services (S3/DynamoDB) ke liye private tunnel. Private EC2 bina internet ya NAT Gateway ke S3 se baat kar sake. Private backend ka backups seedhe S3 bucket mein push karna.
15. DHCP Options Set VPC ke network configuration options (DNS servers, domain name). VPC ke devices ko automatic IP aur DNS config dene ke liye. Internal domain jaise corp.mycompany.internal set karna.
16. Network Interface (ENI) Virtual network card jo EC2 instance se attach hota hai. Private IP, MAC address aur Security Group carry karta hai. EC2 par management traffic ke liye second network card lagana.
17. Default VPC AWS dwara har region mein pehle se banaya gaya ready-made VPC. Beginners bina networking setup ke turant EC2 chala sakein. Quick demo ya tutorial run karne ke liye.
18. Default Route Table VPC create hone par automatically banne wala route table. VPC ke andar local communication ensure karta hai. Subnets ke aapas mein data transfer allow karta hai.
19. Main Route Table Wo route table jo un sabhi subnets par apply hota hai jinka custom route table nahi hai. Fallback security guard ki tarah kaam karta hai. Main Route Table ko hamesha Private rakhna best practice hai.

THEORY 5. AWS REGION AUR AVAILABILITY ZONE

AWS infrastructure ka hierarchy samjhein:

AWS GLOBAL INFRASTRUCTURE │ ▼ AWS REGION (e.g., eu-north-1) (Geographic Area: Stockholm) │ ┌───────────────────────────┼───────────────────────────┐ ▼ ▼ ▼ AZ: eu-north-1a AZ: eu-north-1b AZ: eu-north-1c (Data Center Cluster 1) (Data Center Cluster 2) (Data Center Cluster 3) │ │ │ ▼ ▼ ▼ Subnet-1 (10.0.1.0/24) Subnet-2 (10.0.2.0/24) Subnet-3 (10.0.3.0/24)

Important Concepts:

  • AWS Region: Duniya ka ek geographic area (jaise Stockholm eu-north-1, Mumbai ap-south-1). Ek VPC poore Region mein spread hota hai.
  • Availability Zone (AZ): Region ke andar isolated, independent data centers. Har AZ ka alag power, cooling aur high-speed fiber connection hota hai.
  • Subnet Rule: Ek Subnet sirf aur sirf 1 Availability Zone ke andar hi rehta hai. Subnet kabhi bhi multiple AZs mein split nahi ho sakta!
High Availability (HA) Example: Agar aapke dono servers eu-north-1a mein hain aur us building mein aag lag jaati hai, toh website band ho jayegi. Lekin agar ek server eu-north-1a mein hai aur doosra eu-north-1b mein Load Balancer ke peeche, toh ek AZ band hone par bhi website 100% online rahegi!

THEORY 6. CIDR BLOCK (Classless Inter-Domain Routing)

CIDR ko bohot simple bhasha mein samjhein: Yeh IP address aur uske sath slash (/) laga kar IP ki range batane ka tareeqa hai.

Example: 10.0.0.0/16

  • IPv4 address mein total 32 bits hote hain (4 parts dots se separate: 0 to 255).
  • Slash ke baad ka number (/16) batata hai ki shuru ke kitne bits LOCKED (Fixed) hain.
  • Baqi bache bits (32 - 16 = 16 bits) aapke devices ke liye FREE hain.
  • 2^16 = 65,536 total IP addresses aapko milte hain!

AWS VPC ke Common CIDR Sizes:

CIDR Block Slash Number Total IPs Kahan Use Hota Hai?
10.0.0.0/16 /16 (16 locked bits) 65,536 IPs Poore VPC ke liye standard size
10.0.1.0/24 /24 (24 locked bits) 256 IPs (251 usable) Subnet ke liye standard size
10.0.2.0/24 /24 (24 locked bits) 256 IPs (251 usable) Subnet ke liye standard size
10.0.1.50/32 /32 (32 locked bits) Exact 1 IP Single server / Security group rule
0.0.0.0/0 /0 (0 locked bits) Duniya ke saare IPs "The entire Internet" (Default route)
🚨 AWS Subnet mein 5 Reserved IPs:

Har AWS Subnet mein AWS 5 IP addresses apne internal management ke liye reserve kar leta hai. Agar aap /24 subnet (256 IPs) banate hain, toh aapko 256 - 5 = 251 usable IPs milte hain:

  • 10.0.1.0: Network Address (Subnet identifier).
  • 10.0.1.1: VPC Local Router ke liye reserved.
  • 10.0.1.2: Amazon DNS Server ke liye reserved.
  • 10.0.1.3: AWS future use ke liye reserved.
  • 10.0.1.255: Network Broadcast (AWS broadcast support nahi karta).

THEORY 7. CIDR PRACTICAL EXAMPLE (Subnet Slicing)

VPC CIDR ko ek bada pizza samjhein, aur subnets ko uske slices!

┌─────────────────────────────────────────────────────────────────────────┐ │ VPC CIDR: 10.0.0.0/16 │ │ (Total IPs: 10.0.0.0 to 10.0.255.255) │ │ │ │ ┌───────────────────────────────┐ ┌───────────────────────────────┐ │ │ │ PUBLIC SUBNET │ │ PRIVATE SUBNET │ │ │ │ CIDR: 10.0.1.0/24 │ │ CIDR: 10.0.2.0/24 │ │ │ │ Range: 10.0.1.0 - 10.0.1.255 │ │ Range: 10.0.2.0 - 10.0.2.255 │ │ │ │ (Web Servers, ALB) │ │ (Databases, Backend APIs) │ │ │ └───────────────────────────────┘ └───────────────────────────────┘ │ │ │ │ ┌───────────────────────────────┐ ┌───────────────────────────────┐ │ │ │ SPARE SUBNET AZ-B │ │ SPARE SUBNET AZ-B │ │ │ │ CIDR: 10.0.3.0/24 │ │ CIDR: 10.0.4.0/24 │ │ │ │ Range: 10.0.3.0 - 10.0.3.255 │ │ Range: 10.0.4.0 - 10.0.4.255 │ │ │ └───────────────────────────────┘ └───────────────────────────────┘ │ └─────────────────────────────────────────────────────────────────────────┘
CRITICAL RULE: Subnet CIDR Overlap Nahi Hona Chahiye!

Agar aapne ek subnet 10.0.1.0/24 bana liya, toh doosra subnet 10.0.1.0 se shuru nahi ho sakta. Doosra subnet 10.0.2.0/24, 10.0.3.0/24 hoga. Overlap hone par router confuse ho jayega ki packet kahan bhejna hai!

THEORY 8. PUBLIC VS PRIVATE SUBNET

⚡ CRITICAL INTERVIEW POINT: Subnet ka naam "public-subnet" rakh dene se wo public nahi ban jaata! Subnet tabhi public banta hai jab uske Route Table mein Internet Gateway (0.0.0.0/0 → igw) ka route juda ho!
Feature Public Subnet Private Subnet
Internet Route Route Table mein 0.0.0.0/0 → Internet Gateway hota hai Internet Gateway ka direct koi route nahi hota
Direct Inbound from Internet ✅ Allowed (agar Security Group allow kare) ❌ Bilkul Blocked (Internet se reach nahi ho sakta)
Direct Outbound to Internet ✅ Direct Internet Gateway se ⚠️ Sirf NAT Gateway ke through (outbound only)
Public IP Instances ko Public IPv4 ya Elastic IP milti hai Instances ke paas sirf Private IP hoti hai
Kya Host Karte Hain? Load Balancer, Web Server, Bastion Host, NAT GW RDS Database, Backend API, Redis Cache

THEORY 9. INTERNET GATEWAY (IGW)

Internet Gateway (IGW) VPC level ka component hai jo aapke VPC ko public internet se jodta hai aur instances ko internet par communicate karne ke liye Network Address Translation (NAT) provide karta hai.
┌─────────────────┐ ┌─────────────────┐ ┌────────────────────────┐ ┌──────────────┐ │ User on Web │ ────► │ Internet Gateway│ ────► │ Public Route Table │ ────► │ Public EC2 │ │ (Browser Req) │ ◄──── │ (my-igw) │ ◄──── │ (0.0.0.0/0 -> igw-xxx) │ ◄──── │ (Web Server) │ └─────────────────┘ └─────────────────┘ └────────────────────────┘ └──────────────┘
  • Fully Managed: Koi server manage nahi karna padta, AWS bandwidth automatically scale karta hai.
  • 1:1 VPC Attachment: Ek VPC ke sath ek time par sirf 1 Internet Gateway attach ho sakta hai.
  • Free: Internet Gateway ka koi hourly charge nahi hota.

THEORY 10. ROUTE TABLE

"Route table rules (routes) ka collection hai jo yeh tay karta hai ki aapke subnet ka network traffic kahan jayega."

Public Route Table Example:

Destination (Kahan jana hai?) Target (Kiske through jana hai?) Explanation
10.0.0.0/16 local Local Route: VPC ke andar ka sara traffic aapas mein travel karega. (Default rule, delete nahi hota).
0.0.0.0/0 igw-0123456789abcdef0 Internet Route: Baqi duniya ka sara traffic Internet Gateway ko bhejo!

Private Route Table Example:

Destination Target Explanation
10.0.0.0/16 local VPC ke andar subnets ke beech communication.
0.0.0.0/0 nat-0123456789abcdef0 Outbound internet requests NAT Gateway ke through jayengi.

THEORY 11. NAT GATEWAY (Network Address Translation)

NAT Gateway Private Subnet ke servers ko internet se baatein karne (outbound: updates/patches download karne) deta hai, lekin internet ke kisi bhi bahari user ko private server se connect hone se rokta hai!
┌──────────────────┐ ┌──────────────────────┐ ┌────────────────────┐ ┌──────────────┐ │ Private EC2 / │ ────► │ Private Route Table │ ────► │ NAT Gateway │ ────► │ Internet │ │ Backend Server │ │ (0.0.0.0/0 -> nat-xx)│ │ (In Public Subnet) │ │ (OS Updates) │ └──────────────────┘ └──────────────────────┘ └────────────────────┘ └──────────────┘ │ Attached Elastic IP: 52.18.99.12

NAT Gateway ke 4 Rules:

  1. Hamesha PUBLIC Subnet ke andar create hota hai.
  2. Iske sath Elastic IP attach hona mandatory hai.
  3. Private Route Table mein 0.0.0.0/0 → nat-gateway-id ka route hona chahiye.
  4. Private Route table private subnet ke sath associated honi chahiye.

Internet Gateway vs NAT Gateway:

Feature Internet Gateway (IGW) NAT Gateway
Communication Two-Way (Inbound aur Outbound) One-Way (Sirf Private server se Outbound initiated)
Kahan lagta hai? VPC level par attach hota hai Public Subnet ke andar deploy hota hai
Elastic IP Nahi chahiye Mandatory hai
Cost Free Paid (~$0.045/hour + data transfer)

THEORY 12 & 13. SECURITY GROUP & NETWORK ACL (NACL)

12. Security Group (Stateful Instance Firewall)

Security Group EC2 instance level par lagne wala virtual firewall hai.

  • Stateful: Agar inbound rule ne port 80 par traffic allow kiya, toh return traffic automatically bahar chala jayega, chahe outbound rules mein kuch bhi likha ho!
  • Default Deny: By default sara incoming traffic block hota hai jab tak aap explicitly ALLOW rule na jodein.

13. Security Group vs Network ACL (Master Table):

Feature Security Group (SG) Network ACL (NACL)
Level Instance / ENI Level Subnet Level
State Stateful (Return traffic auto-allowed) Stateless (Return traffic explicitly allow karna padta hai)
Rules Sirf ALLOW rules ALLOW aur DENY dono rules
Evaluation Saare rules ek sath evaluate hote hain Number order mein (100, 200, 300) evaluate hote hain

THEORY 14, 15 & 16. ELASTIC IP, DEFAULT VPC & CUSTOM VPC

14. Elastic IP (EIP)

Elastic IP ek static public IPv4 address hota hai jo instance restart ya stop hone par bhi change nahi hota. NAT Gateway ke liye EIP zaroori hota hai.

15 & 16. Default VPC vs Custom VPC

Feature Default VPC Custom VPC
Creation AWS pehle se bana kar deta hai Aap scratch se manually banate hain
Subnets Saare subnets Public hote hain Aap tay karte hain kitne Public aur Private honge
Production Use ❌ Production ke liye recommend nahi ✅ Enterprise production standard

PRACTICAL 17 TO 23. HANDS-ON PRACTICAL: CUSTOM VPC SE APACHE WEB SERVER TAK

Step 1: Custom VPC Banayein (Practical 1)

  1. AWS Console mein VPC search karein.
  2. Orange button Create VPC par click karein.
  3. Resources to create mein VPC only select karein.
  4. Name: my-custom-vpc
  5. IPv4 CIDR block: 10.0.0.0/16
  6. Click Create VPC. Note down the VPC ID (e.g. vpc-0a1b2c3d4e5f6g7h8).

Step 2: Public aur Private Subnets Banayein (Practical 2)

  1. Sidebar mein Subnets → Create subnet par click karein.
  2. VPC select karein: my-custom-vpc.
  3. Subnet 1 (Public): Name: public-subnet-1a, AZ: eu-north-1a, CIDR: 10.0.1.0/24 → Click Create subnet.
  4. Subnet 2 (Private): Name: private-subnet-1a, AZ: eu-north-1a, CIDR: 10.0.2.0/24 → Click Create subnet.

Step 3: Internet Gateway Banayein aur Attach Karein (Practical 3)

  1. Sidebar mein Internet gateways → Create internet gateway.
  2. Name: my-igw → Click Create.
  3. Top right Actions → Attach to VPC → Select my-custom-vpc → Click Attach internet gateway.

Step 4: Public Route Table Banayein & Route Add Karein (Practical 4 & 5)

  1. Sidebar mein Route tables → Create route table.
  2. Name: public-route-table, VPC: my-custom-vpc → Click Create.
  3. Routes tab par click karein → Edit routes → Add route:
    • Destination: 0.0.0.0/0
    • Target: Internet Gateway → choose my-igw
    • Click Save changes.
  4. Subnet associations tab → Edit subnet associations → Check public-subnet-1a → Click Save associations.
  5. Subnets page par jayein → Select public-subnet-1a → Actions → Edit subnet settings → Check Enable auto-assign public IPv4 address → Click Save.

Step 5: Public Subnet mein EC2 Launch Karein (Practical 6)

  1. EC2 Console mein jayein → Launch instance.
  2. Name: my-public-web-server, OS: Amazon Linux 2023, Instance: t3.micro.
  3. Network settings mein Edit par click karein:
    • VPC: my-custom-vpc
    • Subnet: public-subnet-1a
    • Auto-assign public IP: Enable
    • Security Group: Allow Inbound SSH (Port 22) aur HTTP (Port 80 from 0.0.0.0/0).
  4. Click Launch instance.

THEORY 29 & 30. VPC PEERING & VPC ENDPOINTS

29. VPC Peering

Do alag VPCs ko AWS private network par direct connect karne ke liye VPC Peering ka use hota hai.

  • Dono VPCs ka CIDR block alag hona chahiye (No overlapping CIDRs).
  • Peering transitive nahi hoti (A to B and B to C does not mean A to C).
  • Dono VPCs ke Route Tables mein route add karna mandatory hai.

30. VPC Endpoints

Private EC2 ko internet ya NAT Gateway ke bina AWS S3 ya DynamoDB se connect karne ke liye Gateway VPC Endpoint ka use hota hai (jo bilkul FREE hota hai!).

THEORY 40 & 41. BEST PRACTICES & DEFENSE-IN-DEPTH SECURITY

  • Multi-AZ Architecture: High Availability ke liye hamesha kam se kam 2 AZs mein subnets banayein.
  • Databases in Private Subnets: Databases ko kabhi bhi direct public access na dein.
  • Least Privilege: Security Groups mein sirf wahi ports kholein jo strictly zaroori hon.
  • Use Security Group References: Hardcoded IP ke bajaye Security Group IDs ko source banayein.
  • VPC Endpoints for S3: S3 ke liye Gateway Endpoint use karein taaki NAT Gateway ka bill bache.
  • Delete Unused NAT Gateways: Practice lab complete hone ke baad NAT Gateway delete aur Elastic IP release zaroor karein.

THEORY 42 TO 44. CORE COMPARISONS

  • VPC vs Subnet: VPC poore Region mein spread hota hai (65,536 IPs), jabki Subnet sirf 1 Availability Zone ke andar rehta hai (256 IPs).
  • IGW vs NAT Gateway: IGW 2-way public communication ke liye hai (Free), NAT Gateway private servers ke outbound internet ke liye hai (Paid).
  • Security Group vs NACL: SG instance level par stateful firewall hai (ALLOW rules only), NACL subnet level par stateless firewall hai (ALLOW & DENY rules).

INTERVIEW 45. TOP 30+ AWS VPC INTERVIEW QUESTIONS & ANSWERS

Q1. AWS VPC kya hai?

AWS account ke andar logically isolated virtual private network jahan hum apne EC2, RDS aur Load Balancers securely launch aur control karte hain.

Q2. CIDR kya hota hai?

Classless Inter-Domain Routing. IP address range ko define karne ka standardized format (e.g. 10.0.0.0/16).

Q3. Subnet kya hai?

VPC CIDR ka ek chhota hissa jo single Availability Zone ke andar rehta hai resources ko segment karne ke liye.

Q4. Har Subnet mein kitne IPs AWS reserve karta hai?

Exactly 5 IP addresses (First 4 and Last 1: network, router, DNS, future use, broadcast).

Q5. Subnet ko Public kya cheez banati hai?

Route Table mein 0.0.0.0/0 → Internet Gateway ka route aur instances ko public IP milna. Sirf naam "public" rakhne se subnet public nahi banta.

Q6. Private Subnet kya hota hai?

Wo subnet jiska Internet Gateway se direct koi route nahi hota, taaki bahar ka koi bhi user use access na kar sake.

Q7. Internet Gateway (IGW) kya hai?

VPC level ka managed gateway jo public subnets ko 2-way internet connectivity deta hai.

Q8. Ek VPC mein kitne Internet Gateways attach ho sakte hain?

Exactly ONE (1) Internet Gateway at a time.

Q9. NAT Gateway kya kaam karta hai?

Private subnet ke instances ko outbound internet updates download karne deta hai bina unhe inbound internet par expose kiye.

Q10. NAT Gateway kahan deploy hota hai?

Hamesha Public Subnet ke andar with an Elastic IP.

Q11. Route Table kya hota hai?

Rules ka set jo VPC ke andar network traffic ko uski destination tak direct karta hai.

Q12. Security Group stateful kyun hai?

Kyunki agar incoming traffic allow hai, toh uska return response automatically allow ho jata hai bina outbound rule check kiye.

Q13. Network ACL kya hai?

Subnet boundary level par lagne wala stateless firewall jisme ALLOW aur DENY dono rules number order mein evaluate hote hain.

Q14. Security Group aur NACL mein main difference kya hai?

SG instance level par stateful hai (sirf allow rules). NACL subnet level par stateless hai (allow + deny rules).

Q15. Elastic IP kya hai?

Aapke AWS account ka persistent, static public IPv4 address jo instance stop hone par bhi change nahi hota.

Q16. VPC Peering kya hai?

Do alag VPCs ke beech direct private network connection jo bina internet ke traffic route karta hai.

Q17. Kya VPC Peering transitive hoti hai?

Nahi. Agar A peered hai B se aur B peered hai C se, toh A seedhe C se baat nahi kar sakta.

Q18. VPC Endpoint kya hota hai?

Private EC2 ko internet ya NAT ke bina AWS services (jaise S3/DynamoDB) se privately connect karne ka rasta.

Q19. VPC Flow Logs kya capture karta hai?

VPC network interfaces par aane aur jaane wale IP traffic ka metadata (source, destination, port, accept/reject).

Q20. ENI (Elastic Network Interface) kya hai?

Virtual network card jo EC2 instance par private IP, MAC address aur Security Group carry karta hai.

Q21. Databases ko private subnet mein kyun rakhna chahiye?

Data security ke liye, taaki koi bhi unauthorized internet user ya automated bot database par direct attack na kar sake.

Q22. Kya ek Subnet do Availability Zones mein spread ho sakta hai?

Nahi, ek subnet strictly sirf 1 Availability Zone ke andar rehta hai.

Q23. Security Group chaining kya hoti hai?

Security Group rule ke source mein IP ke bajaye doosre Security Group ka ID daalna (e.g. Database sirf Backend SG ko allow kare).

Q24. Default VPC kya hota hai?

AWS dwara har region mein pehle se banaya gaya ready-to-use VPC jisme saare subnets public hote hain.

Q25. Main Route Table kya hai?

Wo fallback route table jo automatically un subnets par apply hota hai jinke sath koi custom route table explicitly judhi nahi hoti.

Q26. Private EC2 ko internet se updates kaise milte hain?

Public subnet mein lage NAT Gateway ke through.

Q27. CIDR overlap hone se kya dikkat aati hai?

Router confuse ho jata hai aur IP routing fail ho jaati hai, VPC Peering bhi possible nahi hoti.

Q28. 3-tier VPC architecture kya hoti hai?

Tier 1: Public Subnet with Load Balancer; Tier 2: Private Subnet with Backend APIs; Tier 3: Isolated Database Subnet.

Q29. Agar EC2 ka public web page nahi khul raha toh sabse pehle kya check karenge?

1) Security Group Port 80, 2) Route Table 0.0.0.0/0 → IGW, 3) IGW Attached status, 4) EC2 Public IP.

Q30. Gateway Endpoint aur Interface Endpoint mein kya farak hai?

Gateway Endpoint FREE hota hai (S3 & DynamoDB ke liye). Interface Endpoint PrivateLink aur ENI use karta hai (Paid hourly).
