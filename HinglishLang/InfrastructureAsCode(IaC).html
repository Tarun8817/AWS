Level 11: AWS CloudFormation (IaC) — Hinglish
AWS CLOUDFORMATION • HINGLISH GUIDE

Infrastructure as Code (IaC) Complete Guide

Code (YAML/JSON) ke zariye AWS Infrastructure ko Create, Deploy, Update aur Manage karein

⚠️ Cost Warning: Is guide ke practical labs real AWS resources (EC2, S3, RDS wagera) create karte hain. Kaam khatam hone par stack ko delete zaroor karein taaki faltu bills na banein.

1. Introduction (परिचय)

Theory
Aasan Bhasha Mein Definition: AWS CloudFormation ek aisi AWS service hai jisme humein console par baith kar bar-bar mouse click karke server, database ya bucket nahi banana padta. Hum ek text file (YAML ya JSON) mein apna pura infrastructure likh dete hain aur CloudFormation us file ko padhkar sabhi resources automatic create kar deta hai.
TermAasan Matlab (Hinglish)
AWSAmazon Web Services — cloud provider jo compute (EC2), storage (S3), database (RDS) jaisi services deta hai.
CloudFormationAWS ki ek free orchestration service jo template file padhkar aapka setup deploy karti hai.
InfrastructureAapki app ko chalane ke liye jo hardware/network resources chahiye (Servers, Storages, VPC, DB).
IaC (Infrastructure as Code)Infrastructure ko manually click karne ke bajaye text file (code) mein likhkar manage karna.
TemplateWoh YAML ya JSON file jisme likha hota hai ki kaunse resources banaye jayein.
StackTemplate se bana hua complete deployed group — CloudFormation is pure group ko ek single unit ki tarah manage karta hai.
ResourceEk single AWS item jo template banata hai, jaise ek S3 bucket ya ek EC2 virtual server.

Manual Resource Creation Ki Problem

Agar CloudFormation na ho, to ek developer ko manually AWS Console kholkar ek-ek karke click karna padega: pehle VPC banao, fir Subnet, fir Security Group, fir EC2, fir RDS, fir IAM Role... Isme bohot zyada time lagta hai, human errors (galtiyan) hone ke chances rehte hain, aur har baar same setup repeat karna mushkil hota hai.

Without CloudFormation (Manual Clicks): Developer manually banata hai: EC2 -> Security Group -> S3 -> RDS -> IAM Role -> Load Balancer (Slow & Risky) With CloudFormation (IaC): CloudFormation Template (YAML File) | v CloudFormation Stack | v AWS Resources (Sabhi resources automatically aur perfect order mein create hote hain)

2. What is Infrastructure as Code (IaC)?

Theory
Traditional Manual ApproachIaC (Code) Approach
AWS Console login karo ➔ haath se har setting click karke select karo.Ek YAML template likho ➔ AWS CloudFormation ko do ➔ Auto infrastructure create ho jayega.

IaC Ke Fayde (Advantages)

  • Automation: Bina human intervention ke pura data center spin-up ho jata hai.
  • Repeatability: Ek hi template se aap 100 baar exactly same infrastructure bana sakte hain.
  • Version Control: Template ko GitHub/GitLab par save karein, commit history dekhein ki kisne kya change kiya.
  • Consistency: Dev, Staging aur Prod environments bilkul same architecture par chalte hain.
  • Fast Rollback: Agar koi resource fail ho jaye, to CloudFormation automatically changes rollback kar deta hai.
  • Zero Human Error: Koi checkbox ya wrong IP dalne ki galti nahi hoti.
Real-world Example Company ko testing ke liye ek naya Staging environment banana hai. Manual tarike se 2 din lagenge. IaC ke sath bas Environment: staging parameter pass karke 10 minute mein pura setup ready ho jata hai!

3. CloudFormation Architecture

Theory
CloudFormation Template (.yaml / .json) | v CloudFormation Engine / Stack | v +-----------------------------------------+ | EC2 | S3 | RDS | IAM | VPC | +-----------------------------------------+
  • Template: Aapki code blueprint file.
  • Stack: CloudFormation is template ko lekar ek Stack create karta hai. Pure stack ko ek sath update ya delete kiya ja sakta hai.
  • Resources: Actual live AWS services jo run ho rahi hain.

4. Important CloudFormation Terms

Theory

1. Template

Aapki declarative blueprint file (YAML/JSON). Isme likha hota hai ki kya banana hai.

2. Stack

Template ka live deployed instance. Jab aap stack delete karte hain, to uske andar ke sabhi resources ek sath delete ho jate hain.

3. Resource

Individual AWS building block (e.g. AWS::EC2::Instance, AWS::S3::Bucket).

4. Parameter

Deployment time par user se input lene ka tarika (e.g. InstanceType: t3.micro ya t3.large).

5. Mapping

Template ke andar ek fixed lookup table (jaise Region ke basis par sahi AMI ID find karna).

6. Condition

If/Else logic — jaise agar Environment = prod ho tabhi bada database banao.

7. Output

Deployment ke baad zaroori information display karna (jaise Website ka Public IP ya S3 Bucket URL).

8. Intrinsic Functions

CloudFormation ke built-in functions jaise !Ref, !GetAtt, !Sub.

9. Change Set

Live stack update karne se pehle ek preview dekhna ki kya-kya modify ya replace hoga.

10. Drift Detection

Yeh check karna ki kya kisi ne template ke bahar console se manually kuch modify to nahi kar diya.

11. DeletionPolicy

Stack delete hote waqt critical resources (jaise DB ya S3) ko bachaane ke liye rule (Retain ya Snapshot).

12. Nested Stack

Ek bade template ko chhote-chhote child stacks (Network Stack, DB Stack, App Stack) mein tod kar manage karna.

13. StackSet

Ek hi template ko multiple AWS accounts aur multiple regions mein centrally deploy karna.

Theory

6. YAML Basics for CloudFormation

Theory

CloudFormation mein JSON bhi use ho sakta hai, lekin YAML zyada clean aur padhne mein aasan hota hai.

ConceptYAML RuleExample
IndentationSpaces use karein (Tab key kabhi use na karein!). Usually 2 spaces.Nested elements aage shift hote hain.
Key / ValueKey ke baad colon aur ek space zaroori hai.Type: AWS::S3::Bucket
Lists / ArraysDash (-) aur space se shuru hoti hai.- tcp
CommentsHash (#) se shuru hoti hai.# Yeh comment hai
Common YAML Mistake: Agar aapne Type:AWS::S3::Bucket likh diya (colon ke baad space nahi diya), to template fail ho jayega. Hamesha Type: AWS::S3::Bucket likhein!

7. CloudFormation Resource Anatomy

Theory
yaml
Resources:
  MyWebServer:                      # 1. Logical ID (Template ke andar ka naam)
    Type: AWS::EC2::Instance        # 2. Resource Type (AWS ko batata hai kya banana hai)
    Properties:                     # 3. Settings aur configurations
      InstanceType: t3.micro
      ImageId: ami-0c55b159cbfafe1f0
  • Logical ID (MyWebServer): Yeh naam sirf template ke andar doosre resources ko reference karne ke kaam aata hai.
  • Type (AWS::EC2::Instance): Service identifier. Formatted as AWS::Service::ResourceType.
  • Properties: Resource ki specific settings (disk size, instance type, AMI, ports).

9. Practical Lab 2 — Create EC2 Instance Using Parameters

Practical

Parameters ka use karke dynamic EC2 virtual machine create karein.

yaml (ec2-instance.yaml)
AWSTemplateFormatVersion: '2010-09-09'
Description: Lab 2 - EC2 Instance with Dynamic Parameters

Parameters:
  InstanceType:
    Type: String
    Default: t3.micro
    AllowedValues:
      - t3.micro
      - t3.small
      - t2.micro
    Description: EC2 instance ka size chunein

  KeyName:
    Type: AWS::EC2::KeyPair::KeyName
    Description: SSH karne ke liye existing Key Pair chunein

  AMIId:
    Type: AWS::EC2::Image::Id
    Description: Apne region ka Amazon Linux AMI ID dalein

Resources:
  MyEC2Instance:
    Type: AWS::EC2::Instance
    Properties:
      ImageId: !Ref AMIId
      InstanceType: !Ref InstanceType
      KeyName: !Ref KeyName
      Tags:
        - Key: Name
          Value: CloudFormation-EC2

Outputs:
  InstanceId:
    Value: !Ref MyEC2Instance
  PublicIP:
    Value: !GetAtt MyEC2Instance.PublicIp
Important Note on AMI ID: AMI ID har AWS Region mein alag hoti hai (e.g. eu-north-1 vs ap-south-1). Isliye AMI ID ko hardcode karne ke bajaye Parameter banana sabse best practice hai!

11. Practical Lab 4 — Auto Deploy Apache Web Server (UserData)

Practical

Server boot hote hi Apache web server automatic install aur start ho jaye, iske liye UserData script use hoti hai.

yaml
MyWebServerEC2:
  Type: AWS::EC2::Instance
  Properties:
    ImageId: !Ref AMIId
    InstanceType: !Ref InstanceType
    KeyName: !Ref KeyName
    SecurityGroupIds:
      - !Ref WebSecurityGroup
    UserData:
      Fn::Base64: !Sub |
        #!/bin/bash
        dnf update -y
        dnf install -y httpd
        systemctl start httpd
        systemctl enable httpd
        echo "<h1>Hello from AWS CloudFormation! 🚀</h1>" > /var/www/html/index.html

Stack deploy hone ke baad browser mein http://<EC2_PUBLIC_IP> open karke live website test karein!

14–16. Intrinsic Functions: !Ref, !GetAtt, !Sub

Theory

14. !Ref Function

Resource ki main ID ya Parameter ki value lene ke liye use hota hai.

  • EC2 par !Ref MyEC2 ➔ Instance ID deta hai (e.g. i-0123456789abcdef0).
  • S3 par !Ref MyBucket ➔ Bucket Name deta hai.

15. !GetAtt (Get Attribute)

Resource ki specific property (jo !Ref se nahi milti) nikalne ke liye use hota hai.

  • !GetAtt MyEC2.PublicIp ➔ Server ka Public IP address deta hai.
  • !GetAtt MyRDS.Endpoint.Address ➔ Database ka host URL deta hai.

16. !Sub (String Substitution)

String ke andar dynamic variables replace karne ke liye ${VariableName} syntax use hota hai.

yaml
Value: !Sub "http://${MyEC2.PublicIp}:8080/api"

17. Outputs Section

Theory

Deployment ke baad zaroori values ko CloudFormation Console ke Outputs tab mein display karne ke liye use hota hai.

yaml
Outputs:
  ServerPublicIP:
    Description: Web Server Public IP
    Value: !GetAtt MyEC2.PublicIp
  WebsiteURL:
    Description: Direct link to open in browser
    Value: !Sub "http://${MyEC2.PublicIp}"

18. DependsOn Attribute

Theory

Jab CloudFormation automatic dependency detect na kar sake (e.g. EC2 ko chalne se pehle S3 bucket zaroor ready chahiye), tab explicit dependency specify karne ke liye DependsOn use karte hain.

yaml
MyEC2:
  Type: AWS::EC2::Instance
  DependsOn: MyS3Bucket

19. Conditions

Theory

Conditions ke zariye hum if-else logic lagate hain ki resource create hona chahiye ya nahi.

yaml
Conditions:
  IsProduction: !Equals [ !Ref Environment, "prod" ]

Resources:
  ProductionBackupBucket:
    Type: AWS::S3::Bucket
    Condition: IsProduction  # Sirf prod environment mein hi create hoga!

20. Mappings

Theory

Static lookup tables (jaise Region ke anusar AMI ID select karna):

yaml
Mappings:
  RegionMap:
    eu-north-1:
      AMI: ami-0abcdef1234567890
    ap-south-1:
      AMI: ami-0987654321fedcba0

Resources:
  MyEC2:
    Type: AWS::EC2::Instance
    Properties:
      ImageId: !FindInMap [ RegionMap, !Ref "AWS::Region", AMI ]

23. Stack Rollback Mechanism

Theory

Agar deployment ke dauran koi bhi resource fail hota hai, to CloudFormation automatically sabhi changes ko revert (undo) karke stack ko pehle wali safe state par le aata hai.

Troubleshooting CREATE_FAILED / ROLLBACK_COMPLETE: Hamesha Events tab mein sabse pehla CREATE_FAILED event dekhein aur uska Status Reason padhein (e.g. IAM permission error ya invalid subnet).

26. Drift Detection

Theory

Agar kisi engineer ne template ke peeche se AWS Console par jakar Security Group ya EC2 ka size manually change kar diya, to template aur actual setup mein antar aa jata hai. Is antar ko Drift kehte hain.

Stack Actions ➔ Detect Drift par click karke aap dekh sakte hain ki actual infrastructure template se kitna alag ho chuka hai.

35. Common Errors & Fixes

Important

1. YAML Indentation Error

Reason: Tabs use kar liye ya spacing aage-peeche ho gayi. Fix: Sirf 2-spaces use karein, tab key na dabayein.

2. Invalid AMI ID / AMI Not Found

Reason: Region galat hai ya AMI ID mein typo hai. Fix: Current region ke EC2 launch wizard se taaza AMI ID copy karein.

3. S3 BucketAlreadyExists

Reason: S3 bucket name puri duniya mein globally unique hona chahiye. Fix: Bucket name badlein ya BucketName property hata dein taaki AWS auto-generate kare.

4. IAM Capability Missing

Reason: Template IAM Roles bana raha hai lekin user ne acknowledge nahi kiya. Fix: Console par "I acknowledge that AWS CloudFormation might create IAM resources" checkbox check karein.

36. CloudFormation Best Practices

Important
  • Hamesha Parameters use karein taaki template Dev/Test/Prod mein reuse ho sake.
  • Critical databases ke liye DeletionPolicy: Retain ya Snapshot zaroor lagayein.
  • Secrets aur passwords ke liye NoEcho: true lagayein ya AWS Secrets Manager use karein.
  • Production update se pehle Change Set generate karke impact review karein.
  • Code ko GitHub mein version control karein aur pull request review ke baad deploy karein.

39. Top 25 Interview Questions & Answers

Interview
Q1. AWS CloudFormation kya hai?
AWS ki native IaC (Infrastructure as Code) service jo YAML/JSON templates se resources create aur manage karti hai.
Q2. IaC ke main fayde kya hain?
Automation, consistency, human error reduction, version control, aur fast repeatability.
Q3. Template aur Stack mein kya antar hai?
Template code blueprint file hai, jabki Stack us template ka deployed live group hai.
Q4. Template ke mandatory sections kaunse hain?
Sirf Resources section mandatory hai, baaki sab optional hain.
Q5. !Ref function kya return karta hai?
Resource ki primary identifier (e.g. Instance ID ya Bucket Name) ya Parameter ki value.
Q6. !GetAtt function kab use karte hain?
Jab resource ka specific attribute chahiye ho jo !Ref se na mile (e.g. EC2 Public IP ya RDS Endpoint).
Q7. !Sub function ka use kya hai?
String ke andar ${Variable} placeholders ko dynamic values se replace karna.
Q8. DependsOn ka use kab hota hai?
Jab do resources ke beech aisi dependency ho jo CloudFormation automatically !Ref se detect na kar sake.
Q9. Change Set kya hota hai?
Live stack update karne se pehle modifications aur resource replacements ka preview dekhna.
Q10. Drift Detection kya kaam karta hai?
Manual console changes aur template ke beech ka difference detect karta hai.
Q11. DeletionPolicy ke kaunse options hain?
Delete (default), Retain (keep resource), aur Snapshot (backup before delete).
Q12. Nested Stacks kya hote hain?
Ek main stack ke andar doosre child stacks ko modular resources ki tarah include karna.
Q13. StackSets ka fayda kya hai?
Ek hi template ko multiple AWS accounts aur regions mein ek sath deploy karna.
Q14. Agar stack creation fail ho jaye to kya hota hai?
CloudFormation rollback karta hai aur status ROLLBACK_COMPLETE ho jata hai.
Q15. CloudFormation vs Terraform main difference?
CloudFormation AWS-native hai bina state file ke; Terraform open-source aur multi-cloud hai with .tfstate file.
Q16. Password ko template mein safe kaise rakhein?
Parameter mein NoEcho: true lagayein ya AWS Secrets Manager / SSM Parameter Store se fetch karein.
Q17. UserData kya hota hai?
EC2 instance ke first boot par chalne wali shell script jo software install aur configure karti hai.
Q18. Mappings section kab use karte hain?
Region-specific static lookup values (jaise AMIs) store karne ke liye.
Q19. Stack Policy kya hai?
Ek JSON policy jo critical resources ko accidental update ya replacement se protect karti hai.
Q20. Outputs section ka use kya hai?
Stack banne ke baad IP, URLs aur Resource IDs ko Console/CLI par display karna ya doosre stacks ko export karna.
