1️⃣ Basic AWS Terms

Scalability

Scalability means the ability of a system to handle increasing workload, traffic, or users by increasing available resources.

Simple example: Socho tumhare paas ek website hai jisme 100 users aate hain — server easily handle kar leta hai. Ab agar 10,000 users aane lagein, to server ko zyada resources chahiye honge taaki wo bina slow hue us load ko handle kar sake. Yehi ability scalability kehlati hai.

Vertical Scalability — Scaling Up

Isme hum:

  • CPU increase karte hain
  • RAM increase karte hain
  • Ek bada EC2 instance use karte hain
t2.micro ↓ m5.large

Yaha existing server hi zyada powerful ban jaata hai — same server, bas bigger.

Limitations:
  • Hardware ki ek upper limit hoti hai — infinite scale up nahi kar sakte.
  • Change karte waqt server ko stop/restart karna pad sakta hai.
  • Ek hi server rehta hai, isliye ye ab bhi single point of failure ban sakta hai.

Horizontal Scalability — Scaling Out

Isme hum:

  • Zyada EC2 instances add karte hain
  • Workload ko multiple servers ke beech distribute karte hain
  • Generally ye Load Balancer ke saath use hota hai
Load Balancer ↓ ┌──────────┼──────────┐ ↓ ↓ ↓ EC2-1 EC2-2 EC2-3

Scaling Up vs Scaling Out: Scaling Up mein ek hi server ko bada banaya jaata hai; Scaling Out mein multiple servers add kiye jaate hain jo mil kar load share karte hain. Horizontal scaling generally better reliability deta hai kyunki ek server fail hone par baaki servers kaam karte rehte hain.

🛡️ High Availability (HA)

High Availability means designing an application so that it remains accessible with minimal downtime even when some infrastructure components fail.
  • Multiple EC2 instances — ek server pe depend nahi karna.
  • Multiple Availability Zones — alag-alag physical locations mein servers rakhna.
  • Load Balancer — traffic ko healthy servers tak route karna.
  • Auto Scaling — failed instances ko automatically replace karna.
  • Health checks — regularly check karna ki server sahi se kaam kar raha hai ya nahi.
Load Balancer ↓ ┌─────────┴─────────┐ ↓ ↓ AZ-1 AZ-2 EC2 EC2

Multiple Availability Zones use karne se availability improve hoti hai kyunki agar ek AZ mein koi issue (power, network, hardware) aa jaaye, to doosre AZ ka server phir bhi traffic serve karta rehta hai.

⚠️ Important

High Availability ≠ 100% uptime. HA ka matlab hai downtime ko minimize karna, lekin ye guarantee nahi karta ki system kabhi bhi fail nahi hoga.

🌊 Elasticity

Elasticity means automatically increasing or decreasing resources according to demand.
High Traffic ↓ More EC2 Instances ↓ Traffic decreases ↓ Fewer EC2 Instances

ASG configured policies ke through automatic scaling provide karta hai — jaise hi demand badhti hai, naye instances launch hote hain, aur jaise hi demand kam hoti hai, extra instances automatically remove ho jaate hain.

Scalability vs Elasticity vs High Availability

ConceptFocus
ScalabilitySystem ki capability ki wo badhte workload ko handle kar sake (resources add karke)
ElasticityDemand ke hisaab se resources ka automatically badhna/ghatna
High AvailabilityComponent fail hone par bhi application ko accessible rakhna

⚖️ What is ELB?

ELB = Elastic Load Balancing

ELB ek AWS service hai jo incoming traffic ko multiple targets (jaise EC2 instances) ke beech distribute karti hai, taaki koi ek server overload na ho aur application zyada reliable rahe.

Ek Load Balancer:

  • Incoming traffic receive karta hai
  • Requests ko healthy targets ke beech distribute karta hai
  • Health checks perform karta hai
  • Availability improve karne mein help karta hai
  • Multiple Availability Zones ke across kaam kar sakta hai

Problem without a Load Balancer:

Users ↓ Single EC2 ↓ Application

Agar ye EC2 fail ho jaaye, to users application access nahi kar payenge.

With ELB:

Users ↓ Load Balancer ↓ ┌──────────┼──────────┐ ↓ ↓ ↓ EC2-1 EC2-2 EC2-3

🏷️ Types of AWS Load Balancers

Application Load Balancer (ALB)

  • Layer 7 pe operate karta hai
  • HTTP/HTTPS traffic ke liye
  • Host-based routing support karta hai
  • Path-based routing support karta hai
  • Best for: Web applications, REST APIs, Microservices
example.com/users ↓ ALB ↓ User Service
example.com/products ↓ ALB ↓ Product Service

Network Load Balancer (NLB)

  • Layer 4 pe operate karta hai
  • TCP support
  • UDP support
  • TLS support
  • Very high performance, low latency
  • Network-level traffic ke liye suitable

Gateway Load Balancer (GWLB)

  • Network/security appliances ke liye use hota hai
  • Traffic inspection
  • Firewalls
  • Security appliances

Classic Load Balancer ek legacy option hai — modern architectures generally requirement ke hisaab se ALB ya NLB use karte hain.

FeatureALBNLBGWLB
Layer743/4-oriented appliance integration
Main trafficHTTP/HTTPSTCP/UDP/TLSNetwork/security appliance traffic
RoutingContent-basedConnection/network-levelAppliance-oriented
Common useWeb apps/APIHigh-performance network trafficFirewalls/security appliances

🧩 Important ELB Components

Load Balancer

Entry point jo client requests ko receive karta hai.

Listener

Incoming connection requests ko check karta hai.

Example: HTTP : 80, HTTPS : 443

Target Group

Targets ka ek group jo traffic receive karta hai.

Targets mein EC2 instances shamil ho sakte hain.

Health checks target group level pe configure kiye jaate hain.

Targets

Examples: EC2 instances, IP addresses, containers (depending on load balancer type/configuration).

Health Checks

Load Balancer check karta hai ki targets healthy hain ya nahi, traffic bhejne se pehle.

ALB ↓ Health Check ↓ EC2-1 → Healthy EC2-2 → Healthy EC2-3 → Unhealthy

Traffic sirf healthy targets ko hi route hona chahiye.

📈 What is ASG?

ASG = Auto Scaling Group

Ek Auto Scaling Group automatically EC2 instances ki number manage karta hai, configured minimum, desired, aur maximum capacity ke according.

  • Minimum capacity — kam se kam kitne instances hamesha chahiye
  • Desired capacity — normally kitne instances rakhne hain
  • Maximum capacity — zyada se zyada kitne instances allowed hain
Minimum = 2 Desired = 2 Maximum = 5

High traffic ke dauraan:

2 EC2 ↓ 3 EC2 ↓ 4 EC2 ↓ 5 EC2

Low traffic ke dauraan:

5 EC2 ↓ 4 EC2 ↓ 3 EC2 ↓ 2 EC2

ASG in cheezon mein help karta hai:

  • Scalability
  • Elasticity
  • High availability
  • Automatic instance replacement

📋 ASG Launch Template

ASG ke saath generally ek Launch Template use kiya jaata hai kyunki ye batata hai ki naya EC2 instance exactly kaise launch hona chahiye.

Launch Template define kar sakta hai:

  • AMI
  • Instance type
  • Key pair
  • Security group
  • IAM role
  • Network configuration
  • Storage
  • User Data
AMI ↓ Launch Template ↓ Auto Scaling Group ↓ EC2 Instances
ComponentRole
AMIServer ka base image (OS + software)
Launch TemplateAMI + launch settings (instance type, key pair, SG, user data, etc.)
ASGLaunch Template use karke instances ki quantity manage karta hai

🔗 ELB + ASG Relationship

ELB distributes traffic.

ASG manages the number of EC2 instances.

Users ↓ Application Load Balancer ↓ Target Group ↓ ┌───────────┼───────────┐ ↓ ↓ ↓ EC2-1 EC2-2 EC2-3 ↑ ↑ ↑ └───────────┼───────────┘ ↑ ASG ↑ Launch Template ↑ AMI
  • Users — application ko access karne wale log
  • Application Load Balancer — traffic receive karke distribute karta hai
  • Target Group — targets ko group karta hai aur health check rakhta hai
  • EC2 instances — actual traffic process karte hain
  • ASG — instances ki quantity manage karta hai
  • Launch Template — batata hai instances kaise launch hon
  • AMI — server ka base image provide karta hai

🏗️ Complete Real-World Example

Socho humare paas Apache pe chal rahi ek website hai.

Initially:

Users ↓ EC2 Instance

Traffic increase hoti hai.

Problem:
  • Single EC2 overloaded ho jaata hai.
  • Agar instance fail ho jaaye, website unavailable ho jaati hai.

Solution:

Users ↓ ALB ↓ ┌────────┴────────┐ ↓ ↓ EC2-1 EC2-2 ↑ ↑ └────── ASG ──────┘

Agar traffic badhti hai:

EC2-1 + EC2-2 ↓ ASG launches EC2-3 ↓ ALB sends traffic to EC2-1, EC2-2, EC2-3

Agar traffic kam hoti hai:

EC2-1 + EC2-2 + EC2-3 ↓ ASG scales in ↓ EC2-1 + EC2-2

📜 EC2 Apache Server User Data Script

#!/bin/bash

# Update packages
sudo yum update -y

# Install Apache
sudo yum install -y httpd

# Start Apache
sudo systemctl start httpd

# Enable Apache at boot
sudo systemctl enable httpd

# Create simple HTML page
cat <<EOF > /var/www/html/index.html
<html>
<head>
    <title>Apache Web Server</title>
</head>
<body>
    <h1>Welcome to Apache Web Server on Amazon Linux</h1>
    <h2>Hostname: $(hostname)</h2>
</body>
</html>
EOF

#!/bin/bash — batata hai ki ye script Bash shell mein run hogi.

# Update packages aur sudo yum update -y — sabhi installed packages ko latest version tak update karta hai; -y confirmation prompts ko automatically "yes" kar deta hai.

sudo yum install -y httpd — Apache web server (httpd) install karta hai.

sudo systemctl start httpd — Apache service ko turant start karta hai.

sudo systemctl enable httpd — Apache ko har reboot pe automatically start hone ke liye set karta hai.

cat <<EOF > /var/www/html/index.html ... EOF — ek "heredoc" hai jo EOF ke beech ki saari lines seedha index.html file mein likh deta hai.

$(hostname) — server ka current hostname dynamically fetch karke page mein print karta hai.

Common Mistakes to Avoid

Galat:

httpdsudo

Sahi (do alag commands, alag lines pe):

httpd
sudo

Galat:

systemctl start httpd|

Sahi (extra | pipe character nahi hona chahiye):

systemctl start httpd

Dynamic hostname isliye useful hai kyunki jab multiple EC2 instances ek ALB ke peeche chal rahe hote hain, to browser refresh karne pe alag-alag hostname dikhna ye confirm karta hai ki request alag-alag instances tak pahunch rahi hai — testing ke liye ye ek simple aur effective tareeka hai.

🛠️ Create Launch Template

  1. AWS Console open karo.
  2. EC2 pe jao.
  3. Launch Templates select karo.
  4. Create launch template click karo.
  5. Launch Template ka name enter karo.
  6. AMI select karo.
  7. Instance type select karo.
  8. Zaroorat ho to key pair select karo.
  9. Security group configure karo.
  10. Storage configure karo.
  11. User Data add karo.
  12. Configuration review karo.
  13. Create Launch Template click karo.

Launch Template mein sahi AMI, sahi Security Group, aur sahi User Data hona zaroori hai — kyunki ASG isi template ke basis pe naye instances launch karega. Agar template mein galat setting ho, to har naya instance bhi usi galti ke saath launch hoga.

  4. Target type select karo.
  5. Protocol aur port select karo.
  6. VPC select karo.
  7. Health check configure karo.
  8. Create target group click karo.

Protocol: HTTP Port: 80 Health Check Path: /

/ ka matlab hai — health check root URL (http://instance-ip/) pe request bhejega, aur agar Apache waha se koi valid response (jaise 200 OK) deta hai, to us instance ko healthy maana jaayega.

  1. EC2 open karo.
  2. Load Balancers pe jao.
  3. Create Load Balancer click karo.
  4. Application Load Balancer select karo.
  5. Load Balancer ka name enter karo.
  6. Agar public website bana rahe ho to Internet-facing choose karo.
  7. IPv4 select karo.
  8. VPC select karo.
  9. Jahan applicable ho, kam se kam do Availability Zones/subnets select karo.
  10. Security group configure karo.
  11. Listener configure karo.
  12. Target group select karo.
  13. Sab kuch review karo.
  14. Create Load Balancer click karo.
  • Internet-facing ALB — public internet se accessible hota hai; internal use ke liye "internal" bhi choose kiya ja sakta hai.
  • Security Group — decide karta hai ALB pe kaunsa traffic (ports) allow hoga.
  • Listener — check karta hai kaunse port (jaise 80/443) pe requests aa rahi hain.
  • Target Group — batata hai traffic kis group ke EC2 instances ko bheja jaaye.
  • Availability Zones — multiple AZs select karne se high availability milti hai.

🔒 Security Groups

Internet ↓ ALB Security Group ↓ EC2 Security Group

ALB Security Group

Allow karo:

HTTP 80 HTTPS 443

Appropriate client sources se.

EC2 Security Group

HTTP traffic ko ALB security group se allow karo, poore internet se broadly allow karne ke bajaye jahan possible ho. Ye zyada secure isliye hai kyunki EC2 instances direct internet traffic accept nahi karte — sirf ALB ke through hi traffic aata hai, jisse attack surface kam ho jaata hai.

🎯 Important Interview Questions

Q1: What is ELB?

A: Elastic Load Balancing — traffic ko multiple targets ke beech distribute karne wali AWS service.

Q2: What is ASG?

A: Auto Scaling Group — jo configured min/desired/max capacity ke according EC2 instances manage karta hai.

Q3: What is scalability?

A: System ki ability jo badhte workload/traffic ko resources badha kar handle kare.

Q4: What is vertical scaling?

A: Existing server ko bigger instance type mein upgrade karna.

Q5: What is horizontal scaling?

A: Load share karne ke liye zyada servers add karna.

Q6: What is elasticity?

A: Demand ke hisaab se resources ka automatically increase/decrease hona.

Q7: What is high availability?

A: Kuch components fail hone par bhi application ko minimal downtime ke saath accessible rakhna.

Q8: Difference between scalability and elasticity?

A: Scalability capability hai badhte load ko handle karne ki; elasticity us process ko automatic banati hai.

Q9: What is ALB?

A: Application Load Balancer — Layer 7 pe HTTP/HTTPS traffic handle karta hai, content-based routing ke saath.

Q10: What is NLB?

A: Network Load Balancer — Layer 4 pe high-performance TCP/UDP/TLS traffic handle karta hai.

Q11: What is a Target Group?

A: Targets (jaise EC2 instances) ka group jinhe traffic milta hai aur jinke health checks configured hote hain.

Q12: What is a Listener?

A: Load Balancer ka wo part jo specific port (jaise 80/443) pe incoming connections check karta hai.

Q13: What is an ELB health check?

A: Ek periodic check jo verify karta hai ki target traffic handle karne ke liye healthy hai ya nahi.

Q14: What happens when an EC2 target becomes unhealthy?

A: Load Balancer us target ko traffic bhejna band kar deta hai jab tak wo healthy na ho jaaye.

Q15: What is an Auto Scaling Group?

A: Ek AWS resource jo min/desired/max capacity ke according EC2 instances ki count automatically manage karta hai.

Q16: What are minimum, desired, and maximum capacities?

A: Minimum = kam se kam instances; Desired = normal target count; Maximum = zyada se zyada allowed instances.

Q17: What is a Launch Template?

A: Ek saved configuration (AMI, instance type, key pair, SG, user data, etc.) jo naya EC2 launch karne ke liye use hoti hai.

Q18: How does ASG launch a new EC2 instance?

A: ASG apne assigned Launch Template ko use karke exact wahi configuration ke saath naya instance launch karta hai.

Q19: How does ELB work with ASG?

A: ASG instances ko launch/remove karta hai, aur ELB un currently healthy instances ke beech traffic distribute karta hai.

Q20: What happens if one EC2 instance fails?

A: ELB baaki healthy instances ko hi traffic bhejta hai, aur ASG failed instance ki jagah naya instance launch kar deta hai.

Q21: How does ASG help High Availability?

A: Failed instances ko automatically replace karke aur multiple AZs mein instances rakh kar.

Q22: Why use multiple Availability Zones?

A: Taaki ek AZ mein issue aane par bhi application doosre AZ se serve hoti rahe.

Q23: What is Target Tracking Scaling?

A: Ek scaling policy jisme ASG ek target metric value (jaise 50% CPU) maintain karne ki koshish karta hai.

Q24: Difference between ALB and NLB?

A: ALB Layer 7 pe content-based routing karta hai (HTTP/HTTPS); NLB Layer 4 pe high-performance TCP/UDP/TLS handle karta hai.

Q25: Can ELB itself launch EC2 instances?

A: Nahi — ELB sirf traffic distribute karta hai, instances launch/manage nahi karta.

Q26: Can ASG distribute traffic?

A: Nahi — ASG sirf instance count manage karta hai; traffic distribution ELB ka kaam hai.

Q27: Why is a Target Group required?

A: Ye batata hai Load Balancer ko ki traffic kaunse targets ko bhejna hai, aur unka health track karta hai.

Q28: How do you troubleshoot an unhealthy target?

A: Application service status check karo (systemctl status httpd), health check path verify karo, aur security group rules check karo.

Q29: How do you connect an ASG with an ALB?

A: ASG create/edit karte waqt uske saath ek existing target group attach karo, jo ALB se linked ho.

Q30: What is the role of CloudWatch in Auto Scaling?

A: CloudWatch metrics (jaise CPU utilization) monitor karta hai aur configured thresholds cross hone par scaling policies trigger karta hai.
