1. AWS Route 53 — Name and Meaning

Full Form / Name: Amazon Route 53

Amazon Route 53 is the official name AWS gives to its DNS web service. "Amazon" shows it belongs to AWS, and "Route 53" is the product name.

What is AWS Route 53?

What is it?

Amazon Route 53 is an AWS DNS service that helps connect domain names with servers and AWS resources.

What problem does it solve?

Computers talk to each other using numeric IP addresses, which are hard for humans to remember. Route 53 lets people use easy names (like example.com) instead.

Why do we use it?

We use Route 53 to register domains, manage DNS records, route traffic reliably, and connect a domain to AWS services like EC2, ALB or S3.

How does it work? (basic idea)

You type a domain name in the browser; Route 53 looks it up and replies with the IP address (or AWS resource) it should connect to.

Real-world example

When you visit amazon.com, Route 53 (or a similar DNS service) translates that name into the server address that actually serves the Amazon website.

Why is it called "Route 53"?

"Route" refers to routing traffic to the right destination. "53" refers to port 53, the standard network port used by DNS. Together the name hints at "routing DNS traffic."

DNS port 53 DNS servers communicate over network port 53 (both TCP and UDP) — this is a globally standard convention, not something specific to AWS.

2. What is DNS?

DNS stands for Domain Name System.

Without DNS: 13.62.102.238 (hard to remember) With DNS: www.example.com | v 13.62.102.238 (DNS looks this up for you)

DNS is like a phonebook for the internet. Instead of remembering a server's numeric IP address, you type a name, and DNS finds the matching IP address for you. This lookup happens automatically every time you open a website, without you noticing it.

3. Why Do We Need Route 53?

User | v www.example.com | v Route 53 | v AWS Resource / Server | v Application

Step by step: the user types the domain in a browser. The browser asks Route 53 to resolve it. Route 53 replies with the correct AWS resource/server address. The browser connects there, and the application loads.

4. What Does Route 53 Handle?

DNS

Route 53 answers DNS queries, translating domain names into IP addresses or other resource information.

Domain registration

Route 53 also lets you buy/register a new domain name directly through AWS.

DNS records

Route 53 stores DNS records that describe how a domain should be resolved (A, CNAME, MX, etc.). Covered in detail in section 6.

Traffic routing

Route 53 can send traffic to different servers based on rules — called routing policies (weighted, latency-based, failover, etc.).

Health checks

Route 53 can check whether a server is healthy, and route traffic away from unhealthy servers automatically.

Domain-to-resource mapping

Route 53 links a domain to the actual AWS resource it should point to — an EC2 instance, a Load Balancer, an S3 website, etc.

5. Hosted Zone

What is a Hosted Zone?

A Hosted Zone is a container in Route 53 that holds all the DNS records for one domain (like example.com).

Public Hosted Zone

A Public Hosted Zone manages DNS records for a domain that is reachable from the public internet, e.g. a company website.

Private Hosted Zone

A Private Hosted Zone manages DNS records only visible inside a specific VPC, used for internal-only names not exposed to the internet.

When to use each & real examples

Use Public for anything customers or the public need to reach (e.g. www.example.com). Use Private for internal service names used only by your own applications inside a VPC (e.g. internal-db.local).

6. DNS Records

A Record

An A record maps a domain name directly to an IPv4 address.

example.com -> 13.62.102.238

AAAA Record

An AAAA record is like an A record, but maps a domain name to an IPv6 address instead of IPv4.

CNAME Record

A CNAME record points one domain name to another domain name (an alias in DNS terms), not directly to an IP.

Alias Record

An Alias record is a Route 53-specific feature that works like a CNAME but can also be used at the root domain (example.com) and points directly to AWS resources like an ALB or CloudFront.

MX Record

An MX record tells the internet which mail server handles email for a domain.

TXT Record

A TXT record stores arbitrary text, often used to verify domain ownership or set up email security (e.g. SPF).

NS Record

NS (Name Server) records list which name servers are responsible for answering DNS queries for the domain.

SOA Record

The SOA (Start of Authority) record holds administrative information about the DNS zone, like the primary name server and refresh timing. It's created automatically with every hosted zone.

7. Route 53 Routing Policies

1. Simple Routing

Simple routing sends all traffic to one resource, with no special rules.

Route 53 | v Server A (all traffic)

Real-world example: a small personal website with a single server.

2. Weighted Routing

Weighted routing splits traffic between multiple resources based on assigned weights (percentages).

Route 53 | +----+----+ v v 90% 10% Server A Server B

Real-world example: sending 10% of traffic to a new version of the app to test it (a canary release) before rolling it out fully.

3. Latency-Based Routing

Latency-based routing sends each user to the AWS region that gives them the fastest (lowest-latency) response.

User (India) -> Route 53 -> Mumbai region server User (USA) -> Route 53 -> N. Virginia region server

Real-world example: a global app serving users faster by routing them to their nearest region.

4. Failover Routing

Failover routing sends traffic to a primary resource, and automatically switches to a backup only if the primary becomes unhealthy.

Route 53 | v Primary Server --(healthy)--> used | v Secondary Server --(used only if primary is unhealthy)

Real-world example: a production website with a standby disaster-recovery server in another region.

5. Geolocation Routing

Geolocation routing sends users to specific resources based on their geographic location (country/continent), e.g. for legal or content requirements.

User in EU -> Route 53 -> EU-compliant server User in India -> Route 53 -> India-specific content server

Real-world example: showing region-specific pricing or language content.

6. Geoproximity Routing

Geoproximity routing sends traffic based on the physical location of resources and users, and lets you shift more traffic toward one resource using a "bias" value (requires Route 53 Traffic Flow).

7. IP-Based Routing

IP-based routing routes traffic depending on the client's IP address ranges, e.g. sending known ISP/network ranges to an optimized endpoint.

8. Route 53 Health Checks

Primary Server | v Health Check | Healthy -> Primary used Unhealthy -> Secondary used

What is a health check, and why do we need it?

A health check is a regular test Route 53 runs against a server/endpoint to confirm it's working. Without it, Route 53 could keep sending users to a broken server.

HTTP / HTTPS health check

Route 53 sends an HTTP or HTTPS request to a specific path and expects a successful response to consider the resource healthy.

TCP health check

A TCP health check simply tries to open a TCP connection on a given port; if the connection succeeds, the resource is considered healthy.

How failover works

Route 53 links a health check to the primary resource in a failover routing setup. If the check reports unhealthy, Route 53 automatically starts routing traffic to the secondary resource instead.

9. Domain Registration

What is a domain?

A domain is a human-readable name for a website or service, like example.com.

What is domain registration?

Domain registration is the process of officially reserving a domain name for yourself, usually for a yearly fee.

What is a registrar?

A registrar is a company authorized to sell/register domain names (Route 53 can act as one).

What are nameservers?

Nameservers are the specific DNS servers that hold the authoritative DNS records for your domain and answer DNS queries about it.

How Route 53 is used with domains / existing domain vs Route 53-registered domain

You can either register a brand-new domain through Route 53, or keep a domain registered elsewhere and just point its nameservers to Route 53 to manage its DNS records there.

10. Practical: Create a Route 53 Hosted Zone

  1. Login to the AWS Console.
  2. Search for Route 53.
  3. Open Hosted Zones from the left menu.
  4. Click "Create Hosted Zone".
  5. Enter the domain name (e.g. example.com) and choose Public or Private Hosted Zone.
  6. Click "Create hosted zone" to finish.

After creation: NS and SOA records

Route 53 automatically creates NS and SOA records. The NS record lists the 4 name servers assigned to this hosted zone — you'll copy these to your domain registrar if the domain was registered elsewhere. The SOA record holds administrative zone metadata and doesn't usually need editing.

11. Practical: Connect Route 53 with EC2

Example: EC2 Public IP = 13.62.102.238, Domain = example.com

User | v example.com | v Route 53 | v A Record | v EC2 Public IP | v Apache/Nginx | v Website
  1. Open your Hosted Zone for example.com in Route 53.
  2. Click "Create record".
  3. Leave the record name blank (for the root domain) or enter a subdomain like "www". Choose record type A.
  4. Enter the EC2 instance's public IP address (e.g. 13.62.102.238) as the value.
  5. Click "Create records" and wait a few minutes for DNS to propagate.
  6. Make sure the EC2 Security Group allows inbound traffic on port 80 (HTTP), then open the domain in a browser to test.

12. Practical: Route 53 + Application Load Balancer

User | v Route 53 | v ALB | v Target Group | v EC2 | v Application

Why is Alias Record commonly used with an ALB?

An ALB's address is a DNS name, not a fixed IP (it can change). A CNAME can't be used at the root domain, but an Alias record can — and it also updates automatically if the ALB's underlying address changes.

  1. In Route 53, open your Hosted Zone and click "Create record".
  2. Turn on "Alias", and choose record type A.
  3. Select "Alias to Application and Classic Load Balancer" and pick your ALB from the list.
  4. Click "Create records" and verify by opening the domain in a browser.

13. Route 53 + ECS Fargate

User | v Route 53 | v ALB | v ECS | v Fargate | v Docker Container | v Node.js + Express | v Database

Route 53's role here is the same as always — it turns the domain name into the ALB's address using an Alias record. The ALB then forwards traffic to whichever ECS/Fargate container is currently running the app.

14. Real MERN Application Example

Frontend: React • Backend: Node.js + Express.js • Database: MongoDB • Containerization: Docker • Image storage: ECR • Deployment: ECS Fargate • Load balancing: ALB • DNS/domain routing: Route 53

User | v Route 53 | v ALB | v ECS Fargate | v Node.js + Express | v MongoDB

The React frontend is built and served separately (e.g. from S3/CloudFront or the Express server). Users reach the app by typing the domain; Route 53 resolves it to the ALB; the ALB sends requests to a running Fargate container; the Node.js/Express backend inside that container talks to MongoDB and returns data.

15. Subdomain Example

example.com -> Frontend www.example.com -> Frontend (same or redirect) api.example.com -> Backend API admin.example.com -> Admin Panel

A single domain can have multiple subdomains, each pointed at a different service through its own DNS record — letting you split frontend, API and admin panel onto separate servers or services while keeping one domain brand.

16. Important Differences

Route 53 vs DNS

Route 53DNS
An AWS service that implements DNS (and more).The general internet system/protocol for resolving names to addresses.

Route 53 vs CloudFront

Route 53CloudFront
Resolves domain names to resources (DNS).A CDN that caches and speeds up content delivery closer to users.

Route 53 vs ALB

Route 53ALB
Directs the domain name to the right entry point (DNS level).Distributes incoming traffic across multiple servers/containers (application level).

Route 53 vs API Gateway

Route 53API Gateway
Resolves a domain name to an endpoint.Manages, routes and secures HTTP APIs (routes, auth, throttling).

A Record vs CNAME

A RecordCNAME
Points directly to an IPv4 address.Points to another domain name, not an IP.

CNAME vs Alias

CNAMEAlias
Standard DNS record; cannot be used at the root domain.Route 53-specific; can be used at the root domain and points directly to AWS resources, free of charge for queries.

Public Hosted Zone vs Private Hosted Zone

PublicPrivate
Visible/reachable from the public internet.Visible only inside a chosen VPC.

17. Complete Production Architecture

User | v Route 53 | v CloudFront | v Application Load Balancer | v ECS Fargate | v Node.js / Express | v RDS / MongoDB

Route 53 resolves the domain first. CloudFront then caches and speeds up delivery of content (especially static assets) close to the user. The ALB spreads requests across running containers. ECS Fargate runs the Node.js/Express backend containers. The backend reads/writes data in RDS or MongoDB.

A record listing the name servers responsible for a domain's DNS.

A record holding administrative information about the DNS zone.
Q15. What are Route 53 routing policies?
Rules controlling how Route 53 sends traffic: Simple, Weighted, Latency-based, Failover, Geolocation, Geoproximity, and IP-based.

Splitting traffic between resources by assigned percentage weights.
Q17. What is latency-based routing?
Sending each user to the region that gives them the fastest response.

Sending traffic to a primary resource and switching to a backup only if the primary fails a health check.

Create an A record in the hosted zone pointing to the EC2 instance's public IP.

Create an Alias record pointing to the ALB, instead of a plain CNAME.

Use Route 53 to point the domain (and subdomains like api.example.com) to the ALB in front of the containerized Node.js/Express backend, and possibly to CloudFront/S3 for the React frontend.
