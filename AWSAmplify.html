THEORY 1. What is AWS Amplify?

"AWS Amplify is a comprehensive set of purpose-built tools, libraries, and hosting services from Amazon Web Services that enables developers to build, host, and connect full-stack web and mobile applications rapidly on top of AWS infrastructure — without manually configuring complex individual cloud services."

Building modern web apps usually requires stitching together 5-10 different cloud services: S3 for static files, CloudFront for CDN, Cognito for user accounts, API Gateway for endpoints, and DynamoDB for records. Amplify acts as a unified abstraction layer that orchestrates all these underlying services with zero boilerplate.

Frontend vs Backend vs Auth vs Storage:

Layer Responsibility Underlying AWS Engine
Frontend & Hosting Serving client-side React/Vite/Next.js code globally with automated Git CI/CD. Amplify Hosting + Amazon CloudFront
Authentication User signup, login, OTP verification, social OAuth (Google/Apple), and MFA. Amazon Cognito (User & Identity Pools)
API & Data Structured communication bridge for REST endpoints or real-time GraphQL. Amazon API Gateway & AWS AppSync
Storage Uploading, downloading, and securing user media files and documents. Amazon S3 (Simple Storage Service)

THEORY 2 & 3. Why AWS Amplify & Core Architecture

2. Why Developers & Startups Choose Amplify:

  • Zero Server Management: No Linux patching, Nginx configuration, or SSH key management.
  • Native GitOps CI/CD: Pushing code to GitHub automatically triggers build containers and deploys globally.
  • Atomic Deployments: Zero downtime updates; live traffic only shifts after build verification succeeds.
  • Free Automated SSL/TLS: Instant HTTPS certificates with automatic renewals.

3. High-Level Architecture Flow:

Developer (Local Machine) │ ▼ git push origin main GitHub / GitLab Repository │ ▼ Webhook Notification AWS Amplify Hosting │ ➔ 1. Provisions Linux container │ ➔ 2. Installs packages (npm ci) │ ➔ 3. Builds bundle (npm run build ➔ dist) │ ➔ 4. Syncs static bundle to global CDN ▼ Amazon CloudFront (400+ Global Edge Locations) │ ▼ HTTPS / Fast SSL End Users Across the World

THEORY 4, 5 & 6. Core Components, Hosting & GitHub Workflow

PRACTICAL 7. PRACTICAL: Deploy a React/Vite Application on Amplify

Complete Step-by-Step Hands-on Approach:

  1. Step 1: Create Local React App with Vite:
    Terminal
    npm create vite@latest my-amplify-app -- --template react
cd my-amplify-app
npm install
npm run dev
  2. Step 2: Push to GitHub:
    Git Terminal
    git init
git add .
git commit -m "feat: initial commit for Amplify deployment"
git branch -M main
git remote add origin https://github.com/<your-username>/my-amplify-app.git
git push -u origin main
  3. Step 3: Connect to AWS Amplify Console:
    • Open the AWS Console → Search for AWS Amplify.
    • Click Host web app → Select GitHub → Click Next.
    • Authorize AWS Amplify to access your GitHub repositories.
    • Select your repository (my-amplify-app) and target branch (main).
  4. Step 4: Verify Build Settings: Amplify auto-detects Vite and sets the build output to dist. Click Next → Save and deploy.
  5. Step 5: Access Live URL: Amplify executes: Provision → Build → Deploy → Verify. Once complete, click the generated link (e.g., https://main.d1234abcd.amplifyapp.com).

THEORY 8 & 9. Build Settings (amplify.yml) & Environment Variables

8. Production amplify.yml Configuration:

YAML (amplify.yml)
version: 1
frontend:
  phases:
    preBuild:
      commands:
        - npm ci
    build:
      commands:
        - npm run build
  artifacts:
    baseDirectory: dist     # For Vite use 'dist', for Create-React-App use 'build'
    files:
      - '**/*'
  cache:
    paths:
      - node_modules/**/*

9. Environment Variables Best Practice:

Configure variables in Amplify Console → App settings → Environment variables (e.g. VITE_API_URL = https://api.mycompany.com).

🔒 Frontend Security Warning:

All VITE_ and REACT_APP_ environment variables are bundled directly into the browser's JavaScript payload. Never put database credentials or AWS Secret Keys in frontend variables!

THEORY 10 & 11. Amplify Authentication & Amazon Cognito

Amplify Auth is powered by Amazon Cognito, separating identity into two engines:
Cognito Engine Primary Function Tokens / Output Issued
User Pool (Authentication) User directory handling signup, login, password resets, and MFA verification. JWT Tokens: ID Token, Access Token, Refresh Token
Identity Pool (Authorization) Exchanges JWTs for temporary scoped AWS IAM credentials. Temporary AWS AccessKeyId, SecretKey & SessionToken

THEORY 21 TO 23. CUSTOM DOMAIN, ROUTE 53 & CLOUDFRONT

How Custom Domains Work with Route 53:

  1. In Amplify Console, go to Domain management → click Add domain.
  2. Enter your root domain (e.g. mybrand.com).
  3. Amplify automatically provisions an SSL/TLS certificate via AWS Certificate Manager (ACM).
  4. Amplify automatically maps the required CNAME and Alias (A) records inside your Route 53 Hosted Zone.

TROUBLESHOOTING 28 & 29. 10 COMMON AMPLIFY ERRORS & FIXES

Issue / Error Root Cause How to Fix
1. Build Step Failed Missing npm package or syntax error in build script. Check Amplify build logs; run npm run build locally to verify.
2. Blank White Screen on Live App Wrong baseDirectory in amplify.yml. Set baseDirectory: dist for Vite or build for CRA.
3. 404 Error on Page Refresh SPA client-side route requested without a rewrite rule. Add a 200 Rewrite rule directing all non-file paths to /index.html.
4. Browser CORS Error Backend does not allow the Amplify domain. Add Access-Control-Allow-Origin: https://your-amplify-domain in backend.
5. Environment Variable Undefined Missing VITE_ prefix or app was not rebuilt after adding. Prefix variable with VITE_ and trigger a new build in Amplify.
6. Case-Sensitive Import Failure Linux build container enforces case-sensitive file paths. Match exact import path casing (e.g. import Header from './Header').
7. Custom Domain Verification Stuck Missing or incorrect CNAME validation records in DNS. Add ACM CNAME records to DNS host and allow TTL propagation.
8. Node.js Version Mismatch Amplify using older Node version than required by packages. Add nvm use 20 in the preBuild phase in amplify.yml.
9. Cognito Auth 400 Bad Request Mismatched User Pool ID or App Client ID in config. Verify IDs inside amplifyconfiguration.json match AWS Cognito console.
10. Out of Memory Build Error Heavy bundle exceeding standard container memory. Optimize bundle chunks or increase build compute allocation in settings.

IMPORTANT 30. REACT SPA ROUTING (404 ON REFRESH FIX)

The Problem: React Router routes (e.g. /dashboard, /profile) exist only in JavaScript memory in the browser. When a user presses F5 Refresh, the browser asks the static web server for a physical file at /dashboard/index.html. Since that file does not exist, the server returns a 404 Not Found error.

How to Fix: Configure 200 Rewrite Rule in Amplify Console

  1. Open Amplify Console → Go to App settings → Click Rewrites and redirects.
  2. Click Add rule and enter:
    • Source address: </^[^.]+$|\.(?!(css|gif|ico|jpg|js|png|txt|svg|woff|woff2|ttf|map|json)$)([^.]+$)/>
    • Target address: /index.html
    • Type: 200 (Rewrite)
  3. Click Save. Now all route requests return index.html with a 200 status code, allowing React Router to render smoothly!

INTERVIEW 37. TOP 30+ AWS AMPLIFY INTERVIEW QUESTIONS & ANSWERS

Q1. What is AWS Amplify?

A set of purpose-built tools and services from AWS to build, host, and connect full-stack web and mobile apps with automated CI/CD and serverless backends.

Q2. How does Amplify Hosting differ from S3 Static Hosting?

Amplify includes built-in Git CI/CD, automatic SSL certificates, native CloudFront integration, PR previews, and SPA routing rewrites out of the box.

Q3. Which CDN powers Amplify Hosting under the hood?

Amazon CloudFront, delivering content with edge caching across hundreds of global Edge Locations.

Q4. How does Amplify trigger deployments on git push?

Via webhooks. When code is pushed to GitHub, Amplify spins up a temporary Linux container to run build commands and distribute assets.

Q5. Why does refreshing a React SPA route cause a 404 error?

Because client-side routes don't physically exist on the static server. It is resolved by adding a 200 Rewrite rule pointing non-asset URLs to /index.html.

Q6. Which AWS service powers Amplify Authentication?

Amazon Cognito, using User Pools for directory authentication and Identity Pools for AWS IAM authorization.

Q7. What is Cognito User Pool vs Identity Pool?

User Pools manage Authentication (login/signup, issuing JWTs). Identity Pools manage Authorization (granting temporary AWS IAM credentials to access S3/DynamoDB).

Q8. What does amplify.yml do?

It is the build specification defining preBuild, build commands, caching paths, and the output baseDirectory (e.g. dist).

Q9. What is Amplify Gen 2?

The next-generation code-first TypeScript approach for AWS Amplify, built natively on the AWS Cloud Development Kit (CDK).

Q10. Does Amplify replace Node/Express in MERN?

No. Amplify hosts the React frontend and handles auth/storage, while the Node/Express backend runs custom business logic on EC2, ECS, or App Runner.

SCENARIOS 38 & 39. SCENARIOS & QUICK REVISION CHEATSHEET

Scenario 1: React site loads fine on home page, but hitting refresh on /profile returns 404.

Solution: Go to Amplify Console → Rewrites and redirects and add a 200 Rewrite rule directing all traffic to /index.html.

Scenario 2: Code builds on Windows locally, but fails in Amplify CI/CD container.

Solution: Check build logs for case-sensitive import mismatches (e.g. ./Navbar vs ./navbar), as Linux filesystems are case-sensitive.
