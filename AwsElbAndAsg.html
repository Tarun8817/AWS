AWS ELB & ASG

⚖️ AWS ELB & ASG — Complete Guide

Elastic Load Balancing and Auto Scaling Groups — from the basics to full architecture

1️⃣ Basic AWS Terms

Scalability

Scalability means the ability of a system to handle increasing workload, traffic, or users by increasing available resources.

Simple example: imagine you have a website that gets 100 users — the server handles it easily. Now if traffic grows to 10,000 users, the server needs more resources to handle that load without slowing down. That ability is called scalability.

Vertical Scalability — Scaling Up

This involves:

  • Increasing CPU
  • Increasing RAM
  • Using a larger EC2 instance
t2.micro ↓ m5.large

Here, the existing server itself becomes more powerful — same server, just bigger.

Limitations:
  • There is an upper hardware limit — you can't scale up infinitely.
  • The server may need to be stopped/restarted depending on the change.
  • A single server can still remain a single point of failure.

Horizontal Scalability — Scaling Out

This involves:

  • Adding more EC2 instances
  • Distributing workload across multiple servers
  • Usually used together with a Load Balancer
Load Balancer ↓ ┌──────────┼──────────┐ ↓ ↓ ↓ EC2-1 EC2-2 EC2-3

Scaling Up vs Scaling Out: Scaling Up makes one server bigger; Scaling Out adds multiple servers that share the load between them. Horizontal scaling generally gives better reliability, since the remaining servers keep working even if one fails.

🛡️ High Availability (HA)

High Availability means designing an application so that it remains accessible with minimal downtime even when some infrastructure components fail.
  • Multiple EC2 instances — not depending on a single server.
  • Multiple Availability Zones — placing servers in different physical locations.
  • Load Balancer — routing traffic to healthy servers.
  • Auto Scaling — automatically replacing failed instances.
  • Health checks — regularly checking whether a server is working correctly.
Load Balancer ↓ ┌─────────┴─────────┐ ↓ ↓ AZ-1 AZ-2 EC2 EC2

Using multiple Availability Zones improves availability because if one AZ has an issue (power, network, hardware), the server in the other AZ keeps serving traffic.

⚠️ Important

High Availability ≠ 100% uptime. HA means minimizing downtime, not guaranteeing the system will never fail.

🌊 Elasticity

Elasticity means automatically increasing or decreasing resources according to demand.
High Traffic ↓ More EC2 Instances ↓ Traffic decreases ↓ Fewer EC2 Instances

ASG provides automatic scaling through configured policies — as soon as demand rises, new instances launch, and as soon as demand falls, extra instances are automatically removed.

Scalability vs Elasticity vs High Availability

ConceptFocus
ScalabilityThe system's ability to handle growing workload (by adding resources)
ElasticityResources automatically growing/shrinking based on demand
High AvailabilityKeeping the service accessible even when a component fails

⚖️ What is ELB?

ELB = Elastic Load Balancing

ELB is an AWS service that distributes incoming traffic across multiple targets (such as EC2 instances), so that no single server gets overloaded and the application stays more reliable.

A Load Balancer:

  • Receives incoming traffic
  • Distributes requests across healthy targets
  • Performs health checks
  • Helps improve availability
  • Can work across multiple Availability Zones

The problem without a Load Balancer:

Users ↓ Single EC2 ↓ Application

If this EC2 fails, users cannot access the application.

With ELB:

Users ↓ Load Balancer ↓ ┌──────────┼──────────┐ ↓ ↓ ↓ EC2-1 EC2-2 EC2-3

🏷️ Types of AWS Load Balancers

Application Load Balancer (ALB)

  • Operates at Layer 7
  • For HTTP/HTTPS traffic
  • Supports host-based routing
  • Supports path-based routing
  • Best for: web applications, REST APIs, microservices
example.com/users ↓ ALB ↓ User Service
example.com/products ↓ ALB ↓ Product Service

Network Load Balancer (NLB)

  • Operates at Layer 4
  • TCP support
  • UDP support
  • TLS support
  • Very high performance, low latency
  • Suitable for network-level traffic

Gateway Load Balancer (GWLB)

  • Used for network/security appliances
  • Traffic inspection
  • Firewalls
  • Security appliances

Classic Load Balancer is a legacy option — modern architectures generally use ALB or NLB depending on requirements.

RoutingContent-basedConnection/network-levelAppliance-oriented
Common useWeb apps/APIHigh-performance network trafficFirewalls/security appliances

🧩 Important ELB Components

Load Balancer

The entry point that receives client requests.

Listener

Checks incoming connection requests.

Example: HTTP : 80, HTTPS : 443

Target Group

A group of targets that receive traffic.

Targets can include EC2 instances.

Health checks are configured at the target group level.

Targets

Examples: EC2 instances, IP addresses, containers, depending on load balancer type/configuration.

Health Checks

The Load Balancer checks whether targets are healthy before sending traffic to them.

ALB ↓ Health Check ↓ EC2-1 → Healthy EC2-2 → Healthy EC2-3 → Unhealthy

Traffic should be routed only to healthy targets.

📈 What is ASG?

ASG = Auto Scaling Group

An Auto Scaling Group automatically manages the number of EC2 instances according to configured minimum, desired, and maximum capacity.

  • Minimum capacity — the lowest number of instances that should always be running
  • Desired capacity — the target number of instances under normal conditions
  • Maximum capacity — the highest number of instances allowed
Minimum = 2 Desired = 2 Maximum = 5

During high traffic:

2 EC2 ↓ 3 EC2 ↓ 4 EC2 ↓ 5 EC2

During low traffic:

5 EC2 ↓ 4 EC2 ↓ 3 EC2 ↓ 2 EC2

ASG helps with:

  • Scalability
  • Elasticity
  • High availability
  • Automatic instance replacement

📋 ASG Launch Template

A Launch Template is generally used with ASG because it defines exactly how a new EC2 instance should be launched.

A Launch Template can define:

  • AMI
  • Instance type
  • Key pair
  • Security group
  • IAM role
  • Network configuration
  • Storage
  • User Data
AMI ↓ Launch Template ↓ Auto Scaling Group ↓ EC2 Instances
ComponentRole
AMIThe server's base image (OS + software)
Launch TemplateAMI + launch settings (instance type, key pair, SG, user data, etc.)
ASGUses the Launch Template to manage the number of instances

🔗 ELB + ASG Relationship

ELB distributes traffic.

ASG manages the number of EC2 instances.

Users ↓ Application Load Balancer ↓ Target Group ↓ ┌───────────┼───────────┐ ↓ ↓ ↓ EC2-1 EC2-2 EC2-3 ↑ ↑ ↑ └───────────┼───────────┘ ↑ ASG ↑ Launch Template ↑ AMI
  • Users — the people accessing the application
  • Application Load Balancer — receives and distributes traffic
  • Target Group — groups targets and tracks their health
  • EC2 instances — actually process the traffic
  • ASG — manages the number of instances
  • Launch Template — defines how instances should be launched
  • AMI — provides the server's base image

🏗️ Complete Real-World Example

Suppose we have a website running on Apache.

Initially:

Users ↓ EC2 Instance

Traffic increases.

Problem:
  • The single EC2 becomes overloaded.
  • If the instance fails, the website becomes unavailable.

Solution:

Users ↓ ALB ↓ ┌────────┴────────┐ ↓ ↓ EC2-1 EC2-2 ↑ ↑ └────── ASG ──────┘

If traffic increases:

EC2-1 + EC2-2 ↓ ASG launches EC2-3 ↓ ALB sends traffic to EC2-1, EC2-2, EC2-3

If traffic decreases:

EC2-1 + EC2-2 + EC2-3 ↓ ASG scales in ↓ EC2-1 + EC2-2

📜 EC2 Apache Server User Data Script

#!/bin/bash

# Update packages
sudo yum update -y

# Install Apache
sudo yum install -y httpd

# Start Apache
sudo systemctl start httpd

# Enable Apache at boot
sudo systemctl enable httpd

# Create simple HTML page
cat <<EOF > /var/www/html/index.html
<html>
<head>
    <title>Apache Web Server</title>
</head>
<body>
    <h1>Welcome to Apache Web Server on Amazon Linux</h1>
    <h2>Hostname: $(hostname)</h2>
</body>
</html>
EOF

#!/bin/bash — indicates this script runs using the Bash shell.

# Update packages and sudo yum update -y — updates all installed packages to their latest version; -y automatically confirms "yes" to prompts.

sudo yum install -y httpd — installs the Apache web server (httpd).

sudo systemctl start httpd — starts the Apache service immediately.

sudo systemctl enable httpd — configures Apache to start automatically on every reboot.

cat <<EOF > /var/www/html/index.html ... EOF — a "heredoc" that writes everything between the EOF markers directly into the index.html file.

$(hostname) — dynamically fetches the server's current hostname and prints it on the page.

Common Mistakes to Avoid

Incorrect:

httpdsudo

Correct (two separate commands, on separate lines):

httpd
sudo

Incorrect:

systemctl start httpd|

Correct (no stray | pipe character):

systemctl start httpd

A dynamic hostname is useful because when multiple EC2 instances are running behind an ALB, seeing a different hostname on browser refresh confirms that requests are reaching different instances — a simple, effective way to test load distribution.

🛠️ Create Launch Template

  1. Open the AWS Console.
  2. Go to EC2.
  3. Select Launch Templates.
  4. Click Create launch template.
  5. Enter a name for the Launch Template.
  6. Select an AMI.
  7. Select an instance type.
  8. Select a key pair if required.
  9. Configure the security group.
  10. Configure storage.
  11. Add User Data.
  12. Review the configuration.
  13. Click Create Launch Template.

The Launch Template must have the correct AMI, correct Security Group, and correct User Data — because ASG will launch every new instance based on this template. If the template has an incorrect setting, every new instance will inherit that same mistake.

🎯 Create Target Group

  1. Open EC2.
  2. Go to Target Groups.
  3. Click Create target group.
  4. Select the target type.
  5. Select the protocol and port.
  6. Select the VPC.
  7. Configure the health check.
  8. Click Create target group.

For Apache:

Protocol: HTTP Port: 80 Health Check Path: /

/ means the health check sends a request to the root URL (http://instance-ip/), and if Apache returns a valid response (like 200 OK) from there, that instance is considered healthy.

🌐 Create Application Load Balancer

  1. Open EC2.
  2. Go to Load Balancers.
  3. Click Create Load Balancer.
  4. Select Application Load Balancer.
  5. Enter a name for the Load Balancer.
  6. Choose Internet-facing if you're creating a public website.
  7. Select IPv4.
  8. Select the VPC.
  9. Select at least two Availability Zones/subnets where applicable.
  10. Configure the security group.
  11. Configure the listener.
  12. Select the target group.
  13. Review everything.
  14. Click Create Load Balancer.
  • Internet-facing ALB — accessible from the public internet; you can also choose "internal" for internal-only use.
  • Security Group — decides which traffic (ports) is allowed on the ALB.
  • Listener — checks which port (e.g. 80/443) requests are coming in on.
  • Target Group — defines which group of EC2 instances the traffic should be sent to.
  • Availability Zones — selecting multiple AZs provides high availability.

📊 Create Auto Scaling Group

  1. Open EC2.
  2. Go to Auto Scaling Groups.
  3. Click Create Auto Scaling group.
  4. Enter a name for the ASG.
  5. Select the Launch Template.
  6. Select the VPC.
  7. Select multiple Availability Zones/subnets.
  8. Configure the Group Size.
  9. Set the Desired Capacity.
  10. Set the Minimum Capacity.
  11. Set the Maximum Capacity.
  12. Configure scaling options.
  13. Attach the existing target group.
  14. Configure health checks.
  15. Review everything.
  16. Click Create Auto Scaling Group.
Minimum capacity = 2 Desired capacity = 2 Maximum capacity = 5

🎛️ Configure ASG Scaling Policies

Target Tracking Scaling

Target CPU utilization = 50%

ASG adjusts capacity to try to maintain this target.

Step Scaling

Scaling can occur by different amounts depending on CloudWatch alarm thresholds.

Scheduled Scaling

Scaling based on a predictable schedule.

Office Hours → More Instances Night → Fewer Instances

CloudWatch monitors metrics (like CPU utilization) and triggers scaling policies when configured thresholds are crossed.

🧪 Test ELB + ASG

  1. Check the ASG.
  2. Verify EC2 instances are running.
  3. Check the target group.
  4. Verify target health.
  5. Open the ALB DNS name in a browser.
  6. Refresh multiple times.
  7. Verify the application is accessible.
  8. Check the hostname displayed on the webpage.

Seeing different hostnames helps demonstrate that requests are reaching different instances, although request distribution is not guaranteed to alternate on every refresh.

📈 Test Auto Scaling

Desired = 2 Minimum = 2 Maximum = 4

Increase CPU utilization or use a configured CloudWatch metric.

Then verify:

2 EC2 ↓ 3 EC2 ↓ 4 EC2

After the workload decreases:

4 EC2 ↓ 3 EC2 ↓ 2 EC2

Instances increasing is called scale-out, and instances decreasing is called scale-in.

🧯 Test High Availability

ALB ↓ EC2-1 EC2-2

Terminate one EC2 instance.

Expected behavior:

EC2-1 → Terminated EC2-2 → Still running ↓ ASG launches replacement EC2 ↓ New EC2 becomes healthy ↓ ALB can route traffic to it

This demonstrates automatic replacement, which helps maintain service availability.

🔒 Security Groups

Internet ↓ ALB Security Group ↓ EC2 Security Group

ALB Security Group

Allow:

HTTP 80 HTTPS 443

From appropriate client sources.

EC2 Security Group

Allow HTTP traffic from the ALB security group, rather than broadly allowing HTTP from the entire internet when possible. This is more secure because EC2 instances no longer accept direct internet traffic — traffic only arrives through the ALB, reducing the attack surface.

🎯 Important Interview Questions

Q1: What is ELB?

A: Elastic Load Balancing — an AWS service that distributes traffic across multiple targets.

Q2: What is ASG?

A: Auto Scaling Group — manages EC2 instances according to configured min/desired/max capacity.

Q3: What is scalability?

A: The system's ability to handle growing workload/traffic by increasing resources.

Q4: What is vertical scaling?

A: Upgrading an existing server to a bigger instance type.

Q5: What is horizontal scaling?

A: Adding more servers to share the load.

Q6: What is elasticity?

A: Resources automatically increasing/decreasing based on demand.

Q7: What is high availability?

A: Keeping the application accessible with minimal downtime even if some components fail.

Q8: Difference between scalability and elasticity?

A: Scalability is the capability to handle growing load; elasticity makes that process automatic.

Q9: What is ALB?

A: Application Load Balancer — handles HTTP/HTTPS traffic at Layer 7 with content-based routing.

Q10: What is NLB?

A: Network Load Balancer — handles high-performance TCP/UDP/TLS traffic at Layer 4.

Q11: What is a Target Group?

A: A group of targets (like EC2 instances) that receive traffic and have configured health checks.

Q12: What is a Listener?

A: The part of the Load Balancer that checks incoming connections on a specific port (like 80/443).

Q13: What is an ELB health check?

A: A periodic check verifying whether a target is healthy enough to handle traffic.

Q14: What happens when an EC2 target becomes unhealthy?

A: The Load Balancer stops sending traffic to that target until it becomes healthy again.

Q15: What is an Auto Scaling Group?

A: An AWS resource that automatically manages the count of EC2 instances based on min/desired/max capacity.

Q16: What are minimum, desired, and maximum capacities?

A: Minimum = lowest allowed instances; Desired = normal target count; Maximum = highest allowed instances.

Q17: What is a Launch Template?

A: A saved configuration (AMI, instance type, key pair, SG, user data, etc.) used to launch a new EC2 instance.

Q18: How does ASG launch a new EC2 instance?

A: ASG uses its assigned Launch Template to launch a new instance with the exact same configuration.

Q19: How does ELB work with ASG?

A: ASG launches/removes instances, and ELB distributes traffic across whichever instances are currently healthy.

Q20: What happens if one EC2 instance fails?

A: ELB sends traffic only to the remaining healthy instances, and ASG launches a new instance to replace the failed one.

Q21: How does ASG help High Availability?

A: By automatically replacing failed instances and keeping instances spread across multiple AZs.

Q22: Why use multiple Availability Zones?

A: So the application keeps being served from another AZ even if one AZ has an issue.

Q23: What is Target Tracking Scaling?

A: A scaling policy where ASG tries to maintain a target metric value (like 50% CPU).

Q24: Difference between ALB and NLB?

A: ALB does content-based routing at Layer 7 (HTTP/HTTPS); NLB handles high-performance TCP/UDP/TLS at Layer 4.

Q25: Can ELB itself launch EC2 instances?

A: No — ELB only distributes traffic; it does not launch or manage instances.

Q26: Can ASG distribute traffic?

A: No — ASG only manages instance count; traffic distribution is ELB's job.

Q27: Why is a Target Group required?

A: It tells the Load Balancer which targets to send traffic to, and tracks their health.

Q28: How do you troubleshoot an unhealthy target?

A: Check the application service status (systemctl status httpd), verify the health check path, and check security group rules.

Q29: How do you connect an ASG with an ALB?

A: When creating/editing the ASG, attach an existing target group that's linked to the ALB.

Q30: What is the role of CloudWatch in Auto Scaling?

A: CloudWatch monitors metrics (like CPU utilization) and triggers scaling policies when configured thresholds are crossed.
