1️⃣ Definition

Theory

What is AWS EC2?
Amazon EC2 (Elastic Compute Cloud) is a web service from AWS that gives you resizable virtual computers ("servers") in the cloud. Instead of buying physical hardware, you rent a computer from AWS and use it over the internet.

What does EC2 stand for?
Elastic Compute Cloud.

What is an EC2 Instance?
An EC2 Instance is one single virtual server you create and run inside EC2. Think of it as one computer that AWS gives you to use.

Why do we use EC2?
It lets you get a server running in minutes, pay only for what you use, resize it (more/less CPU or RAM) whenever needed, and avoid the cost and effort of buying and maintaining physical machines.

Real-world example

Imagine you built a website on your laptop. To let the whole world visit it, you need a computer that is always switched on and connected to the internet. Instead of running your own laptop 24/7, you rent an EC2 instance from AWS, put your website on it, and now anyone in the world can open it using its public address.

🧭 EC2 Architecture / Basic Flow

Theory
User ↓ Internet ↓ Public IP ↓ Security Group ↓ EC2 Instance ↓ Application / Web Server
  • User — The person opening a browser and requesting the website or application.
  • Internet — The public network that carries the request from the user to AWS.
  • Public IP — The address of your EC2 instance on the internet; without it, the outside world cannot reach your server.
  • Security Group — A virtual firewall in front of the instance that decides which traffic (ports) is allowed in or out.
  • EC2 Instance — The actual virtual server that receives the request.
  • Application / Web Server — The software (like Apache) running inside the instance that actually processes the request and sends back a response.

💡 Why Do We Use EC2?

Theory
  • Website hosting — Run a company or personal website that is reachable 24/7.
  • Backend/API hosting — Host REST/GraphQL APIs that mobile or web apps call.
  • Application servers — Run business software such as CRMs or internal tools.
  • Development environments — Give each developer or team a remote machine to build and test on.
  • Databases — Self-manage MySQL, PostgreSQL, MongoDB, etc. on a dedicated server.
  • Docker workloads — Run containers when you need full control over the host machine.
  • Business applications — ERP systems, reporting tools, internal dashboards, and more.

🧩 Important EC2 Components

Theory

AMI (Amazon Machine Image)

Definition: An AMI is a pre-built template that contains an operating system and sometimes pre-installed software. It's like a "snapshot recipe" used to create an EC2 instance.

Purpose: It saves you from installing an OS from scratch every time you launch a server.

Examples: Amazon Linux 2023, Ubuntu 22.04, Windows Server 2022, Red Hat Enterprise Linux.

How it's used: When you launch an EC2 instance, the very first choice you make is which AMI to boot from — this decides your operating system.

Instance Type

Definition: The instance type decides how much CPU, RAM, and network performance your virtual server gets.

CPU / RAM / Network: Each type name (like t3.micro) maps to a fixed amount of vCPUs, memory, and network bandwidth.

Examples: t3.micro (2 vCPU, 1 GB RAM — great for learning/free tier), t3.small (2 vCPU, 2 GB RAM), t3.medium (2 vCPU, 4 GB RAM).

Key Pair

Definition: A Key Pair is a set of two cryptographic keys — a public key and a private key — used to securely log into your instance.

Public key — Stored by AWS on the instance automatically.

Private key — Downloaded once by you as a .pem file; never shared with anyone.

Why required: Linux EC2 instances don't use a password by default — they use key-based login, which is far more secure.

How SSH uses it: When you connect, SSH proves you own the matching private key without ever sending it over the network.

How to create a Key Pair

  1. Go to EC2 Dashboard → Key Pairs.
  2. Click Create key pair.
  3. Enter a name (e.g., my-ec2-key).
  4. Choose type RSA and format .pem (for Linux/Mac) or .ppk (for PuTTY on Windows).
  5. Click Create key pair — the private key file downloads automatically. Keep it safe; AWS does not store a copy.

Security Group

Definition: A Security Group is a virtual firewall attached to your EC2 instance that controls incoming and outgoing traffic.

Inbound rules — Control traffic coming into the instance (e.g., allowing SSH or web traffic in).

Outbound rules — Control traffic going out of the instance (usually left open by default).

PortProtocolPurpose
22SSHRemote terminal login to Linux servers
80HTTPNormal (unencrypted) website traffic
443HTTPSEncrypted, secure website traffic

Source IP concept: Each rule also has a "source" — which IP addresses are allowed to use that port. 0.0.0.0/0 means "anyone on the internet," while My IP restricts access to only your current IP address.

VPC (Virtual Private Cloud)

Definition: A VPC is your own private, isolated network inside AWS where your resources (like EC2) live.

Relationship with EC2: Every EC2 instance must be launched inside a VPC — it defines the private network boundaries and IP ranges the instance can use.

Subnet

Definition: A Subnet is a smaller division of a VPC's IP address range.

Public subnet — Has a route to the internet, so instances here can have a public IP.

Private subnet — Has no direct route to the internet, used for databases or internal-only servers.

Relationship with EC2: Every EC2 instance is launched inside one specific subnet, which determines whether it can be reached from the internet.

Availability Zone (AZ)

Definition: An Availability Zone is one physical, isolated data center location within an AWS Region.

Why EC2 runs inside an AZ: Every instance must physically exist somewhere — placing it in a specific AZ helps AWS provide fault isolation (if one AZ has an issue, others are unaffected).

Region

Definition: A Region is a geographic area (e.g., Mumbai, Singapore, N. Virginia) containing multiple Availability Zones.

Relationship: One Region contains many Availability Zones (usually 3 or more), and each AZ contains its own separate data centers.

EBS (Elastic Block Store)

Definition: EBS is persistent block storage attached to an EC2 instance, like a virtual hard drive.

Why EC2 uses EBS: An EC2 instance needs a disk to store the operating system and data — EBS provides that disk, and the data survives even if the instance is stopped.

Root volume — The primary EBS volume that holds the operating system; it's created automatically when you launch the instance.

Additional EBS volumes — Extra disks you can attach later for more storage (e.g., for application data or databases).

Public IP

Definition: A Public IP is an internet-routable address assigned to your instance so it can be reached from outside AWS.

Why required: Without it, no one on the internet can connect to your server.

How to find it: Open EC2 → Instances, select your instance, and look at the Public IPv4 address field in the details panel.

Private IP

Definition: A Private IP is an internal address usable only within the VPC.

Internal communication: It's used when EC2 instances need to talk to each other inside the same network, without going over the public internet.

Elastic IP

Definition: An Elastic IP is a static, fixed public IP address that you allocate and control.

Why used: A normal Public IP changes every time you stop and start an instance; an Elastic IP stays the same.

Difference from Public IP: A regular Public IP is temporary and auto-assigned; an Elastic IP is permanent until you manually release it.

User Data

Definition: User Data is a script you attach to an instance that runs automatically the very first time it boots.

Purpose: To automate setup tasks — installing software, starting services, or configuring the server — without manual work.

How to use it: Paste a shell script into the "User data" field under Advanced Details while launching the instance.

💰 EC2 Pricing Basics

Theory
  • On-Demand — Pay by the hour/second with no long-term commitment; most flexible, but most expensive per hour.
  • Reserved Instances — Commit to 1 or 3 years for a significantly lower hourly rate; good for predictable, steady workloads.
  • Savings Plans — Commit to a consistent amount of compute usage (in $/hour) for 1–3 years in exchange for lower prices, more flexible than Reserved Instances.
  • Spot Instances — Use AWS's spare capacity at a steep discount; AWS can reclaim the instance with short notice, so it suits fault-tolerant or flexible workloads.
  • Free Tier — New AWS accounts can run a t2.micro or t3.micro instance for a limited number of hours per month, free, for 12 months — perfect for learning.

🚀 How to Create an EC2 Instance

Practical
AWS Console ↓ EC2 ↓ Launch Instance
  1. Instance Name — Give it a recognizable name, e.g. my-web-server. This is just a label.
  2. AMI — Choose the operating system. For a beginner Linux web server, select Amazon Linux 2023 (Free tier eligible).
  3. Instance Type — Choose t3.micro or t2.micro for learning (Free Tier eligible).
  4. Key Pair — Select an existing key pair or create a new one; download the .pem file and keep it safe.
  5. VPC — Keep the default VPC unless you have a custom network already set up.
  6. Subnet — Choose any public subnet (or "No preference") so the instance gets internet access.
  7. Auto-assign Public IP — Set to Enable so you can reach the instance from the internet.
  8. Security Group — Create a new one and allow SSH (22) from "My IP" and, for a web server, HTTP (80) from anywhere.
  9. Storage / EBS — Keep the default 8 GB gp3 root volume for a simple test server.
  10. Advanced Details — Leave defaults unless you need IAM roles or specific settings.
  11. User Data — Optionally paste a startup script here (see Section 17).
  12. Launch Instance — Click Launch instance; AWS will boot it within a minute or two.

🔍 How to Check EC2 Instance Details

Practical
  1. Go to EC2 → Instances.
  2. Click on your instance's Instance ID to open its details page.
  3. On the Details tab you can find: Instance ID, Instance State, Instance Type, AMI ID, Public IPv4 address, Private IPv4 address, Public IPv4 DNS, Private DNS, Availability Zone, VPC ID, Subnet ID, Security Group, and Key pair name.
  4. Go to the Storage tab to see the attached EBS Volume(s), their size, and device names.

🔑 How to Access EC2

Practical

Method 1: SSH

What SSH is: Secure Shell (SSH) is a protocol that lets you open a secure remote terminal session on another computer over the network.

Why Port 22: SSH communicates over TCP port 22 by convention — this is why the Security Group must allow inbound traffic on port 22.

Where the .pem file is used: It's passed to the SSH command to prove your identity instead of typing a password.

ssh -i "key.pem" ec2-user@PUBLIC-IP

ssh — the command that starts a secure shell connection.

-i "key.pem" — tells SSH which private key file to use for authentication.

ec2-user — the default username for Amazon Linux instances (Ubuntu uses ubuntu).

@PUBLIC-IP — the public IPv4 address of your EC2 instance.

Method 2: EC2 Instance Connect

  1. Go to EC2 → Instances and select your instance.
  2. Click Connect at the top.
  3. Choose the EC2 Instance Connect tab.
  4. Click Connect — a browser-based terminal opens directly, no key file needed.

SSH vs EC2 Instance Connect: SSH requires your own terminal and the private key file; EC2 Instance Connect works straight from the browser using temporary, AWS-managed credentials — convenient for quick access but SSH is more common for regular development work.

🔄 Update the EC2 Server

Practical

For Amazon Linux, run:

sudo dnf update -y

sudo — runs the command as administrator, required for system-level changes.

dnf — the package manager used by Amazon Linux/Fedora/RHEL to install and update software.

update — tells dnf to fetch and install the latest versions of all installed packages.

-y — automatically answers "yes" to confirmation prompts, so the update runs without interruption.

🌐 Install Apache Web Server

Practical 
sudo dnf install -y httpd
sudo systemctl start httpd
sudo systemctl enable httpd
sudo systemctl status httpd

sudo dnf install -y httpd — installs the Apache web server package (called httpd on Amazon Linux).

sudo systemctl start httpd — starts the Apache service immediately.

sudo systemctl enable httpd — configures Apache to start automatically every time the server reboots.

sudo systemctl status httpd — shows whether Apache is currently running and healthy.

What is Apache? Apache HTTP Server is free, widely-used software that serves web pages to visitors' browsers.

Why install it? An EC2 instance is just a bare server — it needs web server software like Apache to actually respond to website requests.

What is systemctl? It's the tool used on modern Linux systems to control services (start, stop, enable, check status).

start — turns the service on right now.

enable — makes the service start automatically on every boot.

status — reports whether the service is active, and shows recent log lines.

🛡️ Configure Security Group for Apache

Practical

Apache serves web pages over HTTP port 80. If this port isn't opened in the Security Group, visitors will never be able to reach the website, no matter how well Apache is configured.

EC2 ↓ Security Groups ↓ Inbound Rules ↓ Edit Inbound Rules ↓ Add HTTP ↓ Port 80 ↓ Source 0.0.0.0/0
  1. Go to EC2 → Instances, select your instance, and open the Security tab.
  2. Click on the attached Security Group.
  3. Go to Inbound rules → Edit inbound rules.
  4. Click Add rule, choose type HTTP (this auto-fills port 80).
  5. Set Source to 0.0.0.0/0 to allow traffic from anywhere.
  6. Click Save rules.
Security note: 0.0.0.0/0 means literally anyone on the internet can reach this port. This is normal and expected for a public website on port 80/443, but you should never open sensitive ports like 22 (SSH) or database ports (3306, 5432) to 0.0.0.0/0 — restrict those to your own IP or a trusted network instead.

📄 Host a Simple Website on EC2

Practical

Apache's default web directory on Amazon Linux is:

/var/www/html
  1. Move into the web directory: 
    cd /var/www/html
  2. Create the homepage file: 
    sudo nano index.html
  3. Paste a simple HTML page: 
    <!DOCTYPE html>
<html>
  <head><title>My EC2 Website</title></head>
  <body>
    <h1>Welcome to AWS EC2!</h1>
    <p>This page is hosted on an Amazon EC2 instance.</p>
  </body>
</html>
  4. Save the file in nano: press Ctrl + O, then Enter to confirm, then Ctrl + X to exit.

Now open a browser and visit:

http://PUBLIC-IP

When you open the Public IP in a browser, the request travels over the internet to your instance's public IP, passes through the Security Group's port 80 rule, reaches Apache, and Apache reads and returns index.html — which the browser then renders as a webpage.

✅ Verify Apache

Practical 
sudo systemctl status httpd
curl localhost
curl http://localhost

sudo systemctl status httpd — confirms whether the Apache service itself is running.

curl localhost and curl http://localhost — send an HTTP request from inside the server to itself, printing the raw HTML response; if you see your page's HTML, Apache is serving content correctly.

📜 EC2 User Data

Theory Practical

What it is: A shell script attached to an instance at launch time.

When it runs: Automatically, only once, the very first time the instance boots.

Why useful: It fully automates setup — no manual SSH steps required after launch.

How to add it: Paste the script into the User data box under Advanced details while launching the instance.

#!/bin/bash

dnf update -y
dnf install -y httpd
systemctl start httpd
systemctl enable httpd
echo "<h1>Welcome to AWS EC2</h1>" > /var/www/html/index.html

#!/bin/bash — tells the system this script should run using the Bash shell.

dnf update -y — updates all installed packages before setting anything up.

dnf install -y httpd — installs Apache.

systemctl start httpd — starts Apache immediately.

systemctl enable httpd — ensures Apache restarts automatically on reboot.

echo "..." > /var/www/html/index.html — writes a simple welcome heading directly into the homepage file, so the website is live the moment the instance finishes booting.

⏯️ Stop, Start, Reboot and Terminate

Theory Practical

Stop

The instance shuts down but is not deleted. The EBS root volume and its data remain intact. It can be started again later. Billing for compute usage stops, but EBS storage charges continue.

Start

Boots up a stopped instance again. It usually gets a new Public IPv4 address unless an Elastic IP is attached.

Reboot

Restarts the operating system without fully stopping the instance. The Public IP stays the same, and it's equivalent to restarting a physical computer.

Terminate

Permanently deletes the instance. By default, the root EBS volume is also deleted (unless "Delete on Termination" is disabled). This cannot be undone — the instance cannot be recovered.

AWS Console steps (all four actions)

  1. Go to EC2 → Instances.
  2. Select the checkbox next to your instance.
  3. Click Instance state at the top.
  4. Choose Stop instance, Start instance, Reboot instance, or Terminate instance.
  5. Confirm the action in the popup dialog.
ActionData Kept?Public IPReversible?
StopYesChanges on next startYes — can start again
RebootYesStays the sameN/A — instance keeps running
TerminateNo (root volume usually deleted)Released permanentlyNo — permanent

🌐 Public IP Behavior

Theory

By default, the normal Public IPv4 address assigned to an EC2 instance is not permanent — it changes every time the instance is stopped and then started again. Rebooting does not change it, but a full stop/start cycle does.

This is why an Elastic IP is used whenever you need a fixed public address — for example, if you've configured a domain name (DNS) to point to your server, or if other systems are hardcoded to connect to a specific IP.

💾 Create and Attach EBS Volume

Practical

What is EBS? Elastic Block Store is persistent, network-attached disk storage for EC2 instances.

Why additional storage? The default root volume may not be enough for application data, logs, or databases, so you attach a second volume dedicated to that data.

Same Availability Zone rule: An EBS volume physically lives inside one Availability Zone, so it can only be attached to an EC2 instance that is running in that same AZ.

  1. Go to EC2 → Elastic Block Store → Volumes.
  2. Click Create volume.
  3. Choose Volume type (e.g., gp3), Size, and the same Availability Zone as your EC2 instance.
  4. Click Create volume.
  5. Select the new volume, click Actions → Attach volume.
  6. Choose your EC2 instance and confirm the Device name (e.g., /dev/xvdf).
  7. Click Attach volume.

To confirm the disk is attached, connect to the instance and run:

lsblk

lsblk lists all block devices; the new volume will appear as an extra disk (e.g., xvdf) with no mount point yet — that's how you identify it.

🗂️ Format and Mount EBS Volume

Practical 
sudo mkfs -t xfs /dev/xvdf

sudo mkdir /data

sudo mount /dev/xvdf /data

df -h

sudo mkfs -t xfs /dev/xvdf — formats the raw new volume with the XFS filesystem so Linux can store files on it. This step is only needed once, on a brand-new empty volume.

sudo mkdir /data — creates an empty folder that will act as the access point for the new disk.

sudo mount /dev/xvdf /data — attaches ("mounts") the formatted volume to the /data folder, so anything saved inside /data is actually stored on the EBS volume.

df -h — confirms the mount worked by showing disk usage, including the new /data entry.

Note: The device name may differ from /dev/xvdf depending on your instance type. Always check the actual name first using lsblk before formatting or mounting.

📸 Create EBS Snapshot

Practical

What is a snapshot? A point-in-time backup copy of an EBS volume, stored in Amazon S3.

Why used? To protect data before risky changes, or to create identical volumes elsewhere.

Relation to EBS: A snapshot is taken *from* an EBS volume, and can later be used to *create* a brand-new EBS volume with the same data.

  1. Go to EC2 → Elastic Block Store → Volumes.
  2. Select the volume you want to back up.
  3. Click Actions → Create snapshot.
  4. Enter a description and click Create snapshot.
  5. View it under Elastic Block Store → Snapshots.

🖨️ Create AMI

Practical

What is an AMI? A complete, reusable template of an EC2 instance — its operating system, installed software, and configuration.

Why create a custom AMI? To quickly launch identical copies of a fully configured server, without repeating setup steps manually.

What's captured? The root volume (and any other attached volumes if selected), including the OS, installed packages, and files.

EC2 ↓ Instances ↓ Select Instance ↓ Actions ↓ Image and templates ↓ Create image
  1. Go to EC2 → Instances.
  2. Select the instance you want to capture.
  3. Click Actions → Image and templates → Create image.
  4. Enter an image name and description.
  5. Click Create image. It will appear under AMIs once ready.

🚀 Launch EC2 From AMI

Practical
  1. Go to EC2 → AMIs.
  2. Select your custom AMI.
  3. Click Launch instance from AMI.
  4. Fill in Instance Type, Key Pair, Security Group, and other settings just like a normal launch.
  5. Click Launch instance.

Launching from a custom AMI is useful because the new instance boots up already configured — no need to reinstall Apache, reconfigure settings, or redo setup steps.

📋 Create Launch Template

Practical

What is a Launch Template? A saved configuration blueprint (AMI, instance type, key pair, security group, etc.) that can be reused to launch instances quickly and consistently.

Why useful? Instead of re-entering every setting each time, you launch straight from the saved template — essential for Auto Scaling and team consistency.

AMI vs Launch Template: An AMI is just the disk image (OS + software); a Launch Template additionally stores instance type, security group, key pair, and other launch settings around that AMI.

  1. Go to EC2 → Launch Templates.
  2. Click Create launch template.
  3. Enter a template name, choose the AMI, instance type, key pair, and security group.
  4. Click Create launch template.

🧬 Launch Multiple EC2 Instances

Practical

Once a Launch Template exists, you can select Number of instances when launching from it (or use it with an Auto Scaling Group) to create several servers with identical configuration in one action — useful for scaling an application quickly.

📌 Elastic IP

Practical
EC2 ↓ Elastic IPs ↓ Allocate Elastic IP ↓ Associate Elastic IP ↓ Select EC2 Instance
  1. Go to EC2 → Network & Security → Elastic IPs.
  2. Click Allocate Elastic IP address, then Allocate.
  3. Select the new address, click Actions → Associate Elastic IP address.
  4. Choose your EC2 instance and click Associate.

Use an Elastic IP whenever your server needs a permanent, unchanging public address — for example, when a domain name (DNS record) points to it.

📊 EC2 Monitoring

Theory Practical
  • CloudWatch — AWS's monitoring service that automatically collects metrics from EC2 instances.
  • CPU Utilization — Percentage of the instance's CPU capacity currently in use.
  • Network In / Network Out — Amount of data received and sent by the instance.
  • Status Checks — Automated health checks AWS runs to verify the instance and its host are functioning correctly.
  1. Go to EC2 → Instances and select your instance.
  2. Open the Monitoring tab to view CPU, network, and status check graphs.

🩺 EC2 Instance Status Checks

Theory
  • System status check — Monitors the AWS hardware/infrastructure hosting your instance (e.g., power, network, hardware issues on AWS's side).
  • Instance status check — Monitors your specific instance's software/network configuration (e.g., OS-level networking or kernel issues).

A failed status check generally means the instance is unreachable or unhealthy — for a beginner, this usually means the instance may need a reboot, or in rarer cases, AWS is resolving an underlying hardware issue.

🔒 EC2 Security Best Practices

Theory
⚠️ IMPORTANT
  • Do not expose SSH (port 22) to everyone unnecessarily.
  • Prefer My IP as the source for SSH rules when appropriate.
  • Use strong key-pair management — keep .pem files organized and backed up securely.
  • Never share your .pem private key files with anyone.
  • Do not hard-code passwords or secrets inside scripts or code.
  • Use IAM roles and policies properly instead of long-lived credentials.
  • Keep the operating system and packages updated regularly.
  • Open only the ports your application actually needs.
  • Use HTTPS (port 443) for any production website.
  • Stop or terminate unused resources to avoid unnecessary charges.

🧯 EC2 Troubleshooting

Practical

Cannot SSH into EC2

Check the following, in order:

  • Is the instance in a running state?
  • Is the Public IP correct and current?
  • Does the Security Group allow inbound port 22 from your IP?
  • Are you using the correct username (e.g., ec2-user)?
  • Are you pointing to the correct .pem file?
  • Is there a network/firewall issue on your own side blocking outbound SSH?

Website Not Opening

  • Is the instance running?
  • Is Apache running (sudo systemctl status httpd)?
  • Does the Security Group allow inbound port 80?
  • Are you using the correct Public IP?
  • Does /var/www/html/index.html actually exist?
  • Any other Security Group rule silently blocking the traffic?

Apache Not Running

sudo systemctl status httpd
sudo systemctl restart httpd

Check the status first to see the error, then restart the service to attempt recovery.

Check Port

sudo ss -tulpn

ss -tulpn lists all listening TCP/UDP ports along with the process using them — useful to confirm Apache is actually listening on port 80.

Check Apache Logs

sudo journalctl -u httpd

journalctl -u httpd shows the system log entries specifically for the httpd (Apache) service — helpful for spotting startup errors or crashes.

📏 Vertical Scaling

Theory
t3.micro ↓ t3.medium

Vertical scaling means changing an existing instance to a bigger (or smaller) instance type to give it more (or less) CPU and RAM — the same single server just becomes more powerful.

↔️ Horizontal Scaling

Theory
Load Balancer ↓ ┌────┼────┐ ↓ ↓ ↓ EC2 EC2 EC2

Horizontal scaling means adding more EC2 instances to share the workload, instead of making one instance bigger. This is useful because it spreads traffic across multiple servers, improving both performance and reliability — if one instance fails, the others keep serving traffic.

⚖️ EC2 + Load Balancer

Theory

A Load Balancer sits in front of multiple EC2 instances and distributes incoming traffic evenly across them. Users always connect to the Load Balancer's address, and it forwards each request to one of the healthy EC2 instances behind it — hiding the individual servers and making it easy to add or remove instances without affecting users.

📈 EC2 + Auto Scaling

Theory

What is Auto Scaling? A feature that automatically adds or removes EC2 instances based on demand (like CPU usage or traffic levels).

Why used? So your application can handle traffic spikes automatically, and save money by shrinking back down when traffic is low.

Low Traffic → Few EC2 Instances High Traffic → Auto Scaling adds more EC2 Instances Traffic drops → Auto Scaling removes extra instances

Auto Scaling works together with a Launch Template (to know exactly how to create new instances) and typically a Load Balancer (to distribute traffic across whatever instances currently exist).

🎯 EC2 Interview Questions

Interview Prep

Q: What is EC2?

A: A web service providing resizable virtual servers in the cloud.

Q: What is an EC2 instance?

A: One single virtual server created and run within EC2.

Q: What is an AMI?

A: A template containing an OS and optionally pre-installed software, used to launch instances.

Q: What is an Instance Type?

A: A configuration that defines the CPU, RAM, and network performance of an instance.

Q: What is a Key Pair?

A: A public/private key combination used for secure, passwordless login to an instance.

Q: What is a Security Group?

A: A virtual, instance-level firewall controlling inbound and outbound traffic.

Q: What is EBS?

A: Elastic Block Store — persistent block storage attached to EC2 instances.

Q: What is a Public IP?

A: An internet-reachable address assigned to the instance, usually changing on stop/start.

Q: What is a Private IP?

A: An internal address used for communication within the VPC.

Q: What is an Elastic IP?

A: A static, permanent public IP address you allocate and control.

Q: What is User Data?

A: A script that runs automatically the first time an instance boots, used to automate setup.

Q: Difference between Stop and Terminate?

A: Stop keeps the instance and data, reversible; Terminate permanently deletes it.

Q: Difference between Stop and Reboot?

A: Stop fully shuts the instance down; Reboot restarts the OS while the instance keeps running.

Q: Difference between AMI and Snapshot?

A: An AMI is a full instance template; a Snapshot is a backup of a single EBS volume.

Q: What is a Launch Template?

A: A saved, reusable configuration for launching EC2 instances consistently.

Q: What is an Availability Zone?

A: One isolated physical data center location within an AWS Region.

Q: What is an AWS Region?

A: A geographic area containing multiple Availability Zones.

Q: How do you connect to a Linux EC2 instance?

A: Via SSH using its Public IP and private key, or via EC2 Instance Connect from the browser.

Q: How do you host a website on EC2?

A: Install a web server (like Apache), place website files in its web root, and open port 80/443 in the Security Group.

Q: How do you troubleshoot an EC2 server that cannot be accessed?

A: Check instance state, Public IP, Security Group rules, correct username, and correct key file.

Q: Why is Port 22 used?

A: It's the standard port for SSH remote terminal access.

Q: Why is Port 80 used?

A: It's the standard port for unencrypted HTTP web traffic.

Q: Why is Port 443 used?

A: It's the standard port for encrypted HTTPS web traffic.

Q: What happens to Public IP after stopping an EC2 instance?

A: It's released and a new one is assigned when the instance is started again (unless an Elastic IP is attached).

Q: Why do we use Elastic IP?

A: To have a fixed, unchanging public address for the instance.

Q: What is vertical scaling?

A: Increasing the resources (CPU/RAM) of a single existing instance.

Q: What is horizontal scaling?

A: Adding more instances to share the workload.
