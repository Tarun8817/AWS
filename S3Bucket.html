AWS S3 — Complete Guide
AWS S3

Simple Storage Service

From basics to advanced — beginner-friendly and interview-ready

1️⃣ What is AWS S3?

Amazon S3 (Simple Storage Service) is an AWS object storage service used to store and retrieve files/data from anywhere over the internet.

S3 is used to store all kinds of files, such as:

  • Images
  • Videos
  • Documents
  • PDFs
  • Backups
  • Logs
  • Static website files
  • Application files
  • Data archives
Local Computer ↓ S3 ↓ Images / Videos / PDFs / Backups
Real-world example

Imagine your phone has 1,000 photos and storage is running out. You can upload them all to S3 — now they're accessible from anywhere over the internet, and your phone's storage is freed up.

💡 Why Do We Use S3?

  • File storage — storing any kind of file
  • Backup — keeping backups of important data
  • Static website hosting — serving HTML/CSS/JS files
  • Application data storage — storing app uploads and media
  • Log storage — keeping server/application logs
  • Data lakes — storing large-scale analytics data
  • Media storage — images, videos, audio
  • Disaster recovery — a safe copy of critical data
  • Sharing files — sharing data via links
  • Storing build/deployment files — CI/CD artifacts

S3 differs from storing files directly on an EC2 server because S3 is durable, highly scalable, and independent of any EC2 instance — if the EC2 instance is deleted or fails, data in S3 stays safe. S3 offers practically unlimited storage, while an EC2 instance's disk is limited.

🧩 Important S3 Terms

Bucket

Bucket is a container in S3 where objects/files are stored.
S3 ↓ Bucket ↓ Files / Objects

Object

Object is the actual file stored inside an S3 bucket.
photo.jpg resume.pdf video.mp4 index.html

An S3 object consists of data (the actual file content) plus metadata (such as content type, size, custom tags), and every object has a unique key.

Object Key

The object key is the name/path used to identify an object inside a bucket.

images/profile.jpg documents/resume.pdf

Region

An S3 bucket is created in a specific AWS Region — data is stored in that Region's data centers.

Prefix

images/ documents/ videos/ backups/

S3 actually uses a flat object namespace — meaning there are no real "folders" underneath. A prefix like images/ looks like a folder in the console, but it's really just part of the object key string.

🏗️ S3 Basic Structure

AWS Account ↓ S3 ↓ Bucket ↓ Objects ↓ Files

Example:

my-company-bucket
│
├── images/
│   ├── logo.png
│   └── profile.jpg
│
├── documents/
│   ├── resume.pdf
│   └── report.pdf
│
└── backups/
    └── backup.zip
  • my-company-bucket — this is the whole bucket.
  • images/, documents/, backups/ — these are "prefixes" that look like folders.
  • logo.png, resume.pdf, backup.zip — these are the actual objects (files).

🛠️ How to Create an S3 Bucket Using AWS Console

  1. Open the AWS Management Console.
  2. Search for S3.
  3. Open Amazon S3.
  4. Click Create bucket.
  5. Enter a globally unique bucket name.
  6. Select the AWS Region.
  7. Configure Object Ownership.
  8. Configure Block Public Access settings.
  9. Configure Bucket Versioning if required.
  10. Configure Tags if required.
  11. Configure Default Encryption.
  12. Review the configuration.
  13. Click Create bucket.
  14. Open the newly created bucket.
  • Bucket name — must be globally unique across all of AWS.
  • Region — determines where the data is physically stored.
  • Object Ownership — decides how object access control is managed (Bucket owner enforced is recommended).
  • Block Public Access — by default keeps everything private/blocked unless explicitly changed.
  • Versioning — keeps multiple versions of an object.
  • Default Encryption — automatically encrypts all files placed in the bucket.

📛 S3 Bucket Naming Rules

  • Bucket name must be globally unique (across all of AWS, not just your account).
  • Use lowercase letters.
  • Avoid spaces.
  • Use numbers and hyphens where appropriate.
  • Bucket names should follow AWS's naming requirements.

Valid examples:

tarun-demo-bucket-2026 my-company-files-123
Invalid examples and why:
  • My_Bucket_Name — uppercase letters and underscores aren't allowed.
  • my bucket — spaces aren't allowed.
  • bucket..name — consecutive periods aren't allowed.
  • A name like 192.168.1.1 — names in IP address format aren't allowed.

🏷️ S3 Storage Classes

S3 Standard

For frequently accessed data — with high durability and availability.

S3 Intelligent-Tiering

When access patterns are unknown or changing — S3 automatically moves data to a cost-effective tier.

S3 Standard-IA

For infrequently accessed data that needs multi-AZ resilience.

S3 One Zone-IA

For infrequently accessed data that can tolerate single-AZ storage (slightly less durable, slightly cheaper).

S3 Glacier Instant Retrieval

Archive data that needs fast retrieval (millisecond access).

S3 Glacier Flexible Retrieval

Long-term archive with flexible retrieval time (minutes to hours).

S3 Glacier Deep Archive

For very long-term archives — the cheapest storage, but retrieval takes longer (hours).

🔄 S3 Versioning

Versioning keeps multiple versions of an object in the same bucket.

The problem without versioning:

file.txt ↓ Updated ↓ Old file may be overwritten

With versioning:

file.txt ↓ Version 1 Version 2 Version 3
  • Accidental deletion protection
  • Accidental overwrite protection
  • Recovery of previous versions
  1. Open S3.
  2. Select the bucket.
  3. Go to Properties.
  4. Find Bucket Versioning.
  5. Click Edit.
  6. Enable Versioning.
  7. Save changes.

To view/restore previous versions, select the object inside the bucket and toggle "Show versions" — from there you can download or restore an older version.

🏷️ S3 Bucket Versioning and Delete Markers

When versioning is enabled and an object is deleted normally, S3 places a delete marker instead of permanently removing it.

Object ↓ Delete ↓ Delete Marker ↓ Previous Version still exists

To permanently delete a particular object version, enable "Show versions," select that specific version ID, and delete it explicitly — only then is that version removed for good.

🔐 S3 Encryption

Encryption is important because it ensures data — even at rest (in storage) — stays protected from unauthorized access.

Server-Side Encryption

  • SSE-S3 — AWS manages the encryption keys itself; the simple, default option.
  • SSE-KMS — uses AWS KMS (Key Management Service), giving extra control and audit logging over key usage.
  • DSSE-KMS — dual-layer server-side encryption with KMS, for extra-sensitive data.

SSE-S3 vs SSE-KMS: SSE-S3 is simpler — AWS manages everything automatically. SSE-KMS gives you more control (who can use the keys, key rotation, detailed audit trail), but involves a bit more configuration and cost.

User ↓ Upload File ↓ S3 ↓ Encrypted at Rest

With client-side encryption, the client (application) encrypts data itself before uploading — S3 only stores the already-encrypted data.

🚫 S3 Block Public Access

Block Public Access helps prevent unintended public access to S3 buckets and objects.

It has four high-level settings that control:

  • Whether new ACLs granting public access are allowed
  • Whether any ACLs granting public access are allowed
  • Whether new public bucket policies are allowed
  • Whether public access is blocked via bucket policies, including cross-account access

Public access should normally remain blocked unless there's a specific requirement (such as static website hosting).

Private Bucket ↓ Only authorized users/services ↓ Access S3 Objects

Public website hosting is a special use case that should be configured deliberately and thoughtfully — accidental public exposure can leak sensitive data.

📜 S3 Bucket Policy

Bucket Policy is a resource-based JSON policy attached to an S3 bucket that controls access to the bucket and its objects.
  • Principal — who (user/account/service) the policy affects
  • Action — which operation (such as s3:GetObject) is allowed/denied
  • Resource — which bucket/object the policy applies to
  • Effect — Allow or Deny
  • Condition — additional rules that are checked before the policy applies
Keep in mind: whenever using a policy example, placeholder bucket names/ARNs must be replaced with your actual values.

IAM Policy vs Bucket Policy: An IAM Policy is attached to an identity (user/role/group) and defines what that identity can do. A Bucket Policy is attached to a resource (the bucket) and defines who can access that bucket — regardless of which identity the request comes from.

🔗 IAM + S3

IAM users, roles, and policies are used to control access to S3.

EC2 ↓ IAM Role ↓ IAM Policy ↓ S3 Bucket ↓ Object

Attaching an IAM Role to an EC2 instance is generally preferable to placing long-lived AWS access keys on it, because:

  • Keys are never hardcoded or leaked
  • Credentials rotate automatically
  • Access can be easily revoked or modified
Practical example

An EC2 server needs to upload application backups to S3. Recommended architecture: EC2 → IAM Role (with S3 upload permission) → Permission → S3. This way, no access key needs to be stored in the server's code.

🔑 S3 Access Control

  • IAM policies — identity-based permissions
  • Bucket policies — resource-based permissions
  • Block Public Access — prevents accidental public exposure
  • Object Ownership — decides whether the bucket owner or the uploader controls the object
  • ACLs — a legacy access control mechanism

Modern S3 configurations generally use Bucket owner enforced Object Ownership and avoid ACL-based access control unless a specific legacy/integration requirement exists — this makes access management simpler and more secure.

🌐 S3 Static Website Hosting

S3 can host static websites containing HTML, CSS, JavaScript, images, and other static assets.
index.html style.css script.js images/
  1. Create a bucket.
  2. Upload website files.
  3. Configure static website hosting.
  4. Set the index document.
  5. Configure access appropriately.
  6. Test the website endpoint.

It's important to understand the security implications of public access — enabling website hosting requires making the bucket's contents publicly readable, so only website files should be in this bucket, never sensitive data. For a production public website, CloudFront + S3 is commonly used, where access is configured so the bucket itself doesn't need to be publicly readable — only CloudFront fetches files from S3.

🚀 S3 + CloudFront

User ↓ CloudFront ↓ S3 Bucket ↓ Website Files
  • CDN — content is served from globally distributed edge locations
  • Lower latency — content is served from closer to the user
  • Caching — repeated requests are faster
  • HTTPS — an encrypted connection is easy to enable
  • Global distribution — fast access worldwide
  • Reduced direct access to S3 — less need to expose S3 publicly

The modern recommended pattern is to use CloudFront with restricted access to S3 — meaning only CloudFront can access the S3 bucket, and the general public cannot access the bucket directly.

♻️ S3 Lifecycle Rules

Lifecycle rules automatically transition or expire objects based on defined conditions.
Day 0 ↓ S3 Standard After 30 days ↓ Infrequent Access After 90 days ↓ Glacier After 365 days ↓ Delete
  1. Open the bucket.
  2. Go to Management.
  3. Click Create lifecycle rule.
  4. Enter a rule name.
  5. Select the scope/filter.
  6. Configure transitions.
  7. Configure expiration if required.
  8. Review.
  9. Create the rule.

Lifecycle rules help reduce storage costs and automate data management — old, rarely-accessed files automatically move to cheaper storage classes, and can also expire (be deleted) if no longer needed.

🔁 S3 Replication

Same-Region Replication (SRR)

Used when replicating objects between buckets in the same AWS Region.

Cross-Region Replication (CRR)

Used when replicating objects between buckets in different AWS Regions.

Bucket A ↓ Replication ↓ Bucket B
  • Disaster recovery
  • Compliance
  • Data locality
  • Backup
  • Multi-region architectures

Important prerequisite: both the source and destination buckets must have versioning enabled for replication to work.

🔒 S3 Object Lock

S3 Object Lock helps prevent objects from being deleted or overwritten for a defined retention period or until a legal hold is removed.
  • Retention period — how long the object stays protected
  • Governance mode — can be overridden with special permissions
  • Compliance mode — cannot be overridden by anyone during the retention period, not even the root user
  • Legal hold — independent of retention period, stays locked until explicitly removed
Real-world example

A company's financial records must not be modified or deleted for 7 years per regulation. Enabling Object Lock (Compliance mode) guarantees that no one — accidentally or intentionally — can delete or overwrite those records.

🔗 S3 Presigned URL

A presigned URL provides temporary access to a specific S3 object without making the object publicly accessible.
Private S3 Object ↓ Presigned URL ↓ Temporary Access
  • Private file downloads
  • User uploads — uploading directly to S3 without routing the file through an application server
  • Temporary sharing
  • Application file access

Every presigned URL has an expiration time — after that time, the URL stops working, so the object is never permanently exposed publicly.

📦 S3 Multipart Upload

Large files can be uploaded in multiple parts.

Large File ↓ Part 1 Part 2 Part 3 Part 4 ↓ S3 ↓ Complete Object
  • Better handling of large files — breaking a big file into smaller parts makes uploading easier
  • Parallel uploads — multiple parts can be uploaded simultaneously, increasing speed
  • Ability to retry failed parts — if one part fails, only that part needs to be re-uploaded, not the whole file

💻 S3 CLI Commands

List buckets

aws s3 ls

Lists all S3 buckets in the account.

Create bucket

The exact syntax for creating a bucket can vary slightly by Region; the recommended approach is to follow the AWS Console or the current AWS CLI documentation for the correct Region-specific syntax.

List objects

aws s3 ls s3://BUCKET-NAME

Lists the objects inside a specific bucket.

Upload file

aws s3 cp file.txt s3://BUCKET-NAME/

Uploads a local file to an S3 bucket.

Download file

aws s3 cp s3://BUCKET-NAME/file.txt .

Downloads a file from S3 to the current directory.

Upload folder

aws s3 cp ./my-folder s3://BUCKET-NAME/my-folder/ --recursive

The --recursive flag uploads the entire folder along with all files/subfolders inside it.

Download folder

aws s3 cp s3://BUCKET-NAME/my-folder ./my-folder --recursive

Downloads an entire folder from S3 to the local machine.

Sync local folder with S3

aws s3 sync ./website s3://BUCKET-NAME/

Syncs a local folder with an S3 bucket — only changed/new files are uploaded, so the whole folder doesn't need to be re-uploaded.

Delete object

aws s3 rm s3://BUCKET-NAME/file.txt

Deletes a specific object from S3.

Delete bucket contents

Important: deleting all objects in a bucket and deleting the bucket itself are two different operations. The command below only deletes contents, not the bucket. 
aws s3 rm s3://BUCKET-NAME --recursive

⚙️ AWS CLI Configuration

aws configure
  • AWS Access Key ID — the public part of your identity
  • AWS Secret Access Key — the secret/private part of your identity
  • Default Region — which Region commands run in by default
  • Output format — how CLI output is displayed (json, text, table)
⚠️ Security Best Practice

Never hard-code or share AWS access keys. For EC2 instances, using an IAM role instead of storing long-lived access keys is the preferred approach.

📄 S3 Bucket Policy Example

A simple JSON example for educational purposes:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::BUCKET-NAME/*"
    }
  ]
}
⚠️ Important
  • This example allows public object read access.
  • It should NOT be used blindly.
  • Public access should only be enabled when intentionally required.
  • Replace BUCKET-NAME with the actual bucket name.
  • Keep Block Public Access enabled for private buckets.

🧯 S3 Permissions Troubleshooting

AccessDenied Error

Possible reasons:

  • IAM policy missing
  • Bucket policy denies access
  • Block Public Access is enabled
  • Wrong bucket/object ARN
  • Request coming from the wrong AWS account
  • Incorrect IAM role attached
  • Object ownership/access configuration mismatch
Request ↓ IAM permissions? ↓ Bucket policy? ↓ Block Public Access? ↓ Object Ownership / ACL? ↓ Correct resource ARN?

✅ S3 Security Best Practices

⚠️ IMPORTANT
  • Keep Block Public Access enabled unless public access is explicitly required.
  • Use least-privilege IAM permissions.
  • Use encryption.
  • Enable versioning for important data.
  • Use lifecycle rules.
  • Use CloudTrail/data events where appropriate for auditing.
  • Avoid storing secrets directly in S3.
  • Use presigned URLs for temporary access.
  • Use IAM roles instead of long-lived credentials.
  • Consider Object Lock for immutable backup/compliance use cases.
  • Monitor unexpected access and configuration changes.

⚖️ S3 vs EBS vs EFS

FeatureS3EBSEFS
TypeObject storageBlock storageFile storage
Attached to EC2NoYesCan be mounted
AccessAPI/HTTPBlock deviceFile system
Use caseFiles/backupsEC2 diskShared file system
ScalabilityVery highVolume-basedElastic
Typical exampleImages/backupsOS/database diskShared application files

When to use each: use S3 for independent, durable object storage (files, backups, media); use EBS for a single EC2 instance's dedicated disk (OS, database); use EFS when you need a shared file system across multiple EC2 instances.

🆚 S3 vs EC2 Storage

EC2 storage

EC2 ↓ EBS ↓ Application Files

S3

Application ↓ S3 API ↓ Bucket ↓ Object

S3 is useful for durable object storage that remains independent of the EC2 instance — if the instance is terminated, data stored in S3 stays safe. By comparison, an EBS volume is generally tightly linked to one specific EC2 instance.

💰 S3 Cost Concepts

  • Storage amount — how much data is stored
  • Storage class — Standard, IA, Glacier, etc.
  • Number/type of requests — the count of GET, PUT, LIST, and similar requests
  • Data retrieval — especially retrieving data from classes like Glacier
  • Data transfer — sending data from S3 to the internet
  • Replication — keeping extra copies
  • Lifecycle transitions — moving from one storage class to another
  • Monitoring/analytics features
Note: this document doesn't claim specific outdated prices, since AWS pricing changes over time — always verify current pricing on AWS's official pricing page. Different storage classes have different storage and retrieval economics.

🏗️ Practical Project: Upload Website Backup to S3

Scenario: An EC2 Apache server has /var/www/html.

Create a backup/archive:

sudo tar -czf website-backup.tar.gz /var/www/html

tar — compresses files/folders into a single archive file.

-czf — c (create), z (gzip compression), f (specify the output filename).

website-backup.tar.gz — the name of the output archive file.

Then upload it:

aws s3 cp website-backup.tar.gz s3://BUCKET-NAME/backups/

This command uploads the local archive file into the backups/ prefix inside the S3 bucket. For this to work, the EC2 instance needs appropriate permissions to upload to S3 — preferably through an IAM role, rather than hardcoded access keys.

🎯 Important S3 Interview Questions

Q1: What is Amazon S3?

A: An AWS object storage service for storing and retrieving files/data over the internet.

Q2: What is an S3 bucket?

A: A container where S3 objects/files are stored.

Q3: What is an S3 object?

A: The actual file stored inside a bucket, along with its metadata.

Q4: What is an object key?

A: The name/path used to identify an object inside a bucket.

Q5: Is S3 a file system?

A: No — S3 is a flat object storage, not a traditional hierarchical file system.

Q6: What are S3 storage classes?

A: Storage tiers for different access-pattern/cost trade-offs — such as Standard, IA, Glacier.

Q7: What is S3 Versioning?

A: A feature that keeps multiple versions of an object in the same bucket.

Q8: What is a delete marker?

A: A marker placed on a normal delete in a versioned bucket, while the previous version still exists.

Q9: What is S3 Lifecycle?

A: Rules that automatically transition objects to a different storage class or expire them.

Q10: What is S3 Bucket Policy?

A: A resource-based JSON policy that controls access to a bucket.

Q11: What is an IAM Policy?

A: An identity-based policy defining what a user/role/group can do.

Q12: Difference between IAM Policy and Bucket Policy?

A: An IAM Policy attaches to an identity; a Bucket Policy attaches to a resource (bucket).

Q13: What is Block Public Access?

A: A setting that protects a bucket/objects from accidental public exposure.

Q14: What is S3 encryption?

A: A mechanism to protect data at rest (in storage) — server-side or client-side.

Q15: Difference between SSE-S3 and SSE-KMS?

A: SSE-S3 has AWS manage the keys itself; SSE-KMS uses KMS with extra control and audit logging.

Q16: What is S3 Static Website Hosting?

A: An S3 feature that lets it serve static files like HTML/CSS/JS directly as a website.

Q17: What is a presigned URL?

A: A temporary URL that allows access to a private S3 object without exposing it publicly.

Q18: What is S3 Replication?

A: A feature that automatically copies objects from one bucket to another.

Q19: Difference between SRR and CRR?

A: SRR replicates between buckets in the same Region; CRR replicates across different Regions.

Q20: What is S3 Object Lock?

A: A feature that prevents objects from being deleted/overwritten for a retention period.

Q21: What is Multipart Upload?

A: A method of uploading large files in multiple parts, improving reliability and speed.

Q22: What is S3 Versioning used for?

A: Protection against accidental delete/overwrite, and recovering previous versions.

Q23: How do you upload a file using AWS CLI?

A: Using the command aws s3 cp file.txt s3://BUCKET-NAME/.

Q24: How do you download an S3 object using CLI?

A: Using the command aws s3 cp s3://BUCKET-NAME/file.txt ..

Q25: How does EC2 access S3?

A: Generally through an IAM Role attached to the EC2 instance.

Q26: Why should we use IAM Roles with EC2?

A: Because they're more secure than storing long-lived access keys — credentials are temporary and auto-rotating.

Q27: What happens when Block Public Access is enabled?

A: Policies/ACLs that would make the bucket/objects public are effectively blocked, unless deliberately allowed.

Q28: Why use CloudFront with S3?

A: For better performance (CDN, caching, lower latency), HTTPS, and reducing S3's direct public exposure.

Q29: Difference between S3, EBS, and EFS?

A: S3 is object storage (independent), EBS is block storage (attached to one EC2), EFS is shared file storage (mountable across multiple EC2s).

Q30: How can S3 be used for backups?

A: By archiving application/server data and uploading it to S3, with versioning/lifecycle.

Q31: How can S3 help with disaster recovery?

A: Through cross-region replication, keeping data durable in another Region too.

Q32: What happens if an object is deleted from a versioned bucket?

A: A delete marker is added, and previous version(s) still exist until explicitly permanently deleted.

Q33: What causes an S3 AccessDenied error?

A: Missing IAM permission, a restrictive bucket policy, Block Public Access, wrong ARN, or wrong account/role.

Q34: How can you make an S3 object temporarily accessible?

A: By generating a presigned URL, which has an expiration time.

Q35: How can you reduce S3 storage costs?

A: By using lifecycle rules to move data to cheaper storage classes or expire it.
