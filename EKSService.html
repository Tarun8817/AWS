AWS EKS

Elastic Kubernetes Service

"Run, Deploy, Scale and Manage Kubernetes Applications on AWS"

1. Introduction to Amazon EKS Theory

Simple Definition:
"Amazon EKS (Elastic Kubernetes Service) is a managed AWS service that allows us to run, operate, and scale Kubernetes clusters in the AWS cloud without having to install and operate our own Kubernetes control plane."

Core Concepts Explained in Plain English:

  • AWS (Amazon Web Services): The world's leading cloud computing platform providing scalable on-demand infrastructure.
  • Docker / Container: A standardized unit of software that packages application code and all its dependencies so the app runs quickly and reliably across different computing environments.
  • Container Orchestration: The automated management of container lifecycles — handling provisioning, deployment, scaling, load balancing, networking, and self-healing.
  • Kubernetes (K8s): The industry-standard open-source container orchestration engine originally developed by Google.
  • Amazon EKS: Fully managed upstream-certified Kubernetes on AWS with built-in integrations for IAM, VPC, ALB, ECR, and CloudWatch.
  • Kubernetes Cluster: A set of worker machines (nodes) that run containerized applications managed by a central control plane.

The Problem of Managing Containers Manually:

WITHOUT KUBERNETES / EKS: Developer ──> Launch EC2 ──> SSH ──> docker run ──> Container [Problems: If container crashes at 2 AM, it stays dead. Scaling requires manual server setup. Rolling updates cause downtime.] WITH KUBERNETES & EKS: Developer ──> kubectl apply ──> Amazon EKS Control Plane ──> Pods / Nodes ──> Highly Available Application [Benefits: Automatic self-healing, zero-downtime rolling updates, automatic horizontal scaling, native load balancing.]

2 & 3. What is Kubernetes & Why Do We Need It? Theory

Kubernetes (often abbreviated as K8s) is an open-source container orchestration platform designed to automate deploying, scaling, and operating application containers.

What Kubernetes Does Automatically:

1. Automated Deployments: Roll out new versions of applications smoothly with zero downtime.
2. Self-Healing: Automatically restarts failed containers, replaces unhealthy pods, and kills unresponsive containers.
3. Horizontal Scaling: Automatically scales pod replicas up or down based on CPU, memory, or custom traffic metrics.
4. Service Discovery & Load Balancing: Assigns individual IP addresses to Pods and provides single DNS names for groups of pods.
5. Configuration & Secret Management: Deploys and updates secrets and application config without rebuilding container images.
6. Storage Orchestration: Automatically mounts local, cloud, or network storage systems (EBS, EFS).
MANAGING CONTAINERS AT SCALE: 1 Container: Easily managed with simple Docker CLI. 10 Containers: Port conflicts, monitoring headaches, manual restart on failures. 100+ Pods: Impossible to manage manually! Requires automated scheduling, multi-node networking, ingress routing, and autoscaling.

5, 6, 7. EKS Architecture: Control Plane & Data Plane Architecture

================================== AMAZON EKS ARCHITECTURE ================================== [ AWS MANAGED CONTROL PLANE ] (Highly Available across 3 AZs) ┌────────────────────────────────────────────────────────────────────────┐ │ │ │ [ kube-apiserver ] ◄──── kubectl / eksctl commands │ │ │ │ │ ├────────► [ kube-scheduler ] (Assigns Pods to healthy Nodes) │ │ ├────────► [ kube-controller-manager ] (Maintains desired state)│ │ └────────► [ etcd ] (Encrypted key-value database of cluster) │ │ │ └───────────────────────────────────┬────────────────────────────────────┘ │ Secure TLS Tunnel [ CUSTOMER DATA PLANE / WORKER NODES ] ┌───────────────────────────────────┴────────────────────────────────────┐ │ │ │ ┌──────────────────────────────┐ ┌──────────────────────────────┐ │ │ │ WORKER NODE 1 (EC2 / Spot) │ │ WORKER NODE 2 (EC2 / Spot) │ │ │ │ ┌────────────────────────┐ │ │ ┌────────────────────────┐ │ │ │ │ │ kubelet & kube-proxy │ │ │ │ kubelet & kube-proxy │ │ │ │ │ ├────────────────────────┤ │ │ ├────────────────────────┤ │ │ │ │ │ Container Runtime │ │ │ │ Container Runtime │ │ │ │ │ │ (containerd) │ │ │ │ (containerd) │ │ │ │ │ ├────────────────────────┤ │ │ ├────────────────────────┤ │ │ │ │ │ [ Pod A ] [ Pod B ] │ │ │ │ [ Pod C ] [ Pod D ] │ │ │ │ │ │ (Node.js) (React) │ │ │ │ (Express) (Nginx) │ │ │ │ │ └────────────────────────┘ │ │ └────────────────────────┘ │ │ │ └──────────────────────────────┘ └──────────────────────────────┘ │ │ │ └────────────────────────────────────────────────────────────────────────┘ =============================================================================================

Control Plane Components:

  • kube-apiserver: The central frontend for the Kubernetes control plane. Exposes the Kubernetes API and handles all authentication/authorization.
  • etcd: Consistent and highly-available key-value store used as Kubernetes' backing store for all cluster data and state.
  • kube-scheduler: Watches for newly created Pods with no assigned node, and selects a worker node for them to run on.
  • kube-controller-manager: Runs controller loops (Node controller, Job controller, EndpointSlice controller, ServiceAccount controller).

Data Plane (Worker Node) Components:

  • Kubelet: An agent that runs on each node in the cluster, ensuring containers described in PodSpecs are running and healthy.
  • Kube-proxy: A network proxy that runs on each node, maintaining network rules that allow network communication to Pods.
  • Container Runtime: The software responsible for running containers (e.g., containerd).

9 to 15. Pods, Deployments, Services, Ingress, Namespaces, ConfigMaps & Secrets Core Concepts

1. Pod: The Atomic Unit

A Pod encapsulates one or more containers (such as Docker containers), storage resources, a unique network IP, and options that govern how the container(s) should run.

Important Rule: In production, you almost never create standalone Pods directly using kind: Pod. You create Deployments which manage Pods automatically to provide self-healing and replication!

2. Deployment: Desired State Manager

DEPLOYMENT HIERARCHY: Deployment (Defines desired state: 3 replicas, image v1.2) │ ▼ ReplicaSet (Ensures exact count of 3 Pods are active) │ ├──────────────┬──────────────┐ ▼ ▼ ▼ [ Pod 1 ] [ Pod 2 ] [ Pod 3 ]

3. Kubernetes Service Types

Pods are ephemeral (their IP addresses change when they restart). A Service provides a single, unchanging IP address and DNS name to route traffic to a group of dynamic Pods.

Service Type How It Works Accessibility Primary Use Case
ClusterIP (Default)Exposes the Service on an internal IP in the cluster.Internal only.Backend APIs, internal databases, microservices communication.
NodePortExposes Service on each Node's IP at a static port (30000-32767).External via Node IP:Port.Direct debugging, legacy infrastructure integration.
LoadBalancerProvisions a cloud load balancer (AWS NLB/CLB) pointing to the Service.Public Internet.Exposing individual production services directly to the web.
ExternalNameMaps Service to a DNS name (CNAME record).DNS alias.Routing to external RDS database endpoint.

4. Ingress vs Service

While a LoadBalancer service creates 1 separate AWS Load Balancer for each service (costly!), an Ingress routes multiple services through a single Application Load Balancer (ALB) using host-based and path-based routing rules.

INGRESS ROUTING: https://app.example.com/api ───► [ ALB Ingress ] ───► Backend Service ───► Backend Pods https://app.example.com/web ───► [ ALB Ingress ] ───► Frontend Service ──► Frontend Pods

EKS VPC Networking & CNI:

EKS uses the Amazon VPC CNI plugin. Unlike traditional overlay networks where Pods have private overlay IPs that require NAT, the VPC CNI assigns real, routable IP addresses directly from your AWS VPC subnets to each Pod!

Option A: Fast Automated Cluster Creation via eksctl

eksctl is the official CLI tool by AWS and Weaveworks that automates VPC, Subnet, IAM, NAT Gateway, Control Plane, and Managed Node Group creation in a single command.
Bash / PowerShell
# Create standard 2-node managed cluster (Takes ~10-15 minutes)
eksctl create cluster \
  --name eks-demo-cluster \
  --region YOUR-REGION \
  --nodegroup-name standard-workers \
  --node-type t3.medium \
  --nodes 2 \
  --nodes-min 1 \
  --nodes-max 4 \
  --managed

Option B: AWS Console Steps (Manual):

  1. Open AWS Console -> Search EKS -> Click Add cluster -> Create.
  2. Name: eks-demo-cluster, Kubernetes version: Latest supported (e.g. 1.30), Cluster Service IAM Role: eksClusterRole.
  3. Specify VPC and select at least 2 public and 2 private subnets across multiple AZs.
  4. Cluster endpoint access: Public and Private.
  5. After cluster becomes ACTIVE, navigate to Compute tab -> Add Node Group -> Attach node IAM role, select t3.medium, desired size 2.

Configuring kubeconfig & Verifying Nodes:

Bash / PowerShell
# Update local kubeconfig to connect kubectl to your EKS cluster
aws eks update-kubeconfig --region YOUR-REGION --name eks-demo-cluster

# Verify nodes are in Ready status
kubectl get nodes -o wide

61, 62, 63. Troubleshooting 20 Common EKS Errors Troubleshooting

Error / Status Possible Root Cause Diagnostic Command How to Fix
CrashLoopBackOff App crashing immediately on startup (syntax error, missing env var, DB connection fail). kubectl logs <pod> Fix application runtime errors or inject missing ConfigMaps/Secrets.
ImagePullBackOff / ErrImagePull Incorrect ECR image URI, tag typo, or node IAM role missing ECR pull permissions. kubectl describe pod <pod> Verify image URI and ensure AmazonEC2ContainerRegistryReadOnly is on node IAM role.
Pending Pods Insufficient CPU/memory capacity on worker nodes, or no nodes matching nodeSelector. kubectl describe pod <pod> Add more worker nodes, scale node group, or decrease container resource requests.
CreateContainerConfigError Referenced ConfigMap or Secret does not exist in the same namespace. kubectl describe pod <pod> Create the missing ConfigMap or Secret object.
ALB Target Unhealthy (502 / 504) Health check path returning non-200 status, or Security Group blocking ALB to node traffic. Target Group Console / kubectl logs Configure correct /health path and allow inbound traffic from ALB security group.

75 & 76. 30-Step End-to-End Practical EKS Project Capstone Project

Follow this checklist to build and deploy a production-grade Kubernetes application on Amazon EKS from scratch:

  1. Create Node.js application (server.js and package.json).
  2. Create production multi-stage Dockerfile.
  3. Build local Docker image: docker build -t eks-demo ..
  4. Test container locally at http://localhost:3000.
  5. Create Amazon ECR private repository named eks-demo.
  6. Authenticate Docker with ECR via aws ecr get-login-password.
  7. Tag image with full ECR repository URI.

82. 50+ EKS Interview Questions & Answers Interview Q&A

# Interview Question Short, Precise & Technical Answer
1What is Amazon EKS?A managed AWS service that runs open-source Kubernetes clusters with automated control plane management.
2What is Kubernetes?An open-source container orchestration engine that automates container deployment, scaling, and operations.
3What is a Pod?The smallest deployable unit in Kubernetes representing one or more co-located containers sharing storage and network.
4What is a Deployment?A declarative controller that manages ReplicaSets and provides declarative updates for Pods.
5What is a ReplicaSet?A controller that ensures a specified number of identical Pod replicas are running at any given time.
6What is a Kubernetes Service?An abstraction that defines a logical set of Pods and a policy to access them via stable IP/DNS.
7ClusterIP vs NodePort vs LoadBalancer?ClusterIP = internal only; NodePort = exposes on node static port; LoadBalancer = creates cloud load balancer (ALB/NLB).
8What is Ingress?An API object that manages external HTTP/HTTPS routing into cluster services using host/path rules.
9What is ConfigMap vs Secret?ConfigMap stores plain configuration data; Secret stores base64-encoded sensitive information.
10What is a Namespace?A virtual cluster partition used for resource isolation and multi-tenancy within the same physical cluster.
11What is Kubelet?The node agent responsible for registering nodes and ensuring containers described in PodSpecs are running.
12What is kube-proxy?A network proxy running on each node that maintains network routing rules for Service communication.
13What is etcd?A distributed, consistent key-value store used as the single source of truth for all Kubernetes cluster state.
14What is kube-scheduler?The control plane component that assigns unscheduled Pods to suitable worker nodes based on resource availability.
15What is kube-controller-manager?A daemon that embeds core control loops regulating the state of the cluster.
16What is Amazon VPC CNI?AWS networking plugin that assigns real VPC IP addresses directly to Kubernetes Pods.
17What is IRSA?IAM Roles for Service Accounts; maps Kubernetes service accounts to AWS IAM roles using OpenID Connect (OIDC).
18What is EKS Pod Identity?A modern, simplified mechanism to grant AWS IAM permissions directly to Pods without managing OIDC providers.
19What is an EKS Managed Node Group?An EC2 auto scaling group whose lifecycle, provisioning, and AMI updates are automated by AWS EKS.
20What is EKS on AWS Fargate?Serverless compute for EKS where each Pod runs on its own dedicated, isolated microVM without managing EC2 nodes.
21What is EKS Auto Mode?An AWS feature that automatically sizes, provisions, and scales node infrastructure dynamically based on pod requirements.
22What is Horizontal Pod Autoscaler (HPA)?Autoscaler that adjusts the number of pod replicas based on observed CPU/memory utilization.
23What is Cluster Autoscaler / Karpenter?Tools that automatically add or remove worker nodes when Pods cannot be scheduled due to lack of resources.
24What is CrashLoopBackOff?A status indicating that a container starts, encounters a fatal error/crash, and Kubernetes repeatedly retries restarting it.
25What is ImagePullBackOff?A status indicating Kubernetes cannot pull the container image due to invalid URI, missing tag, or authorization failure.
26How do you troubleshoot a Pending Pod?Run kubectl describe pod <name> to check Events for resource shortages or node affinity mismatches.
27How do you view previous container crash logs?Run kubectl logs <pod-name> --previous.
28What is a Liveness Probe?Health check that indicates if a container is running; if it fails, kubelet kills and restarts the container.
29What is a Readiness Probe?Health check indicating if a container is ready to accept traffic; if it fails, traffic is diverted away from the Pod.
30What is a Startup Probe?Health check used for slow-starting applications that disables liveness/readiness checks until startup completes.
31What is a Rolling Update?A deployment strategy that gradually replaces old pods with new pods with zero downtime.
32How do you undo a failed deployment rollout?Run kubectl rollout undo deployment/<deployment-name>.
33What is Helm?The package manager for Kubernetes used to package, version, share, and deploy Kubernetes applications.
34What is AWS Load Balancer Controller?A Kubernetes controller that provisions and manages AWS ALBs and NLBs for Ingress and Service objects.
35What is Kubernetes RBAC?Role-Based Access Control regulating access to Kubernetes API resources based on Roles and RoleBindings.
36What is a NetworkPolicy?Specifications of how groups of Pods are allowed to communicate with each other and other network endpoints.
37What is a DaemonSet?A controller ensuring that all eligible nodes run exactly one copy of a specified Pod (e.g. logging/monitoring agents).
38What is a StatefulSet?A controller for stateful apps providing stable, unique network identifiers and persistent storage bindings.
39What is a PersistentVolumeClaim (PVC)?A user request for storage volume matching specific size and access modes.
40How does EKS connect securely to RDS?Via private VPC subnets and Security Group rules allowing inbound traffic from node security groups to RDS port 5432/3306.
41How does EKS upload files to S3?Via IRSA or EKS Pod Identity; the AWS SDK in the container automatically assumes the IAM role to call S3 APIs.
42Why never hardcode AWS credentials in containers?Security risk and credential leaks; IAM role assumption is secure, temporary, and automatically rotated.
43EKS vs ECS: When to choose EKS?Choose EKS when multi-cloud portability, extensive CNCF tooling (Helm, Istio), or advanced Kubernetes features are required.
44EKS vs ECS: When to choose ECS?Choose ECS for simplicity, pure AWS native integration, lower operational complexity, and zero control plane cost.
45What is kubeconfig?The configuration file used by kubectl containing cluster endpoints, certificates, and authentication contexts.
46How do you update kubeconfig for EKS?aws eks update-kubeconfig --region <region> --name <cluster-name>.
47What is container resource request vs limit?Request = guaranteed minimum CPU/RAM needed for scheduling; Limit = maximum threshold container can consume.
48What happens if a container exceeds memory limit?The Linux kernel OOM (Out Of Memory) killer terminates the container with Exit Code 137.
49How does Kubernetes self-healing work?The controller manager continuously reconciles the current state against the desired state defined in manifests.
50How do you upgrade an EKS cluster version?Update the control plane version in the EKS Console/CLI, then update node group AMIs and add-ons (VPC CNI, CoreDNS, kube-proxy).
