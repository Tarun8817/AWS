AWS RDS — Complete Guide

AWS RDS (Relational Database Service)

Beginner-friendly study note — English edition — for learning, revision, interviews and printing.

1. What is AWS RDS?

AWS RDS = Amazon Relational Database Service

Definition AWS RDS is a managed database service provided by AWS that makes it easier to create, operate, manage, backup, monitor, and scale relational databases.

What is a database?

A database is an organised place where an application stores data so that it can save, find, update and delete it later. Example: users, orders, products.

What is a relational database?

A relational database stores data in tables (rows and columns), and tables can be linked to each other using keys. You use SQL to talk to it. Examples: MySQL, PostgreSQL.

idnameemail
1Taruntarun@example.com
2Riyariya@example.com

What does “managed service” mean?

A managed service means AWS looks after a large part of the infrastructure work (servers, hardware, OS-level maintenance, backup features and so on) so you can focus on your application. You still make choices and still own your data, your settings and your security configuration.

Why do we use RDS? What problem does it solve?

Without RDS (self-managed MySQL on a server)With RDS
We install MySQL, configure the server, manage backups, updates, security, monitoring, etc. ourselves. AWS manages much of the infrastructure and database administration for us. We mainly create, configure and use the database.
Note RDS does not remove every DBA task. You still design tables, write good queries, create users, tune performance, and configure security properly.

2. RDS Supported Database Engines

A DB engine is the actual database software. RDS lets you pick one:

EngineOne-line explanation
MySQLVery popular open-source relational database; great for web apps and beginners.
PostgreSQLOpen-source relational database known for advanced features and standards compliance.
MariaDBOpen-source database that started as a fork of MySQL and is largely MySQL-compatible.
OracleCommercial enterprise database, often used in large companies (licensing applies).
Microsoft SQL ServerMicrosoft’s relational database, common in .NET / Windows environments.
Amazon AuroraAWS-built database, compatible with MySQL and PostgreSQL, designed for high performance and availability.
MERN and RDS For a MERN application, MongoDB is normally used instead of RDS because MongoDB is a NoSQL database. However, if the MERN application’s backend needs a relational MySQL/PostgreSQL database, RDS can be used.

3. Purpose of AWS RDS

RDS handles or helps with the following administrative tasks:

AreaIn simple words
Database setupCreate a ready database from the console in a few clicks, with no manual install.
Automated backupsDaily backups and logs are kept for a retention period you choose.
Software patchingEngine updates and security patches can be applied in maintenance windows.
MonitoringCPU, memory, storage and connections can be watched in CloudWatch.
MaintenanceAWS handles hardware and underlying infrastructure upkeep.
ScalingUse a bigger instance, more storage, or read replicas when needed.
High availabilityMulti-AZ keeps a standby copy in another Availability Zone for failover.
SecuritySecurity groups, encryption, SSL/TLS, private subnets, IAM options.
RecoveryRestore from a snapshot or to a point in time (with automated backups).
Remember These features are available and often need to be enabled or configured by you (for example Multi-AZ, backup retention, encryption). RDS does not automatically do every administration task for you.

4. Real-World MERN Project Example

Suppose my project is MERN-style, but the database is MySQL on RDS:

  • Frontend: React
  • Backend: Node.js + Express.js (runs on an EC2 instance)
  • Database: MySQL on AWS RDS
User | v React Frontend | v Node.js + Express Backend (on EC2) | v AWS RDS MySQL | v Database (tables: users, ...)

Request flow

  1. User opens the React application.
  2. React sends an API request.
  3. Node.js/Express receives the request.
  4. Backend connects to RDS MySQL.
  5. MySQL executes the query.
  6. Database returns data.
  7. Backend sends the response to React.
  8. React displays the result.

Example: user registration

POST /api/register
{
  "name": "Tarun",
  "email": "tarun@example.com",
  "password": "MyPassword123"   // sent to the server over HTTPS only
}

The backend stores this in the RDS MySQL users table:

  • name
  • email
  • password hash (not the real password)
Never store plain-text passwords Always hash passwords (for example with bcrypt) before saving. If the database leaks, hashes are much safer than plain text.

DB engineThe database software.MySQL 8.x
DB instance classThe size (CPU + RAM) of the instance.db.t3.micro (small, for learning)
StorageDisk space for your data.20 GB

Think of it like a house: the instance is the house, the engine is the system inside (MySQL), the instance class is the size of the house, the endpoint is the address, the port is the door number, and the username/password are the keys.

6. How to Create an AWS RDS MySQL Database

Console screens can change slightly over time, but the flow stays the same.

  1. Login to the AWS Console.
  2. In the search bar, type RDS.
  3. Open Amazon RDS.
  4. Click Create database.
  5. Choose Standard create (gives you all options). Easy create is simpler, with fewer choices and default settings — fine for a first try.
  6. Select engine: MySQL.
  7. Choose the Free Tier template if it is available for your account/region.
  8. Choose an appropriate DB instance size (for learning, a small burstable class such as db.t3.micro is common).
  9. Set the DB instance identifier: my-mysql-db
  10. Set the Master username: admin
  11. Set a strong password.
  12. Choose appropriate storage (the default small size is fine for learning).
  13. Configure Connectivity.
  14. VPC: use the appropriate VPC (the default VPC is fine for practice).
  15. Public access: see the explanation below.
  16. Security group: create a new one, for example rds-mysql-sg.
  17. Port: 3306.
  18. Click Create database and wait until the status becomes Available.
Username and password rules AWS may restrict certain username/password formats (length, some characters). Follow the password requirements shown by the console. The exact rules depend on the selected RDS engine and configuration, so do not assume special characters are always allowed or always forbidden. If the console rejects a character, change the password.

What does “Public access = Yes” mean?

It means the DB instance can get a publicly resolvable address so it can be reached from outside the VPC. By itself it does not open the database to everyone. Public access only gives the DB a publicly reachable network path if the VPC/subnet/security configuration also allows it (a route to an internet gateway, security group rules, network ACLs).

Practice setup summary (learning only) Engine: MySQL • Template: Free tier (if available) • ID: my-mysql-db • Username: admin • Public access: Yes (only if you want to connect from your laptop) • New SG: rds-mysql-sg • Port: 3306.

What is port 3306?

A port is like a numbered door on a server. MySQL listens on door number 3306 by default, so clients must connect to this port.

7. Security Group

A Security Group acts like a virtual firewall for your AWS resource. It decides who can connect, on which port and protocol.

Inbound rule for MySQL

TypeProtocolPortSource
MySQL/AuroraTCP3306see below

Source options

SourceMeaningUse
0.0.0.0/0Any IPv4 address in the worldOnly a temporary learning/testing shortcut. NOT recommended for production databases.
x.x.x.x/32 (My IP)Exactly one IP address — yoursBetter for local testing.
EC2 security group (e.g. EC2-SG)Only resources attached to that security groupBest for production.
EC2-SG ---- allows TCP 3306 ----> RDS-SG (app server) (database)
Why EC2-SG → RDS-SG is better Only your application servers can talk to the database. If the EC2 IP changes, or you add more servers with the same security group, the rule still works. Nobody else on the internet can even try to connect.
Rule Never expose a production database to the public internet unnecessarily.

8. RDS Endpoint

Where to find it: AWS Console → RDS → Databases → click your DB (my-mysql-db) → Connectivity & security tab → Endpoint (and Port).

Definition The endpoint is the hostname that applications use to connect to the RDS database. 
Endpoint: my-mysql-db.xxxxxxxxx.eu-north-1.rds.amazonaws.com

Use the endpoint instead of an IP address, because IP addresses can change.

9. How to Access AWS RDS MySQL From Outside AWS

A) From your local laptop

Requirements:

  • RDS Public access must be enabled if direct public connectivity is intended.
  • The Security Group must allow TCP 3306 from your current public IP.
  • Network ACL / route table / subnet configuration must permit connectivity (a public subnet with a route to an internet gateway).
  • A MySQL client must be installed on your laptop.

Preferred security group rule:

Type: MySQL/Aurora   Protocol: TCP   Port: 3306
Source: My IP  →  x.x.x.x/32

instead of 0.0.0.0/0.

Why? /32 means exactly one IP, so only your machine can reach the DB port. 0.0.0.0/0 means any IPv4 address, so anyone can attempt to connect and guess passwords. Note that home internet IPs often change, so update the rule if you suddenly get a timeout.

Command:

mysql -h <RDS-ENDPOINT> -P 3306 -u admin -p

Example:

mysql -h my-mysql-db.xxxxxxxxx.eu-north-1.rds.amazonaws.com -P 3306 -u admin -p

After you press Enter, MySQL asks for the password (Enter password:). Type it (it will not be displayed) and press Enter.

B) From EC2 (recommended for applications)

If EC2 and RDS are in the same VPC, the application can normally connect using the RDS endpoint without making the database publicly accessible.

Internet | v EC2 / Application | v (private connection inside the VPC) RDS MySQL RDS Security Group: Allow TCP 3306 Source = EC2 Security Group

This is safer than opening MySQL to the entire internet.

Tip If you cannot connect, see Common Connection Errors.

10. Connecting RDS with Node.js

Install the package first:

npm install mysql2
const mysql = require("mysql2");

const connection = mysql.createConnection({
  host: process.env.DB_HOST,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  port: 3306
});

connection.connect((err) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log("Connected to RDS MySQL");
});

Line-by-line explanation

  • require("mysql2") — imports the mysql2 library that lets Node.js talk to MySQL.
  • createConnection({...}) — prepares the connection settings (it does not connect yet).
  • host: process.env.DB_HOST — the RDS endpoint, read from an environment variable instead of being written in code.
  • user and password — the DB username and password, also from environment variables.
  • database — which database to use (for example myapp).
  • port: 3306 — the MySQL port. (You can also use process.env.DB_PORT.)
  • connection.connect((err) => {...}) — actually tries to connect. If err exists, the connection failed and the error is printed.
  • console.log("Connected to RDS MySQL") — the success message.
Do not hard-code passwords in source code Use environment variables instead. Never write the real password in a file that goes to GitHub.

Example .env file (add .env to .gitignore):

DB_HOST=
DB_USER=
DB_PASSWORD=
DB_NAME=
DB_PORT=3306

The values are left empty on purpose: fill them in on your own machine or server. To load a .env file in Node.js you can use the dotenv package; with Docker you pass them using -e flags.

11. EC2 + Docker + RDS

An EC2 instance can run your Node.js app inside a Docker container while the database stays on RDS.

Internet | v EC2 | v Docker Container | v Node.js + Express | v AWS RDS MySQL
Key idea The database does NOT need to run inside the Docker container. The application container connects to RDS using the RDS endpoint.

Why is this good? Containers can be stopped, replaced or rebuilt easily, while the data stays safely in RDS (with backups and monitoring).

12. EC2 Commands

Run these on your EC2 instance (Amazon Linux). Spellings are corrected compared to rough notes (for example usermod, not “usermond”).

1) Install Docker

sudo yum install -y docker

Installs Docker using the yum package manager. -y answers “yes” to prompts automatically. (On newer Amazon Linux 2023, dnf is also used; yum still works there.)

2) Start Docker

sudo systemctl start docker

Starts the Docker service now. Older notes show sudo service docker start, which also works on many Amazon Linux systems; systemctl is the modern way.

3) Enable Docker after reboot

sudo systemctl enable docker

Makes Docker start automatically whenever the server reboots.

4) Add ec2-user to the docker group

sudo usermod -aG docker ec2-user

-aG means append to Group. After this, ec2-user can run Docker without sudo, but you may need to log out and log back in first for the change to apply.

5) Check Docker version

docker --version

6) Check Docker service status

sudo systemctl status docker

You should see active (running). Press q to exit the status view.

7) Pull an example image

docker pull philippaul/node-mysql-app:02
Important philippaul/node-mysql-app:02 is only an example image from a public Docker Hub account. It is not an official AWS image. Only run images you trust or built yourself, and check which environment variables the image expects.

8) Run the container

Run it only after you know the RDS endpoint, the credentials, and the variable names the app expects. The application must be configured with the RDS endpoint and credentials. See the next section.

Never commit database passwords to GitHub Do not put real passwords in code, Dockerfiles, docker-compose files or notes that get pushed. Use environment variables, and for production consider AWS Secrets Manager.

14. Create Database / Table

Connect using the mysql client first, then run:

CREATE DATABASE myapp;

USE myapp;

CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(150) UNIQUE,
    password VARCHAR(255)
);

-- Insert example (the password is a hash, not plain text)
INSERT INTO users (name, email, password)
VALUES ('Tarun', 'tarun@example.com', '$2b$10$exampleHashedPasswordHere');

-- Select example
SELECT id, name, email FROM users;

Explanation

  • CREATE DATABASE myapp; — creates a new database called myapp.
  • USE myapp; — tells MySQL to work inside this database from now on.
  • CREATE TABLE users (...) — creates a table named users.
  • id INT AUTO_INCREMENT PRIMARY KEY — a unique number for each row that increases automatically.
  • name VARCHAR(100) — text, up to 100 characters.
  • email VARCHAR(150) UNIQUE — the same email cannot be saved twice.
  • password VARCHAR(255) — stores the password hash (hashes are long, so 255).
  • INSERT INTO ... VALUES ... — adds a new row (user).
  • SELECT ... FROM users; — reads data from the table. Selecting the password column is usually not needed.

15. RDS Storage

  • Storage type: the kind of disk (for example General Purpose SSD or Provisioned IOPS SSD). It affects speed and cost.
  • Allocated storage: how many GB you reserve at creation, for example 20 GB.
  • Storage autoscaling: if data grows, storage can be configured to increase automatically within the maximum limit you set.

Example: You start with 20 GB and set a maximum of 100 GB. As the app grows, storage can grow up to 100 GB without manual work.

Storage scaling is not compute scaling More storage gives more disk space. It does not add CPU or RAM. For more CPU/RAM you change the DB instance class (see Scaling).

16. RDS Backups

Automated backups

RDS can take daily backups and save transaction logs automatically, kept for a retention period you choose. This allows point-in-time recovery within that period.

Manual snapshots

A snapshot is a backup you create yourself at a specific moment. It stays until you delete it.

Backup vs Snapshot

Automated BackupManual Snapshot
Created byRDS automaticallyYou
RetentionLimited to the retention period you setKept until you delete it
Restore optionPoint-in-time recoveryRestore to that snapshot moment
Good forEveryday protectionBefore big changes, before deleting the DB

Restoring creates a new DB instance; you then point your app to the new endpoint.

17. RDS Multi-AZ

Multi-AZ means RDS keeps a standby copy of your database in a different Availability Zone (AZ). If the primary has a problem, RDS can fail over to the standby.

Remember Multi-AZ is mainly for high availability and failover. It is not for making reads faster.
Availability Zone A Availability Zone B +---------------+ sync +---------------+ | Primary DB | ------> | Standby DB | +---------------+ copy +---------------+ Your app uses one endpoint; on failure it points to the standby

Simple example: Your main database server in Zone A has a hardware problem. With Multi-AZ, RDS switches to the standby in Zone B, and your app continues after a short interruption.

Multi-AZ costs more because you pay for the extra standby capacity.

18. Read Replica

A Read Replica is an additional copy of the database used to serve read queries (SELECT), which reduces the load on the main DB.

Main DB -> writes (INSERT / UPDATE / DELETE) Read Replica -> reads (SELECT)

Example: A blog site has millions of readers but only a few writers. Send reads to replicas and keep the main DB for writes. Replicas may lag slightly behind the main DB.

Multi-AZ vs Read Replica

FeatureMulti-AZRead Replica
Main purposeHigh availability & failoverRead scaling / performance
Used for reads?The standby is normally for failover, not for your app’s reads (standard single-standby setup)Yes, apps send SELECT queries to it
Data copySynchronous (standby kept in step)Asynchronous (may lag slightly)
Automatic failoverYes, designed for itNot its purpose; promotion is a separate action
EndpointSame endpoint for your appIts own endpoint
Do not mix them up Multi-AZ = safety / uptime. Read Replica = extra read capacity. They are different features and can be used together.

21. RDS Security

  • Security Groups: firewall rules; allow only the needed sources on 3306.
  • Private subnets: place the DB where the internet has no direct route.
  • IAM (where applicable): controls who can manage RDS in AWS; IAM database authentication is available for some engines.
  • Encryption: encrypt data at rest (storage, backups, snapshots) using AWS KMS. Best chosen at creation time.
  • SSL/TLS connections: encrypt data while it travels between the app and the DB.
  • Secrets Manager: store and rotate DB credentials instead of keeping them in code.
  • Strong passwords: long and unique, following the console rules.
  • Least privilege: give app users only the permissions they need, not admin power.
  • Avoid public access for production when it is not necessary.
Production preference EC2 → Private RDS  instead of  Internet → Public RDS

23. How to Connect From Local Windows

  1. Install a MySQL client (for example MySQL Shell or the MySQL Command Line Client from the MySQL installer, or another MySQL-compatible client).
  2. Make sure the RDS security group allows your public IP on TCP 3306 and the DB is publicly accessible.
  3. Open Command Prompt or PowerShell and run:
mysql -h <RDS-ENDPOINT> -P 3306 -u admin -p
FlagMeaning
-hhost (the RDS endpoint)
-Pport (capital P = 3306)
-uusername
-pask for the password (small p)

Note: -P (capital) is the port and -p (small) is the password prompt. They are different.

Things that can block the connection Windows Firewall, your local network, ISP restrictions, AWS networking, security group rules, subnet routing and RDS public accessibility can all affect connectivity.

24. Common Connection Errors

1) Connection timed out

The request never reached the DB or got no answer. Possible causes:

  • Security Group does not allow your IP / EC2-SG on 3306
  • Public access disabled (when connecting from outside)
  • Network routing / subnet / NACL problem
  • Wrong endpoint
  • Wrong port

2) Access denied for user

You reached the DB but the login failed. Possible causes:

  • Wrong username
  • Wrong password
  • The user does not have permission for that database/host

3) Unknown host

  • Wrong endpoint (typo, extra space, wrong region)
  • DNS / network issue on your side

4) Can’t connect to MySQL server

A general error. Check that the DB status is Available, the endpoint and port are correct, the security group and public access settings are right, your network allows outbound 3306, and your client can resolve the hostname.

Troubleshooting checklist

  • Is the DB status Available?
  • Am I using the correct endpoint (no typos)?
  • Is the port 3306?
  • Does the RDS security group allow TCP 3306 from the correct source (my current IP or EC2-SG)?
  • If connecting from my laptop, is Public access enabled and is the subnet routed to the internet?
  • Is my public IP still the same as in the rule?
  • Are the username and password correct?
  • Is my Windows Firewall / office / ISP network blocking outbound 3306?
  • If from EC2: are EC2 and RDS in the same VPC, and is EC2-SG set as the source?

25. RDS Delete / Stop / Cost

Can RDS be stopped?

In many configurations, yes: you can stop a DB instance temporarily. Stopping is temporary, and RDS may start the instance again automatically after a maximum period (for example about 7 days). Some configurations (for example certain Multi-AZ or read-replica setups) may have restrictions.

ActionWhat happens
StopThe instance is paused temporarily. Compute charges stop, but storage (and backup storage) can still be charged.
DeleteThe instance is removed permanently. You can choose to create a final snapshot first. Without a snapshot, data may be lost.
SnapshotA saved backup of your DB at a moment in time. It can be used to restore later and may also incur storage charges.
Cost warning RDS resources can incur charges depending on configuration and usage (instance hours, storage, backups, data transfer, Multi-AZ, replicas). Free Tier eligibility depends on your AWS account, service configuration, region and current AWS terms. Do not assume every RDS configuration is free. Check the current AWS Free Tier page and your billing dashboard, and delete practice databases you no longer need.

26. Interview Questions & Answers

Q1. What is AWS RDS?
A managed relational database service from AWS that makes it easier to create, operate, back up, monitor and scale databases like MySQL and PostgreSQL.
Q2. Why do we use RDS?
To reduce manual database administration: AWS helps with setup, backups, patching, monitoring, availability and scaling, so developers can focus on the application.
Q3. Is RDS a database?
No. RDS is a service that runs and manages database engines (MySQL, PostgreSQL, etc.). The engine is the actual database.
Q4. What is a managed database service?
A service where the provider handles much of the infrastructure and routine administration, while you manage your data, schema, access and configuration.
Q5. What is an RDS endpoint?
The hostname applications use to connect to the DB instance, shown in the RDS console under Connectivity & security.
Q6. What port does MySQL use?
3306 by default.
Q7. How can an EC2 instance connect to RDS?
Keep them in the same VPC (or connected networks), allow TCP 3306 in the RDS security group from the EC2 security group, and connect using the RDS endpoint, port, username and password from the app.
Q8. What is Multi-AZ?
A setup with a standby DB in another Availability Zone for high availability and automatic failover. It is not for read scaling.
Q9. What is a Read Replica?
A copy of the DB used to serve read queries and reduce load on the main DB. It is used for read scaling.
Q10. Difference between RDS and EC2-hosted MySQL?
With RDS, AWS provides managed features (backups, patching options, monitoring, Multi-AZ options) and you manage less infrastructure. With MySQL on EC2 you install and manage the OS, MySQL, backups, updates and HA yourself: more control, but more work.
Q11. Why should we not allow 3306 from 0.0.0.0/0 in production?
It lets any IPv4 address attempt to connect, greatly increasing the risk of brute-force attacks and exploitation. Allow only the app security group or trusted IPs.
Q12. Can we access RDS from our local machine?
Yes, if the DB is publicly accessible, the network path is routed, and the security group allows your IP on 3306, using a MySQL client. For production, prefer access through the app/EC2, a bastion host or a VPN.
Q13. What is a Security Group?
A virtual firewall that controls allowed inbound and outbound traffic for AWS resources by protocol, port and source.
Q14. What is the difference between public and private RDS?
Public RDS can be reachable from the internet if network and security rules allow it. Private RDS is not directly reachable from the internet and is accessed from inside the VPC — the common production choice.
Q15. How would you connect a Node.js application to RDS?
Install mysql2, read host, user, password, database and port from environment variables, create a connection (or pool) with them, and make sure the app’s security group is allowed on RDS port 3306.

EC2 / DockerThe server (EC2) and container (Docker) where the backend runs.

Version 2: More production-oriented

Users | v Load Balancer | v EC2 / ECS | v Private RDS | v Database
  • Load Balancer: spreads traffic across multiple app servers and can run health checks.
  • EC2 / ECS: multiple app instances or containers.
  • Private RDS: the database in private subnets, reachable only from the app’s security group.
Why is RDS usually private in production? Users only need to talk to the app, never to the database directly. A private DB has no direct internet route, so there is a much smaller attack surface. Even if someone learns your endpoint, they cannot connect from the internet.

28. RDS in One Minute

AWS RDS = Managed relational database service.

For my application:

React → Node.js/Express → RDS MySQL

RDS manages much of the database infrastructure. RDS gives:

  • Endpoint
  • Backups
  • Monitoring
  • Scaling options
  • High availability options
  • Security features

MySQL default port: 3306

Local access: RDS endpoint + MySQL client + correct networking/security rules.

Production: EC2/Application → Private RDS

Quick create checklist (practice)

  • Create RDS MySQL (Free tier template if available), ID my-mysql-db, user admin, strong password (follow the console rules)
  • New security group rds-mysql-sg, port 3306
  • For laptop testing: Public access = Yes + allow 3306 from My IP (/32)
  • Copy the endpoint from the console
  • Install Docker on EC2 and pull/run the app image with environment variables
  • For production: switch to a private RDS and allow only EC2-SG
  • Delete practice resources to avoid charges
Common mistakes to avoid Hard-coding passwords • opening 3306 to 0.0.0.0/0 in production • assuming Public access alone opens the DB to everyone • confusing Multi-AZ with Read Replicas • assuming RDS is always free • forgetting to delete practice databases.
